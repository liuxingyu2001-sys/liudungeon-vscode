# 十、排错与常见问题

> [← 九、PlaceholderAPI 变量](09-PlaceholderAPI变量.md) · [总目录](../05-使用说明.md) · [十一、附录：目录结构与文件清单 →](11-附录.md)

## 10.0 先跑体检：`/ld doctor`

`/ld doctor` 分三段（⚠ 脚本引擎不可用时没有中间那段）：

```
配置体检报告
  [example] 1 条问题
    ▸ 模板「forgedungeon」……                        ← 每个副本的配置问题
【脚本语法校验】
  已校验 1 条条件表达式，全部通过。                  ← 条件表达式的静态校验
【地图模板】
  ✔ [example] forgedungeon                          ← 副本引用的模板是否存在
```

开服时还会跑一次配置检查（`printBanner()`）：把配置解析问题汇总到控制台（最多 10 条），
但**不跑**条件表达式校验与模板检查 —— 那两段只在 `/ld doctor` 里。

> ⚠ **报错文案本身是错的，别照着做**：提示里的「在服务器根目录创建该世界文件夹」是过时说法。
> 模板一律放 `plugins/liudungeon/maps/<模板名>/`（见 8.2）；正确做法是
> `/ld template list` 看模板在不在 → `/ld template import <地图名>` 导入。

## 10.1 插件根本没加载

**症状**：控制台出现 `InvalidPluginException: … Error resolving libraries`。

**原因**：Paper 下载 `libraries:` 里的依赖时超时。**整个插件不加载**（不是降级）。

**处理**：① 换国内镜像（见 [2.3](02-安装与依赖.md#23-依赖库为什么-jar-只有-05mb)）；
② 或手动放 jar —— 推荐直接平铺进 `plugins/liudungeon/libs/`（不要求目录结构；
放进 `libraries/` 则必须按 Maven 布局且 **11 个齐全**，缺一个整套不用）；③ 重启。

## 10.2 进本后一片空白 / 掉虚空

**症状**：日志 `已加载区块 0`，玩家脚下没有地形。**原因**：模板的区块数据不在世界根目录（Bukkit 只认 `<世界>/region/`）。

**处理**：`/ld template repair <模板名>` —— 它只重建 `level.dat`，不做布局规范化（10.3 同一个原理）。

空白世界的根因通常是**模板里根本没有区块数据**，按顺序查：

1. `/ld template info <模板名>` 看「N 个区块文件」是不是 **0**；
2. 搜日志 `内没有找到任何区块文件`，并分清两种成因：模板里**本来有**区块 → 真坏了（复制或布局规范化出问题，日志会写明）；模板里**本来就没有** → **生成器型世界**的正常样子（如内置 `voidgen`，区块由 `world_gen_settings.dat` 现生成，磁盘上不该有 `.mca`，这种情况只在 debug 里记一句）；
3. 区块布局**不用手工搬**：复制实例时 `WorldLayoutNormalizer` 会自动把 `dimensions/minecraft/overworld/region/` 归位。

### 10.2.1 用 `voidgen` 时「一片空白」是正常的

虚空世界**就是一片空白 + y=64 的一层基岩**，`已加载区块 0` 只说明"没有预生成区块"。判断标准是**能不能站住**：

- 站得住（脚下有基岩）→ 正常，去 `/ld edit enter <副本ID>` 搭地牢；
- 一直往下掉 → 出生点配错了。`voidgen` 地板在 **y=64**，`world.spawn` 写 `0,65,0`。

## 10.3 开本报 `Overworld settings missing`

**原因**：模板的 `level.dat` 结构不对（通常是旧版插件手写的那份）。**处理**：`/ld template repair <模板名>`，详见 [8.4](08-地图模板管理.md#84-关于-leveldat很重要)。

## 10.4 怪物不生成

按可能性排序：

| 原因 | 排查方式 |
|---|---|
| MythicMobs 怪物名写错 | ⚠ **`/ld doctor` 查不出来**（不校验 MM 怪物 ID）。控制台出现 `无法生成怪物「X」：MythicMobs 中不存在该 ID…` 就是它；用 `/mm mobs` 对照 |
| 怪物组没被启动 | `/ld group <实例ID>` 看状态；`/ld spawn <组名>` 手动触发 |
| 撞上实体上限 | 看 `performance.entity-limit`（默认 400），日志有提示 |
| 触发器条件不成立 | `/ld doctor` 会做条件表达式的静态校验 |
| 区块被卸载 | 插件已用区块票据兜底；再查 `world.preload-spawn-chunks` 与 `world.preload-radius`（**不是** `performance` 段） |

## 10.5 脚本不生效

| 现象 | 原因 |
|---|---|
| 启动横幅 `脚本引擎: §c不可用` | GraalJS 依赖没找齐，见 [2.3](02-安装与依赖.md#23-依赖库为什么-jar-只有-05mb) |
| `condition` 永远判假 | 条件写成了翻译器不认识的中文自然语言，见 [7.6](07-脚本开发指南.md#76-条件表达式) |
| 脚本报错但游戏没反应 | 把 `config.yml` 的 `debug` 设为 `true` 看完整堆栈 |
| 涉及宿主类的脚本失败 | 开了 `script.sandbox`，宿主类查找被禁 |

## 10.6 复活系统「跟摆设一样」：玩家倒下后卡在旁观者

**先看 `revive.count`。** 默认就是 `0`，而 `0` 的语义是**禁止复活** —— 配了 `auto` / `item` / `ally` 也必须同时把次数给上：

```yaml
revive:
  count: 3        # 3 = 次数；-1 = 无限；0（或没写）= 禁止复活，下面的 auto/ally 全都不生效
  auto:
    delay: 5
```

`/ld doctor` 会直接报：`revive 段配了复活方式，但 revive.count = 0（禁止复活），玩家倒下后将没有任何方式能起来`。

| 现象 | 原因 |
|---|---|
| 倒下后原地卡住、旁观者视角、无提示 | `count: 0`：没有任何复活方式能生效 |
| 倒下后直接弹出原版「重生」界面 | 死亡没被接管，见下一条 |
| 看到「你倒下了」但 5 秒后仍起不来 | 次数池被队友用光（`ally.consume_count: true`）；日志 `[复活] xxx 自动复活失败：复活次数已耗尽`（**INFO 级**，属正常结果） |
| 提示「当前没有其他存活的队友，无法被救起」 | 单人进本或队友全倒：`ally` 需要**活着**的队友按住潜行读条 |
| 一个人倒下就触发 `all_death` | 没配 `revive` 段（或 `count: 0`）按 `strict` 判定；配了可用复活方式会自动转 `lenient` |
| 全队阵亡后既起不来也出不去 | 现在插件会在 `all_death` 脚本跑完后自动判失败退出（10 秒后传出）；想自己收尾就在脚本里 `action.fail('原因')` 或 `action.revive('@all')` |
| `on_exhausted` 没触发 | 它只在**最后一次复活成功、剩余次数刚变 0** 时触发；次数早用完、之后复活失败不再触发（那种走 `all_death`） |

**关于原版重生界面**：插件在 `EntityDamageEvent`（`HIGH`）里拦致命伤并取消事件、把玩家切成旁观者，正常情况下**不该出现**。真出现就查：① 玩家是否真在副本实例里（`/ld info`）；② 死亡是否来自伤害事件 —— `/kill`、掉虚空、以及别的插件直接 `setHealth(0)` 这类**非伤害类死亡**不经过拦截；③ `/ld doctor` 里 `[复活]` 那行有没有打印「已启用复活系统」。

## 10.7 换了 jar 之后某个功能整片报 `ClassNotFoundException`

```
java.lang.NoClassDefFoundError: com/liu/liudungeon/edit/EditTools
Caused by: java.lang.ClassNotFoundException: com/liu/liudungeon/edit/EditTools
```

**这不是打包漏类**（`unzip -t` 显示 jar 完好、类也在）。原因是**服务器运行期间用 `cp` 覆盖了 jar**：Bukkit 的 `PluginClassLoader` 还持着旧 jar 的文件引用，而 `cp` 换掉了 inode，于是它去读**还没加载过**的类就找不到。症状很有欺骗性：启动横幅正常、已加载的功能照常工作，只有**替换那一刻之后第一次被加载**的类全挂。

**判别**：看报错开始时间与 jar 修改时间是否吻合 ——

```bash
stat -c '%y  %n' plugins/liudungeon-1.0.5.jar          # jar 什么时候被覆盖的
grep -n "Loading server plugin liudungeon" logs/latest.log   # 进程什么时候起的
```

jar 修改时间**晚于**进程启动时间 → 就是这个原因。正确做法：控制台 `stop` 等完全退出 → `bash tools/deploy.sh`（脚本会拒绝在运行期间覆盖）→ 重新启动。确实要热替换用 `--allow-running`（不推荐）。启动横幅会打印构建时间，一眼能看出跑的是不是刚部署的 jar。

## 10.8 启动横幅显示 `WG[无]` 但 WorldGuard 明明装了

已修复：原先按 Bukkit 的 `World`/`Location` 找 WorldGuard 的反射方法，而 WorldGuard 7 用的是 **WorldEdit** 的 `World`/`Location`，签名对不上 → 静默返回 null。现在两种签名都试并对 WorldEdit 类型做转换，重启加载新版即可。

## 10.9 磁盘不释放

副本世界的落点有**三处**，删除时必须都覆盖：

```
<服务器根>/ld_xxx/                                  ← 落点 1
<宿主世界>/dimensions/minecraft/ld_xxx/                ← 落点 2（世界数据真正写在这）
<服务器根>/plugins/WorldGuard/worlds/<世界名>/          ← 落点 3（装了 WG 才有，删世界不会带走它）
```

插件已处理（含启动时的孤儿清理，受 `world.cleanup-orphans-on-start` 控制，默认 `true`）。**落点 2 是最容易漏的**：Paper 26.x 会把落点 1 搬进落点 2 并删掉落点 1（日志 `Migrating world directory from ./ld_xxx/region to …`），所以凡是进程死在"插件删目录"之前的（崩溃、面板 kill、关服时插件先被卸载），留下的只有落点 2。

发现残留时：`/ld template list` 查看模板与占用（`/ld status` 没有磁盘字段）→ **重启服务器**（启动时清理孤儿目录）。

- **编辑会话的残留不删，而是搬进 `bak/`**：`ld_<副本ID>_edit` 可能是"上次没来得及同步回模板"的唯一一份地形，启动清理会把它搬到 `plugins/liudungeon/bak/<世界名>_<时间戳>/{world,dimension}/` 并打 WARNING；确认没用后自己删。普通实例残留（只是模板拷贝）直接删除。
- 副本世界**不是**每次都写盘：`setAutoSave(false)` 让区块卸载时整段跳过保存，副本里改的方块与实体不落盘；每次进本真实的写入只有**克隆的那份模板**。所以想省磁盘要动的是**模板体积**（内置 `voidgen` 约 250 字节、0 个区块文件），见 [8.2.1](08-地图模板管理.md#821-内置的虚空世界-voidgen)。
- 第三方插件会为每个副本世界留记录：`plugins/MyPet/worldgroups.yml`（约 21 字节/世界，下次启动自己清）、`plugins/CMILib/Saves/worldNames.yml`（约 58 字节/世界，只增不减）。一万次进本约 0.6 MB，不影响性能，**不用管**。

## 10.10 编辑模式 `/ld edit` 的排查

完整说明见 [十二章](12-游戏内编辑模式.md)，这里只列症状与处理。

| 症状 | 原因 | 处理 |
|---|---|---|
| 「编辑世界 `ld_xxx_edit` 已被加载（疑似上次异常残留）」 | 上次异常（崩溃、`kill -9`、PlugMan 热重载）留下还在加载的世界 | **重启服务端**，不要手动删目录（世界对象还在内存里时删只会更乱） |
| 「复制编辑世界失败」/「加载编辑世界失败」 | 磁盘满、模板目录权限、模板损坏 | 看日志堆栈；先 `/ld template info <模板名>`，必要时 `/ld template repair <模板名>` |
| 编辑世界目录残留、磁盘不释放 | 会话世界目录也是**两处落点**（服务器根 + `dimensions/minecraft/`） | 正常退出/试玩/关服会卸载并删除；异常退出留下的会在启动清理时**搬进 `bak/`**（不删，可能是唯一一份地形），见 10.9 |
| `save` 报「保存失败（原文件已备份，未改动）」 | 写入失败（磁盘满、文件被占用） | 备份在写回**之前**，原文件未动；处理完再 `/ld edit save` 一次（缓冲还在） |
| `save` 没生效 / 改了但游戏里还是老样子 | ① 根本没 save（看面板「待保存 N 项」）；② 你看的是**已经在跑的实例**，它不受编辑影响 | 先 `/ld edit panel` 确认数字再 `save`；然后 `/ld enter` 开**新实例**验证。编辑期间别用文本编辑器同时改同一份 YAML |
| 菜单打开是空的 | 这个副本确实还没有区域/交互点/怪物组 —— 空列表**不是坏了**，中间有 `（空）` 提示 | 点底部 `49`（`➕ 新建…`）；区域列表为空时会提示先建区域再用魔棒画两个角 |
| 点了菜单按钮没反应 | ① 点到灰玻璃填充格或纯展示格；② 条目没绑定你按的那个键（左/右/`Shift+左`/`Shift+右` 各不相同，见图标 lore）；③ 聊天栏的 `[设为目标]`/`[✔删除]` 是**上一次查询**的按钮，已过期 | 看聊天栏提示；或重新右键一次方块刷新列表 |
| 背包满、编辑用的书掉了 | 放不下时会把书**丢在你脚下**（有意为之，避免书消失而状态还挂着） | 捡起来继续；先清出 1 格更稳妥 |
| 聊天发不出去 / 说了话没反应 | 会话正在等聊天输入（新建向导、输入数值），下一条**非指令**消息会被当输入吞掉 | `/ld edit cancel` 取消挂起输入；打开任何 GUI 也会自动清掉 |
| 签了别的书被当成脚本提交 | 挂着书本文本编辑时，签署任何一本书都会被捕获 | 编辑会话期间的预期行为；`/ld edit cancel` 取消 |
| 「会话被别人占用」 | ①「副本 X 正在被 Y 编辑」= 同一副本同时只能一人编辑；②「模板 X 已被另一个编辑会话占用」= 有人正在编辑**共用同一模板的另一个副本** | `/ld edit status`（控制台也能跑）看全部会话与待保存项数；等对方 `exit`。**同一个副本**的 `enter` 是恢复会话，不会报这个 |
| 掉线后回来会话没了 | 掉线超 10 分钟，会话超时关闭，未保存变更落草稿 | 去 `plugins/liudungeon/bak/<副本ID>_edit_draft_<时间戳>/` 找草稿；地形在超时收尾时已同步回模板 |
| 控制台执行 `/ld edit enter` 没反应 | 除 `status` / `help` 外，`/ld edit` 子指令**只能由玩家执行** | 用游戏内管理员账号；控制台只用 `/ld edit status` |

## 10.11 菜单 / `/ld list` 里没有某个副本

| 症状 | 原因 | 处理 |
|---|---|---|
| 菜单和 `/ld list` 里都没有 `example` | **设计如此**：`dungeons/example/` 是首次启动写出的演示副本，不出现在任何列表与补全里 | 想看就 `/ld enter example`；想拿它当起点用 `/ld create <副本ID>` |
| 自己建的副本不见了 | 该副本 `config.yml` 顶层写了 `hide: true` | 改成 `false`（或删掉）再 `/ld reload`；带 `liudungeon.admin` 的人始终看得到隐藏副本 |
| 副本在菜单里是**屏障**、点了没反应 | 该副本 `enable: false`（停用） | 改回 `true` 再 `/ld reload`；停用的副本连 `/ld enter` 也会被拒 |
| 整个菜单是空的 | `dungeons/` 下一个能加载的副本都没有 | 看启动日志 `已加载 N 个副本`；`/ld doctor` 会指出哪个目录缺 `config.yml` |
| 副本在磁盘上、但没被加载 | 目录名以 `.` 开头或以 `_backup` 结尾，加载器按约定跳过 | 改名成正常 ID 再 `/ld reload` |

> `/ld info <副本ID>` 不受可见性影响 —— 只要知道 ID，隐藏的、停用的、演示副本都能查。

## 10.11.1 玩家说「我挖不动方块 / 放不了方块」

**这是默认行为，不是坏了。** 副本内默认禁止玩家破坏与放置方块
（`world.allow_build` 不写就是 `false`），连桶、点火、骨粉催熟也在拦截范围内。
玩家会收到一条 `本副本不允许破坏方块。` 的提示（同一人 3 秒内只提示一次）。

| 症状 | 原因 | 处理 |
|---|---|---|
| 所有人在副本里都挖不动 | `world.allow_build` 没写或为 `false` —— **就是这样设计的** | 要自由建造的沙盒副本才写 `allow_build: true`；正常副本保持禁止 |
| 机关点（`BREAK_BLOCK` / `PLACE_BLOCK`）也不触发 | 不该发生 —— 机关点的判定在 `allow_build` **之前**，不受它影响 | 若确实不触发，问题在交互点本身（坐标/类型/`required_block`），看 `/ld doctor` 的交互点一节 |
| 想自己（op）在副本里改一下地形 | 这一项**没有绕过权限**，对 op 一样生效（刻意的） | 用 `/ld edit enter <副本ID>` 进编辑模式改（编辑会话不算副本实例，不受限制），或用脚本 `action.setblock` |
| 发射器倒水没被拦 | **有意不管**：`BlockDispenseEvent` 里没有玩家信息，归因不到是谁触发的 | 要限制发射器就用交互点或脚本 |
| 玩家说「熔岩/水在流动改变地形」 | 环境蔓延（`BlockSpreadEvent` 等）不是玩家动作，不由这条规则管 | 用 `world_rules` 的 GameRule 或 `tasks.yml` 处理 |

查看某副本当前是允许还是禁止：`/ld info <副本ID>` 里那一行 `玩家改地形: 禁止 (默认)`。

## 10.11.2 复活按钮显示的是英文材质名

倒下后聊天栏那个按钮写的是 `[ 点击使用 TOTEM_OF_UNDYING 复活 ]` ——
**默认就是这样**，按钮上的名字取自 `revive.item.display-name`，不写就显示材质名。

| 症状 | 原因 | 处理 |
|---|---|---|
| 按钮上是 `TOTEM_OF_UNDYING` 这类英文 | `item` 段没写 `display-name` | 写 `display-name: "&d&l复活图腾"`（支持 `&a` 与 `#rrggbb`）再 `/ld reload` |
| 配了中文，按钮还是英文 | 键名层级写错了 | 必须是 `revive.item.display-name`，别写在 `revive:` 直下 |
| 名字配了颜色代码，却显示成 `&d&l复活图腾` 这几个字符 | **旧版本的 bug，已修**：按钮那两行用 `Component.text()` 拼字符串，它不认 `&` 代码；现在走 `Text.of` 解析。如果你还在旧版上，升级即可 | 升级插件；名字带不带颜色代码都行，不带就继承按钮本身的绿色粗体 |
| 想换掉"你身上有复活道具"那句 | 那句话里的名字**同一个来源**，改 `display-name` 就会跟着变 | 无需额外配置 |
| 复活公告里也是这个名字 | 有意为之：公告与按钮用同一个名字，玩家才不会以为是两种道具 | 同上 |
| 自动复活时公告说"X 使用复活道具复活了自己" | **旧版本的 bug，已修**：那句公告不分方式，全按道具复活写，自动起来的人被说成用了道具 | 现在插件**不发任何复活公告**，要公告就自己在 `on_revive` / `on_ally_revive` 里写，见 [6.2 复活钩子](06-配置文件详解.md#复活钩子on_revive--on_ally_revive--on_exhausted) |
| 复活后全队什么提示都没有 | **有意为之**：插件不再发内置公告 | 想要就在 `on_revive` 里 `action.message('@all', ...)`；按方式区分用 `cause` |
| 公告里想写"谁把谁救起来的" | 救起者名在 `rescuer` 里（字符串） | 在 `on_ally_revive` 里 `action.message('@all', '&a' + rescuer + ' 救起了 {player.name}')` |
| 想让"被队友救活"时额外做点什么 | 那是一个独立钩子 | `revive.on_ally_revive`，脚本里 `rescuer` 是救人者的名字 |
| 扣道具时什么提示都没有 | `item.consume-message` 不写就是**静默扣**（道具是直接从背包删的） | 要提示就写 `consume-message: "&7消耗了一个 {item}&7。"`，`{item}` = 显示名 |
| 启动日志里却还是英文 | **有意为之**：日志打的是材质名（`道具复活 TOTEM_OF_UNDYING（显示为「复活图腾」）`），方便对着 `config.yml` 排查 | 不用处理 |

> 插件**不读那件物品自己改的名字**（铁砧改名的下界之星也一样算数），
> 判定"身上有没有复活道具"只看材质名；显示名只认配置。

## 10.11.3 菜单 / 列表里副本的顺序不对

**顺序本身不会出错，但"没配 priority"和"配了没生效"看起来一样。** 规则只有两条：
先比 `priority`（**数字小的靠前**），相同则按副本 ID 排。

| 症状 | 原因 | 处理 |
|---|---|---|
| 顺序看着像随机的 | **不是随机的**：这些副本的 `priority` 都是默认的 `10`，所以按 ID 排在排，只是 ID 是英文目录名，看不出来 | 按 ID 顺序看就对了；想自己定顺序就给关心的那几个写 `priority` |
| 配了 `priority: 1`，但它没排到第一个 | 有别的副本配了更小的数（`0` 或负数也排最前），或键写错了层级 | `/ld list` 每行末尾有生效的优先级数字（非默认的显示为**金色**），一眼能看出谁更小；键必须写在 **`config.yml` 顶层**，不能缩进到 `dungeon:` / `world:` 里 |
| 改了 priority 但列表没动 | 忘了 `/ld reload`；或者改动只让它在同优先级组里换了位置（比如把它从 `10` 改成 `10` 之外又和别的重了） | `/ld reload` 后看 `/ld info <副本ID>` 的 `列表优先级` 确认生效值 |
| 想让某个副本沉到最后 | — | 写一个比 10 大的数，如 `priority: 100` |
| 进不去是不是因为优先级太低 | **不是**。`priority` 只影响显示顺序，与进入条件、能不能进、实例上限都无关 | 进不去看 `10.9` / `10.11.2` 与 `/ld doctor` |

> `/ld info <副本ID>` 里的 `列表优先级` 显示的是**生效值**（没配时就是 `10`），
> 不是"配没配"。默认值也是实打实参与排序的。

## 10.11.4 悬浮字（`action.hologram`）没出现 / 不消失

**先看控制台**：这个功能的所有失败路径都会打 warning（不像有些动作是静默的），
所以"什么都没发生"时日志里一定有线索。

| 症状 | 原因 | 处理 |
|---|---|---|
| 打不开、控制台说**参数顺序看着反了** | 写成了 `hologram(位置, 文本)` | 顺序是 `hologram(文本, 位置, [整体大小], [时长], [Y偏移])`；写反时插件**不生成**并明说 |
| 说**位置无法解析** | 位置既不是 `区域.点位`、也不是区域名、也不是 `x,y,z` | 三种写法任选；点位要先在 `zones.yml` 里定义 |
| 生成成功但控制台说**Y 偏移不正常** | 偏移写了 NaN / 无穷 / 超过 ±256 格（多半是把世界坐标当偏移填了） | 偏移是"相对落点"的格数，正数往上：`hologram('字', 'Boss房', 2, 0, 2.5)`；NaN 按 0 处理 |
| 生成成功但看不到 | ① 字陷在方块里 —— 按**区域名**取的落点是范围盒中心，常正好卡在地板/墙里（点位与坐标一般是脚下一格）；② 离你太远；③ 视角正背对（悬浮字是**正面朝向**的板子） | 用第五个参数抬起来（`2`~`3` 格通常就浮到房间上方）；先用自己脚下的坐标试一次（站在目标位置执行 `/ld script log(player.getLocation())` 抄坐标）；`/ld info <副本ID>` 的「悬浮字」段能看到确实生成了几块 |
| 写 `'10s'` 却一直不消失 | 单位写错（`'10ss'` / `'10 秒后'`）：解析失败时值是 `0`，含义从"10 秒后消失"变成"一直挂着" | 支持 `10s` / `10秒` / `5分` / `200t` / `500ms`；控制台会为写错的单位打 warning |
| 想立刻清掉全部悬浮字 | 时长 `0` / 不写 = 到副本结束才回收 | 脚本里 `action.clear_holograms()` |
| 循环里生成，警告**上限 64 块已满** | 单个副本同时最多 64 块（实体是持续开销） | 给每块写 `duration`；或先 `clear_holograms()` 再重新生成 |

## 10.12 日志关键字速查

| 关键字 | 含义 |
|---|---|
| `[进本]` / `[出本]` / `[复活]` | 进本各阶段 / 出本与状态还原 / 复活系统事件 |
| `模板克隆完成，用时 N ms` | 复制模板耗时，大图会明显变长 |
| `已加载区块 N` | **必须 > 0** |
| `安全落脚点 X,Y,Z` | 插件在配置出生点附近找到的可站立位置 |
| `副本实例已启动/已结束` | 生命周期边界 |
| `action.create_obstacle: 障碍物「X」不存在` | 脚本里的障碍物 ID 与 `obstacles.yml` 键名对不上（只留这一行 warning，玩家侧毫无提示） |
| `障碍物「X」要写 N 格，超过单次写入上限 32768` | 区域画太大（加载期就报，运行期**拒绝执行**而不是写一半），见 [6.6](06-配置文件详解.md#66-obstaclesyml-障碍物) |
| `障碍物「X」引用的区域「Y」不存在` | `obstacles.yml` 的 `区域:` 在 `zones.yml` 里找不到 |
| `障碍物「X」的方块「…」格式错误` | 方块清单那行不是 `x,y,z,材质` 四段 |
| `action.hologram 的参数顺序看着反了` | 写成了 `hologram(位置, 文本)` —— 本次不生成，见 [10.11.4](#10114-悬浮字actionhologram没出现--不消失) |
| `action.hologram 的位置「X」无法解析` | 位置既不是 `区域.点位`、也不是区域名、也不是 `x,y,z` |
| `action.hologram 的时长「X」解析不出来` | 单位写错（`10ss`），已按「不自动消失」处理（不是报错，但意思变了） |
| `动作频率超限` / `同时存在上限 64 块已满` | 循环里生成悬浮字太多，见 [10.11.4](#10114-悬浮字actionhologram没出现--不消失) |
| 门「自己回来了 / 自己开了」 | 障碍物覆盖的区块被卸载过（实例世界不自动保存）。插件已给障碍物区块打票据常驻，但仍建议放在**玩家会去的战斗区**，见 [6.6](06-配置文件详解.md#66-obstaclesyml-障碍物) |
| `Error resolving libraries` | 依赖下载失败，插件未加载 |
| `实例世界 <名> 内没有找到任何区块文件！副本会是一片空白` | **模板有区块但复制后没搬过来**（真故障）。生成器型模板不会报这句，见 10.2.1 |
| `已生成内置虚空世界模板 maps/voidgen` | 首次启动生成内置虚空世界（无区块文件正常） |
| `模板「X」的目录就是正在运行的世界 Y` | 模板目录与正在加载的世界**指向同一目录**，危险状态 |
| `已从 maps/ 目录加载 N 个地图模板` | 模板扫描结果 |
| `已清理 N 个上次残留的实例世界目录，释放 X` | 启动清理（两处落点都扫，含 `dimensions/<命名空间>/ld_xxx`） |
| `已清理 N 个残留的 WorldGuard 世界数据目录` | 启动清理顺带收 `plugins/WorldGuard/worlds/ld_xxx/`；只认 `ld_` 前缀，不碰 `world` 与你自己的世界名 |
| `上次的编辑世界 <名> 没来得及同步回模板（X），已搬到 <路径> 保留，未删除` | 编辑残留搬进 `bak/` 而非删除（可能是唯一一份编辑成果） |
| `上次的编辑世界 <名> 残留未清理（保留失败），位置: <路径>` | 搬 `bak/` 失败（跨盘、权限、磁盘满），按提示路径手动处理 |
| `编辑结果已同步回模板: <模板名>（副本 <副本ID>）` | 退出编辑时地形已同步回 `maps/<模板名>/` |
| `编辑世界同步回模板失败 <模板名>: … 会话世界目录 <路径> 保留` | 同步失败，会话世界目录没删，可手动复制回 `maps/<模板名>/` |
| `编辑会话超时关闭: <副本ID>（未保存变更草稿: <路径>）` | 掉线超 10 分钟，未保存变更已落草稿 |
| `关服时编辑会话未保存，已落草稿: <路径>` | 关服/重载时还有未保存变更 |
| `编辑世界加载失败 <世界名>` | 编辑世界创建失败，随后会删掉半成品拷贝 |
