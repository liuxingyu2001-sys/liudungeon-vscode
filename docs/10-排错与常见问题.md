# 十、排错与常见问题

> [← 九、PlaceholderAPI 变量](09-PlaceholderAPI变量.md) · [总目录](../05-使用说明.md) · [十一、附录：目录结构与文件清单 →](11-附录.md)

## 10.0 先跑体检：`/ld doctor`

绝大多数问题在进本之前就能被发现。`/ld doctor` 分三段输出（⚠ 脚本引擎不可用时**没有中间那段**）：

```
配置体检报告
  [example] 1 条问题
    ▸ 模板「forgedungeon」……                        ← 每个副本的配置问题

【脚本语法校验】
  已校验 1 条条件表达式，全部通过。                  ← 条件表达式的静态校验

【地图模板】
  ✔ [example] forgedungeon                          ← 副本引用的模板是否存在
```

**开服时也会跑一次配置检查**（`printBanner()`）：把 `allIssues()` 的配置解析问题
汇总到控制台（**最多 10 条**，更多时提示你敲 `/ld doctor`）——
注意它**不跑**后面的条件表达式语法校验与模板检查，那两段只在 `/ld doctor` 里。
目的就是把「玩家进本才炸」提前到开服。

> ⚠ **这两条提示文案本身是错的，别照着做**：`/ld doctor` 与副本加载期的报错会说
> 「**服务器根目录下找不到该世界文件夹**」「请**在服务器根目录创建**该世界文件夹」——
> 这是**过时的旧说法**。模板一律放在 **`plugins/liudungeon/maps/<模板名>/`**（见 8.2），
> 去服务器根目录建文件夹没有任何用。
> 正确做法：`/ld template list` 看模板在不在 → `/ld template import <地图名>` 导入。

## 10.1 插件根本没加载

**症状**：控制台出现

```
[ModernPluginLoadingStrategy] Could not load plugin 'liudungeon-1.0.2.jar'
org.bukkit.plugin.InvalidPluginException: java.lang.RuntimeException: Error resolving libraries
```

**原因**：Paper 下载 `libraries:` 里声明的依赖时超时。**它不是降级，是整个插件不加载。**

**处理**：

1. 换国内镜像（见 [2.3](02-安装与依赖.md#23-依赖库为什么-jar-只有-05mb)）
2. 或手动放 jar —— **推荐直接平铺进 `plugins/liudungeon/libs/`**（不要求目录结构）。
   放进 `libraries/` 则**必须按 Maven 目录布局**（`<group 点换斜杠>/<artifact>/<version>/<artifact>-<version>.jar`）
   且 **11 个必须齐全**，缺一个就整套不用（详见 [2.3](02-安装与依赖.md#23-依赖库为什么-jar-只有-05mb)）
3. 重启

## 10.2 进本后一片空白 / 掉虚空

**症状**：日志里 `已加载区块 0`，玩家脚下没有地形。

**原因**：模板的区块数据不在世界根目录。Bukkit 只认 `<世界>/region/`。

**处理**：

```
/ld template repair <模板名>
```

**`repair` 只重建 `level.dat`，不会重做布局规范化**（这也是它修 `Overworld settings missing` 的原理，见 10.3）。

空白世界的根因通常是**模板里根本没有区块数据**。按顺序查：

1. `/ld template info <模板名>` 看「N 个区块文件」是不是 **0**；
2. 搜日志里的 `内没有找到任何区块文件` —— 出现这行就说明模板是空的；
3. 区块布局**不需要手工搬**：开本复制实例时 `WorldLayoutNormalizer` 会自动把
   `dimensions/minecraft/overworld/region/` 归位到 `<实例世界>/region/`。

## 10.3 开本报 `Overworld settings missing`

**原因**：模板的 `level.dat` 结构不对（通常是旧版本插件手写的那份）。

**处理**：

```
/ld template repair <模板名>
```

详见 [8.4](08-地图模板管理.md#84-关于-leveldat很重要)。

## 10.4 怪物不生成

按可能性排序：

| 原因 | 排查方式 |
|---|---|
| MythicMobs 怪物名写错 | ⚠ **`/ld doctor` 查不出来**（它只查配置解析问题、条件表达式语法、模板是否就绪，不校验 MM 怪物 ID）。开本后控制台出现 `无法生成怪物「X」：MythicMobs 中不存在该 ID，且不是有效的原版实体名。请检查 monsters.yml 的 id 字段。` 就是它；用 `/mm mobs` 对照 |
| 怪物组没被启动 | `/ld group <实例ID>` 看怪物组状态；`/ld spawn <组名>` 手动触发 |
| 撞上实体上限 | 看 `config.yml` 的 `performance.entity-limit`（默认 400）；日志会有提示 |
| 触发器条件不成立 | `/ld doctor` 会做条件表达式的静态校验 |
| 区块被卸载 | 插件已用区块票据兜底；若仍出现，查的是 `world.preload-spawn-chunks` 与 `world.preload-radius`（**不是** `performance` 段 —— 那段只有实体上限/拆分阈值/方块写入速率） |

## 10.5 脚本不生效

| 现象 | 原因 |
|---|---|
| 启动横幅显示 `脚本引擎: §c不可用` | GraalJS 依赖没找齐，见 [2.3](02-安装与依赖.md#23-依赖库为什么-jar-只有-05mb) |
| `condition` 永远判假 | 条件表达式写成了中文自然语言但翻译器不认识，见 [7.6](07-脚本开发指南.md#76-条件表达式) |
| 脚本报错但游戏没反应 | 把 `config.yml` 的 `debug` 设为 `true` 看完整堆栈 |
| 涉及宿主类的脚本失败 | 开了 `script.sandbox`，宿主类查找被禁 |

## 10.6 启动横幅显示 `WG[无]` 但 WorldGuard 明明装了

已修复。原因是我们按 Bukkit 的 `World`/`Location` 类型去找 WorldGuard 的反射方法，
而 WorldGuard 7 用的是 **WorldEdit** 的 `World`/`Location`，签名对不上 → 静默返回 null。
现在两种签名都试，并对 WorldEdit 类型做转换。重启加载新版即可。

## 10.7 磁盘不释放

副本世界的落点与残留有**三处**，删除时必须都覆盖：

```
<服务器根>/ld_xxx/                                  ← 落点 1
<宿主世界>/dimensions/minecraft/ld_xxx/                ← 落点 2（世界数据真正写在这）
<服务器根>/plugins/WorldGuard/worlds/<世界名>/          ← 第 3 处：WG 的世界数据（装了 WG 才有）
```

前两处是「实例世界」，第三处是 **WorldGuard 自己的世界目录** —— 删世界不会自动带走它，
实测十几次开本能攒下近十个。

插件已处理（含启动时的孤儿清理）。⚠ 启动清理受 `world.cleanup-orphans-on-start`（默认 `true`）控制。

如果发现残留：

```
/ld template list              查看模板与占用（`/ld status` 没有磁盘字段）
重启服务器                     启动时会清理孤儿目录
```

服务器**异常退出**（kill -9、断电）时会留下孤儿目录，属正常现象。

## 10.8 编辑模式 `/ld edit` 的排查

完整说明见 [十二章](12-游戏内编辑模式.md)，这里只列症状与处理。

| 症状 | 原因 | 处理 |
|---|---|---|
| 进入提示「编辑世界 `ld_xxx_edit` 已被加载（疑似上次异常残留）」 | 上次异常（崩溃、`kill -9`、PlugMan 热重载）留下了还在加载的世界 | **重启服务端**。不要手动删目录 —— 世界对象还在内存里时删目录只会更乱（插件正常收尾时会自行卸载并清理） |
| 进入提示「复制编辑世界失败」/「加载编辑世界失败」 | 磁盘满、模板目录权限、模板本身损坏 | 看日志堆栈；先 `/ld template info <模板名>` 确认模板健康，必要时 `/ld template repair <模板名>` |
| 编辑世界的目录残留、磁盘不释放 | 会话世界目录 `ld_<副本ID>_edit` 也是**两处落点**（服务器根 + 宿主世界的 `dimensions/minecraft/`） | 正常退出/试玩/关服都会卸载并删除；异常退出会留下。重启时启动清理会带走孤儿目录（受 `world.cleanup-orphans-on-start` 控制，见 10.7） |
| `save` 报「保存失败（原文件已备份，未改动）」 | 写入失败（磁盘满、文件被占用） | 备份在写回**之前**，原文件未被改动；处理完再 `/ld edit save` 一次即可（缓冲还在）。完整堆栈在服务端日志里 |
| `save` 没生效 / 改了但游戏里还是老样子 | ① 根本没 save（看面板的「待保存 N 项」）；② 你看的是**已经在跑的实例**，它不受编辑影响 | 先 `/ld edit panel` 确认数字，再 `/ld edit save`；然后 `/ld enter` 开个**新实例**验证。编辑期间别用文本编辑器同时改同一份 YAML |
| 菜单打开是空的 | 这个副本确实还没有区域 / 交互点 / 怪物组 —— 空列表**不是坏了**，中间有一行 `（空）` 提示 | 点底部的 `49`（`➕ 新建…`）。区域列表为空时会提示先建区域、再用魔棒画两个角 |
| 点了菜单按钮没反应 | ① 点到灰玻璃填充格或纯展示格；② 该条目没绑定你按的那个键（左 / 右 / `Shift+左` / `Shift+右` 各不相同，见各菜单的图标 lore）；③ 聊天栏的 `[设为目标]` / `[✔删除]` 是**上一次查询**的按钮，已被判过期 | 看聊天栏提示（有「列表已过期…请再右键一次方块刷新」这类话）；或重新右键一次方块刷新列表 |
| 背包满、编辑用的书掉了 | 书本编辑器放不下时会把书**丢在你脚下**（这是有意的，避免书直接消失而挂起状态还在） | 捡起来继续编辑；先清出 1 格空位更稳妥 |
| 聊天发不出去 / 说了话没反应 | 会话正在等聊天输入（新建向导、输入数值…），下一条**非指令**消息会被当成输入吞掉 | `/ld edit cancel` 取消挂起输入；打开任何 GUI 也会自动清掉挂起输入 |
| 签了别的书被当成脚本提交 | 挂着书本文本编辑时，签署任何一本书都会被捕获 | 编辑会话期间的预期行为；`/ld edit cancel` 取消 |
| 提示「会话被别人占用」 | ① 「副本 X 正在被 Y 编辑」= 同一副本同时只能一个人编辑；② 「模板 X 已被另一个编辑会话占用」= 你（或别人）正在编辑**共用同一模板的另一个副本** | 用 `/ld edit status`（控制台也能跑）看全部会话与待保存项数；等对方 `/ld edit exit`。注意**同一个副本**的 `enter` 是恢复会话，不会报这个 |
| 掉线后回来会话没了 | 掉线超过 10 分钟，会话超时关闭，未保存变更落草稿 | 去 `plugins/liudungeon/bak/<副本ID>_edit_draft_<时间戳>/` 找草稿；地形在超时收尾时已同步回模板。日志关键字见 10.9 |
| 控制台执行 `/ld edit enter` 没反应 | 除 `status` / `help` 外，`/ld edit` 的子指令**只能由玩家执行** | 用游戏内管理员账号执行；控制台只用 `/ld edit status` 查会话 |

## 10.9 日志关键字速查

| 关键字 | 含义 |
|---|---|
| `[进本]` | 进本流程每个阶段 |
| `[出本]` | 出本与状态还原 |
| `[复活]` | 复活系统事件 |
| `模板克隆完成，用时 N ms` | 复制模板耗时，大图会明显变长 |
| `已加载区块 N` | **必须 > 0** |
| `安全落脚点 X,Y,Z` | 插件在配置出生点附近找到的可站立位置 |
| `副本实例已启动/已结束` | 生命周期边界 |
| `Error resolving libraries` | 依赖下载失败，插件未加载 |
| `实例世界 <名> 内没有找到任何区块文件！副本会是一片空白` | **模板是空的**（最常见的一类"世界开了但一片虚空"） |
| `模板「X」的目录就是正在运行的世界 Y` | 模板目录与一个正在加载的世界**指向同一个目录**，危险状态 |
| `已从 maps/ 目录加载 N 个地图模板` | 模板扫描结果，用来确认模板被识别到了 |
| `已清理 N 个上次残留的实例世界目录，释放 X` | 启动清理（受 `world.cleanup-orphans-on-start` 控制） |
| `编辑结果已同步回模板: <模板名>（副本 <副本ID>）` | 退出编辑时地形已同步回 `maps/<模板名>/` |
| `编辑世界同步回模板失败 <模板名>: … 会话世界目录 <路径> 保留` | 同步失败，会话世界目录**没有**被删 —— 可手动复制回 `maps/<模板名>/` |
| `编辑会话超时关闭: <副本ID>（未保存变更草稿: <路径>）` | 掉线超 10 分钟，未保存变更已落草稿 |
| `关服时编辑会话未保存，已落草稿: <路径>` | 关服 / 重载时还有未保存变更 |
| `编辑世界加载失败 <世界名>` | 编辑世界创建失败，随后会删掉半成品拷贝（见 10.8） |

## 10.10 反馈问题时请附上

```
/ld status
/ld doctor
/ld list
/ld template list        # 涉及"世界空白 / 磁盘不释放"时必带
```

以及**进本那一段完整日志**（从 `[进本] 请求进入` 到 `开本完成`）。
