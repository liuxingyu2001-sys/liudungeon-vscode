# 十一、附录：目录结构与文件清单

> [← 十、排错与常见问题](10-排错与常见问题.md) · [总目录](../05-使用说明.md)

## 11.1 服务端目录

```
<服务器根>/
├── libraries/                         Paper 下载的插件依赖（自动，勿手改）
├── ld_<模板名>_<8位ID>/                副本实例世界【落点 1】（出本即删，见 8.6 / 10.7）
├── plugins/
│   ├── liudungeon-x.y.z.jar       插件本体（约 0.5MB）
│   └── liudungeon/                    插件数据目录
│       ├── config.yml
│       ├── gui.yml
│       ├── data.db
│       ├── dungeons/<副本id>/          每个副本一套配置
│       ├── maps/<模板名>/              地图模板
│       ├── bak/                        编辑模式的备份与草稿（见 12.9）
│       │   ├── <副本id>_edit_<时间戳>/    `/ld edit save` 的旧文件备份（只含被改过的文件）
│       │   └── <副本id>_edit_draft_<时间戳>/  掉线超时/关服时的未保存变更草稿
│       ├── export/                    `/ld export` 与 `/ld doctor --json` 的输出
│       └── libs/                       脚本引擎依赖的手动放置位置（可选）
├── world/                             宿主世界（通常是主世界）
│   └── dimensions/minecraft/
│       ├── ld_<模板名>_<8位ID>/         副本实例世界【落点 2】—— 世界数据真正写在这
│       └── ld_<副本id>_edit/          编辑会话世界（仅编辑期间存在，见 12.2）
└── plugins/WorldGuard/worlds/          WorldGuard 的世界数据（若装了 WG，见 10.7）
```

> ⚠ 实例世界有**两处**落点，清理时必须都覆盖（插件自己会清，手工清的时候别漏）。
> 「宿主世界」不一定是 `world` 这个名字 —— 插件按 `Bukkit.getWorldContainer()` 定位，
> 遍历的是**任意非实例世界**。

## 11.2 一个副本的配置目录

```
dungeons/<副本id>/
├── config.yml          基础信息 / 世界（含世界规则）/ 进入要求 / 黑名单 / 时限 / 实例 / 复活 / 扫荡（sweep）
├── scripts.yml         生命周期脚本（7 个钩子）
├── monsters.yml        怪物组（波次）
├── stages.yml          阶段流程机
├── zones.yml           区域与命名点位
├── obstacles.yml       障碍物：可开关的方块组（见 6.6）
├── interacts.yml       交互点
├── tasks.yml           定时/循环/事件任务
├── rewards.yml         奖励（固定 / 权重随机 / 保底）
├── chest_rewards.yml   箱子 UI 奖励（⚠ 已解析但**未实现**，见 6.12；示例副本已不再生成它）
├── 说明.md             副本速览（流程 / 文件清单 / 想改什么去哪；/ld create 会自动带一份）
└── *.js                JavaScript 函数库
```

**任何单个文件解析失败都不会让副本整体加载失败** —— 问题会记入 `/ld doctor` 报告，
方便逐个修。唯一必需的是 `config.yml`。

> 用 `/ld edit` 在游戏里改这些文件时，旧版本会备份到 `plugins/liudungeon/bak/`（见 12.9），
> 副本目录本身不会多出任何文件。
