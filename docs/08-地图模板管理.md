# 八、地图模板管理

> [← 七、脚本开发指南](07-脚本开发指南.md) · [总目录](../05-使用说明.md) · [九、PlaceholderAPI 变量 →](09-PlaceholderAPI变量.md)

## 8.1 先有副本，还是先有模板？

两者独立，可以先有任何一个：

- **什么都不用先做**：插件内置了一张虚空世界 `voidgen`（见 8.2.1），
  `/ld create <副本ID>` 建出来的副本默认就用它，**建完就能进**。
- **先建副本、之后再换地图**：`/ld create <副本ID>` 之后按 8.3 导入自己的地图，
  再把副本 `config.yml` 的 `world.template` 改掉。
- **先导入模板**：按 8.3 导入，再 `/ld create <副本ID> <模板名>` 建副本指向它。

`/ld create` 不写模板名时的取值顺序：**同名模板存在就用同名的，否则用内置 `voidgen`**
（以前的默认值是"副本 ID 当模板名"，而服主极少真的先导一张同名地图 ——
于是建出来的副本一开本就报「模板世界不存在」）。它**不会**替你导入世界 ——
导入需要一个已加载的源世界，得由你指定。

## 8.2 模板放在哪

**模板一律放在 `plugins/liudungeon/maps/<模板名>/`**，不放服务器根目录。

这样做的好处：模板不会随服务器启动被当成世界加载。一个正在被加载的世界如果同时充当模板，
服务端会持续往里面写盘，副本复制时会连它当时的实体一起克隆进副本。

> 插件会在检测到「模板目录**就是**某个运行中世界的目录」时告警。
> 注意判定是按**路径**比对的，不是按名字 —— 你的世界叫 `forgedungeon`、
> 模板也叫 `forgedungeon` 但两者是完全不同的目录时，不会误报。

### 8.2.1 内置的虚空世界 `voidgen`

插件第一次启动时会自己在 `plugins/liudungeon/maps/voidgen/` 生成一张**虚空世界**，
开箱即用：磁盘上只有两个文件（约 **250 字节**），**没有一个区块文件** ——
区块由服务端按生成器设置按需生成，所以既不占磁盘、也不给每个副本留 2.4 MB 的预生成地形。

```
plugins/liudungeon/maps/voidgen/
├── level.dat                          # 世界元数据（约 190 字节）
└── data/minecraft/
    └── world_gen_settings.dat         # 生成器设置（约 250 字节）← 虚空就定义在这里
```

它长什么样：**什么都没有，只有 y=64 的一层基岩地板**（出生点在 `0,65,0`，站在那层基岩上），
生物群系是平原（怪物能刷、光照正常）。适合"自己从头搭地牢"，也适合先跑通流程再换地图。

> 服主实测的那份虚空世界有 4 个 `region/*.mca`、576 个区块、2.4 MB 大小，
> 而里面同样只有一层基岩 —— 同样的事用生成器设置表达只要 250 字节，所以内置模板不塞区块数据。

**关于它的几条规则**：

| 情况 | 行为 |
|---|---|
| `maps/voidgen` 不存在 | 首次启动自动生成；日志里会写 `已生成内置虚空世界模板 maps/voidgen（虚空 + y=64 一层基岩地板，无区块文件…）` |
| `maps/voidgen` **已经存在** | **一个字都不改**（哪怕是你自己导入的同名地图）—— 服主的数据优先 |
| 删掉它 | 下次启动会重新生成（因为它同时也是新副本的默认模板） |
| 我导入过一份自己的 `voidgen`，想换回内置的小模板 | 把 `maps/voidgen/` 整个**搬出 `maps/`**（例如 `mv maps/voidgen ../voidgen-旧地图`），下次启动自动重生成。**别**改名成 `maps/voidgen.bak/` —— 只要目录里有 `level.dat` 或 `region/`，它就会被当成一张模板列进 `/ld template list` |
| 想换成自己的地图 | 用 `maps/` 下**别的名字**（如 `my_dungeon`）导入，再把副本 `config.yml` 的 `world.template` 改过去 |
| 想改地板高度 | 改的是插件代码里的 `VoidTemplate.FLOOR_Y`，不是你该动的东西 —— 直接用编辑器铺你自己的地板更省事 |

⚠ **它只有一层基岩，脚下是虚空**：`world.spawn` 写 `0,65,0`（母本默认值）就站在地板上。
如果你把出生点填到地板上方很高，玩家会摔下来（插件会找安全落脚点，但只在配置坐标附近 ±4 格内找）。

> **换成内置模板能省多少**（实测，见[第四十六节](../04-开发进展记录/15-副本世界压测.md)）：
> 每次进本真正写盘的就是"克隆模板"这一份，所以模板体积 = 每次进本的开销。
> 实测单轮：一份 2.6 MB 的区块世界写 **2,599,255 字节**，内置生成器模板只写 **1,033 字节**
> （差约 2500 倍；按 40 次进本算，前者约 104 MB、后者约 41 KB）。
> 而副本里面玩出来的东西**两边都是一个字节都不落盘** —— 改方块、刷怪、按需生成的地形都不写盘。

## 8.3 导入

```
/ld template import <地图名>                     # 模板名 = 地图名
/ld template import <地图名> <模板名>             # 指定模板名
/ld template import <地图名> <模板名> --overwrite # 覆盖已有模板
```

> ⚠ **模板名只能用 `A-Z a-z 0-9 _ -`**（源码强制校验）。中文名会被拒绝 ——
> 注意 `/ld template import` 自带的帮助示例写的是中文名，那是**帮助文案本身有误**，
> 别照着抄。要中文显示名请改副本 `config.yml` 的 `dungeon.name`。

> ⚠ **`--overwrite` 有丢图风险，先看清楚再用**：实现是「找到源目录 → 删掉目标模板目录 →
> 把源复制过去」。而查找来源的第 4 顺位就是 `maps/<模板名>` **本身** ——
> 如果你要导入的地图只存在于模板目录里（即"想刷新自己"），
> `source` 和 `dest` 会指向同一个路径，于是**先删后复制 = 把模板删空**。
> 目前代码没有防这一手（已记录为待修）。
> **安全用法**：源必须是服务器根目录或维度目录里的地图，不要用模板自身当源；
> 操作前先备份 `plugins/liudungeon/maps/<模板名>/`。

**导入时只做两件事**：

1. **补齐 `level.dat`** —— 详见 8.4
2. **维度目录改名** —— 主世界维度目录统一改名为 `overworld`，与实例世界名解耦

> ⚠ **区块布局的规范化不在导入时做，而是在「开本复制实例」时自动做**
> （`WorldLayoutNormalizer` 在 `copyTemplate()` 里调用）。
> 所以模板目录里区块还在 `dimensions/minecraft/overworld/region/` 是**正常的**，
> 不需要手工搬 —— 开本时插件会自己处理。

**查找导入来源的顺序**（`locateSource()`，4 条，前一条找不到才试下一条）：

| # | 位置 | 说明 |
|---|---|---|
| 1 | `<服务器根>/<地图名>` | 服务器根目录下的世界文件夹 |
| 2 | `<世界>/dimensions/minecraft/<地图名>` | Paper 26.x 的维度落点（`/mv import` 常在这） |
| 3 | `<世界>/<地图名>` | 旧式回退路径 |
| 4 | `plugins/liudungeon/maps/<地图名>` | 已导入过的模板（⚠ 见下方 `--overwrite` 警告） |

## 8.4 关于 level.dat（很重要）

不同服务端实现写出来的 `level.dat` 结构**完全不同**。以 Leaf 26.2 为例：

| 字段 | 原版 / 老式 | Leaf 26.2 |
|---|---|---|
| 出生点 | `SpawnX/SpawnY/SpawnZ` | `spawn:{pos:[x,y,z], yaw, pitch, dimension}` |
| 难度 | `Difficulty=1` | `difficulty_settings:{locked, difficulty:'hard', hardcore}` |
| 地形设置 | `WorldGenSettings.dimensions` | level.dat 里**没有**这项，拆到了 `data/minecraft/world_gen_settings.dat` |

所以**手写一份 level.dat 是行不通的** —— 字段集对不上，服务端会直接报：

```
IllegalStateException: Overworld settings missing
```

插件的做法是**底板法**：

1. 找一份**服务器自己产出的** `level.dat` 当底板（优先主世界）；
2. 只改 `LevelName`、出生点、`LastPlayed`，其余字段原样保留；
3. 写临时文件 + 原子替换。

这样字段结构永远和当前服务端一致，不需要维护任何字段兼容表。

**地形设置从哪来？** Leaf / Paper 26.x 把世界生成设置放在
`data/minecraft/world_gen_settings.dat`，它随模板一起被复制，服务端会优先用它。
所以模板里的地形不会被重新生成。

## 8.5 模板维护指令

| 指令 | 作用 |
|---|---|
| `/ld template list` | 列出所有模板 |
| `/ld template info <模板名>` | 查看大小、区块文件数、`level.dat` 状态、被哪些副本引用、维度目录 |
| `/ld template repair <模板名>` | **只重建 level.dat，不重新复制地图** |
| `/ld template delete <模板名>` | 删除模板（带路径安全检查） |
| `/ld template reload` | 重新扫描 maps 目录 |

`repair` 是为大图准备的：模板地图动辄几个 GB，仅仅因为 `level.dat` 结构不对就重新导入
代价太大。`/ld template info` 会显示 `level.dat 正常` 或具体问题，看到异常直接 repair 即可。

## 8.6 实例世界

- 命名规则：`ld_<模板名>_<8位随机ID>`，例如 `ld_forgedungeon_82f8f213`
- 出本后自动删除。**要清的地方有三处**（少清任何一处都会慢慢攒垃圾）：
  1. 服务器根目录下的 `ld_xxx/`
  2. 宿主世界（通常是主世界）下的 `dimensions/minecraft/ld_xxx/`
  3. **`plugins/WorldGuard/worlds/<世界名>/`** —— 装了 WorldGuard 才有；实测十几次开本能攒下近十个
     目录（WorldGuard 自己的世界数据是按世界名建的，删世界不会自动带走）
- 服务器异常退出后可能残留，启动时会自动清理孤儿目录 ——
  ⚠ 这依赖 **`world.cleanup-orphans-on-start`（默认 `true`）**，把它设成 `false` 就不会清了
