## 6.0 本章导航：文件清单、键名规则与容错

### 文件清单与「缺失会怎样」

```
plugins/liudungeon/
├── config.yml               插件主配置（6.1）
├── gui.yml                  GUI 菜单配置（见第五章）
├── data.db                  SQLite 数据库文件
├── maps/<模板名>/            地图模板（见第八章）
└── dungeons/<副本ID>/        一个副本 = 一个目录
    ├── config.yml           唯一必需的文件（6.2）
    ├── monsters.yml         怪物组（6.3）
    ├── stages.yml           阶段流程机（6.4）
    ├── zones.yml            区域与命名点位（6.5）
    ├── obstacles.yml        障碍物：可开关的方块组（6.6）
    ├── interacts.yml        交互点（6.7）
    ├── tasks.yml            定时/循环/事件任务（6.8）
    ├── rewards.yml          奖励（6.9）
    ├── chest_rewards.yml    箱子 UI 奖励（6.10）
    ├── scripts.yml          生命周期脚本钩子（见第七章）
    └── *.js                 JavaScript 函数库（目录下所有 .js 都会被读入）
```

| 文件 | 必需 | 缺失的后果 |
|---|---|---|
| `dungeons/<id>/config.yml` | **是** | 该目录被**整份跳过**，报「缺少 config.yml」 |
| `monsters.yml` | 建议 | 记为问题，副本没有任何怪物可刷 |
| `scripts.yml` | 建议 | 记为问题，副本没有开场与结算流程 |
| `stages.yml` | 否 | 阶段机完全不介入，行为与没有阶段一样 |
| `zones.yml` | 否 | 没有区域与命名点位（引用点位处回退出生点） |
| `interacts.yml` / `tasks.yml` | 否 | 对应功能为空 |
| `obstacles.yml` | 否 | 没有可开关的障碍物（脚本调 `create_obstacle` 会报「不存在」） |
| `rewards.yml` | 否 | `action.grant_reward` 会报「奖励不存在」 |
| `chest_rewards.yml` | 否 | 无箱子 UI（该文件当前整体未生效，见 6.12） |
| `*.js` | 否 | 脚本里不能调用自定义函数（`announceWave` 之类） |

目录级规则：

- **目录名就是副本 ID**，`/ld enter <ID>` 用的就是它（也支持用去色后的显示名）。
- 以 `.` 开头、或以 `_backup` 结尾的目录会被跳过（留给你放备份）。
- 示例目录 `dungeons/example/` 只在不存在时生成，**不会覆盖你改过的内容**。
- 示例的 `world.template` 是 `voidgen` —— 插件内置的虚空世界，所以**示例副本开箱即可进入**。

> **解析原则：任何一个文件写错，都不会让副本整体加载失败。**
> 问题会记进 `/ld doctor` 报告，其余部分照常工作。

### 中英双语键名

副本目录下的 10 个 YAML **都支持中文键名**（对齐 QueDP 的配置习惯）——
⚠ **唯一例外是 `scripts.yml`**：它的 7 个钩子名（`init` / `start` / `complete` / `exit` /
`fail` / `player_death` / `all_death`）**只认英文**，没有中文别名；
`start` 段内部的 `条件` / `脚本` 和连字符写法才有别名。
所以 `name` 与 `名称`、`location` 与 `位置` 都能用。

| 规则 | 行为 |
|---|---|
| 别名顺序 | 每个字段声明一串别名（英文主键 + 中文别名），**按声明顺序探测，命中即返回** |
| 优先级方向 | **各文件不一致**：`zones` / `stages` / `interacts` / `rewards 的保底段` 是**中文优先**；`monsters` / `tasks` / `chest_rewards` / 副本 `config.yml` 是**英文优先**。**同一字段不要中英都写**，否则结果取决于代码里的顺序 |
| 取不到值 | 一律**回落默认值**，不抛异常、不打断加载 |
| 主配置 | `plugins/liudungeon/config.yml` **不支持中文键**（走原版 `getConfig()`，键名写错 = 用默认值） |

### 类型容错规则（**「配了没反应」的第一嫌疑人**）

插件对写错的配置极其宽容：不崩、不报错、回落默认值。代价是**问题往往不显眼**。
下面这些写法都会**静默失效**：

| 字段类型 | 正确写法 | ⚠️ 会静默失效的写法 |
|---|---|---|
| 整数 | `1800`、`"1800"` | `1800.0`（小数回落默认值，**不是**取整）、留空 |
| 布尔 | `true` / `false`；字符串 `"true"/"1"/"yes"/"on"/"是"/"开"` 与 `"false"/"0"/"no"/"off"/"否"/"关"` | **写成数字 `1` / `0`（不带引号）** —— YAML 解析成整数后，`isBoolean` 与 `isString` 都为 false，于是**回落默认值**。这是最容易踩的一条 |
| 字符串列表 | YAML 列表；单个字符串（当作一项）；多行块 `\|-`（整块当作**一条**脚本，可含 if/else）| `''` 空串 → 空列表（等价于没写） |
| 子段 | `xxx:` 缩进若干行；`xxx: {}` 也可 | 只写段名不给内容（值为 null）等价于「没写这一段」 |
| 含特殊字符的值 | 加引号，如 `范围: '0,64,0 ~ 10,70,10'` | 冒号后漏空格（`范围:'a~b'`）会被当成一个普通键名 |
| 列表形态的键名 | `monsters` / `items` / `options` | **列表形态只认英文键名**。写成 `怪物:` + 列表不会生效，该组会变成 0 个怪物并直接判定完成 |

> **排查口诀：「配了没反应」先看类型。** 绝大多数是布尔写成了 `1`、整数写成了 `1800.0`，
> 或者把段写成了标量。

> **脚本字段统一写成 `|-` 块**：一行一条语句、行尾加分号，例如
> `complete: |-` 下面依次写 `action.title(...);` / `action.grant_reward(...);`。
> 块里是纯 JavaScript，注释要用 `//`（写 YAML 的 `#` 会变成语法错误）；
> 也别给整行套引号 —— 那会变成一个什么都不做的字符串字面量。
> 老配置里的 `- "action.xxx()"` 列表写法仍然兼容。完整规则见
> [07 的 7.1.1](07-脚本开发指南.md#711-脚本怎么写统一这一种排版)。

开启后会在启动后自动跑一次核心链路自检（模板克隆 → 世界加载 → 世界规则 →
脚本执行 → 刷怪 → 击杀推进 → 世界销毁），结果打到控制台。**生产环境保持关闭。**

### 出本时到底还原了什么

进本时记一份玩家状态快照，出本时按四类处理（**行为固定，没有开关**）：

| 类别 | 内容 | 出本时 |
|---|---|---|
| **还原** | 位置、游戏模式与飞行（倒下等复活时会被切成旁观者，不还原会卡住） | **一律还原** |
| **出本兜底** | 结束时仍处于**倒下 / 已阵亡**的玩家 | 扶起来：切回生存、给**半血**、灭火、60 tick 无敌（不扣次数、不发消息、不跑复活脚本） |
| **不还原**（2026-09-16 起停用） | 血量、饱食度、着火、空气、**药水效果**、移速与飞度、发光 | **一律不动** —— 副本里的变化会带回主世界，需要就自己用脚本收尾 |
| **产出类** | **背包**（物品+盔甲+副手）、**经验** | **一律不碰** |

> 状态类为什么停用：采集血量上限读的是 `attr.getValue()`（基数 + 修饰符），还原写的是
> `attr.setBaseValue()`（基数），两边不对称 —— 只要穿一件加血量上限的装备，
> 每进/出一次副本基数就被抬一次（`20(+10) → 30(+10) → 40(+10) …`）。代码保留在
> `PlayerSnapshot.restore()` 里备用；重新启用前必须先确认采集侧读 `getBaseValue()`。
> 副作用：**药水效果不会清**（副本 buff / 诅咒跟出本）、血量 / 饱食度 / 着火保持副本里的样子、
> 被脚本改过的移速不会自动恢复；唯一例外是倒下 / 已阵亡的玩家（他们进本被压到 1 点血）。
>
> 产出类为什么不还原：快照记的是**进本前的装备**，而插件从不在进本时清空背包 ——
> 覆盖回去只会抹掉你在副本里拿到的东西（含 `action.grant_reward()` 的奖励），
> 通关脚本「先 `grant_reward` 再 `exit_dungeon()`」会被它毁掉。**故意不提供开关**：
> 能配错的东西迟早会被配错。

## 6.2 副本 `config.yml`

### 顶层 `enable` / `hide` —— 副本总开关与隐藏

| 键 | 默认 | 作用 |
|---|---|---|
| `enable` | `true` | `false` = **停用**：GUI 里显示为屏障、任何进入途径都被拒 |
| `hide` | `false` | `true` = **不在列表里显示**（GUI 与 `/ld list` 都看不到），但 `/ld enter <副本ID>` 仍可进入 |

两个键都可以写中文（`启用` / `隐藏`），也接受 `enabled` / `hidden`。

```yaml
enable: true      # 能不能进
hide: false       # 列不列出来
```

**两者的分工**：

| 想要的效果 | 怎么配 |
|---|---|
| 这个副本临时下线，谁都别进 | `enable: false` |
| 副本能玩，但不想挂在列表里（活动 / 测试副本） | `hide: true` |
| 完全删掉 | 删目录（会连带丢掉配置与地图关联，不推荐） |

### 顶层 `enable` 详解 —— 停用之后会发生什么

`enable: false` 时：GUI 里显示为**屏障**（不可点击，注明「该副本已停用」）；任何进入途径
（GUI / `/ld enter` / 脚本 `action.*`）都被拒；**配置照常加载**，`/ld doctor` 依然能体检它，
改回 `true` 再 `/ld reload` 即可上线。

- 停用的判断排在进入校验的**最前面**，不会因为「人数不足」「冷却中」给出误导性原因。
  与 `requirements` 的分工：后者是**对玩家**的限制（等级/人数/费用），`enable` 是**整个副本**的开关。
- `hide: true` **不影响进入条件** —— 知道 ID 的人照样能进（带 `liudungeon.admin` 的玩家始终
  看得到隐藏副本）；要限制人请用 `requirements` 的权限/等级/门票，或干脆 `enable: false`。

> ⚠️ **不要改内置示例里的这两个默认值**：`src/main/resources/example/config.yml` 同时是
> `/ld create <副本ID>` 抄给新副本的**母本**（原样复制，只改写展示名与模板名）。改成
> `enable: false` 的话，以后每个新建副本一出生就是停用且不显示的。要下线副本，改**那个副本自己**的
> `config.yml`（见 [第三十八节](../04-开发进展记录/10-建本母本与扩展打包.md)）。

#### 演示副本 `example` 不在这两个键的管辖范围内

`dungeons/example/` 是插件自己的演示数据，不是你建的副本：**不出现在 GUI、`/ld list`、
任何补全里**（连管理员也不显示，这是插件的固定行为，不是 `hide` 那种配置状态）；但
`/ld enter example`、`/ld info example`、`/ld edit enter example` 照常可用，也照常参与
`/ld doctor` 体检与「模板被谁引用」。想拿它当起点就用 `/ld create <副本ID>` 建一份，别直接改它。

### `dungeon` 段 —— 基础信息

| 键 | 默认值 | 说明 |
|---|---|---|
| `name` | 副本 ID | 显示名，支持颜色代码 |
| `icon` | `DIAMOND_SWORD` | GUI 里的图标材质 |
| `difficulty` | `普通` | 难度标签，仅展示 |
| `description` | 空 | 描述行列表 |
| `death_check_mode` | `strict` | `strict` / `lenient`。⚠️ **仅用于 `/ld info` 展示，不影响实际行为** —— 全灭判定固定走"还有人能起来就不算全灭"的逻辑。见 [6.12](#612-已解析但未生效的字段) |

### `world` 段 —— 世界配置

| 键 | 默认值 | 说明 |
|---|---|---|
| `template` | `voidgen` | 模板名，对应 `plugins/liudungeon/maps/<这个名字>/`。**默认的 `voidgen` 是插件内置的虚空世界**（首次启动自动生成，只有几百字节、无区块文件，地板是 y=64 的一层基岩）—— 所以不导入任何地图也能开本。换成自己的地图：`/ld template import <地图名> [模板名]`，再把这里的名字改掉 |
| `spawn` | `0,64,0,0,0` | 出生点 `x,y,z,yaw,pitch`（写在 **`world` 段**里）。**不需要精确**，插件会自动找安全落脚点。⚠ 写在 `dungeon` 段里的 `dungeon.spawn` **不生效**（没有任何读取点，`/ld doctor` 会报出来）—— 出生点只有这一处 |
| `border` | `-1` | 世界边界**半径**，`-1` = 不设置。见下方注意 |
| `world_rules` | 内置默认 | 见下 |

`world_rules` 内置默认值（共 **10 条**，取自 `WorldRuleApplier.recommendedDefaults()`，用 Paper 26.x 的新式 id）：

| 规则 | 值 | 作用 |
|---|---|---|
| `keep_inventory` | `true` | 死亡不掉落（副本必开） |
| `spawn_mobs` | `false` | 关自然刷怪，由怪物组精确控制 |
| `advance_time` | `false` | 关昼夜交替 |
| `advance_weather` | `false` | 关天气循环 |
| `mob_griefing` | `false` | 关怪物破坏方块 |
| `natural_health_regeneration` | `false` | 关自然回血 |
| `show_advancement_messages` | `false` | 关成就播报 |
| `immediate_respawn` | `false` | 保留死亡界面（复活系统需要） |
| `mob_drops` | `true` | 怪物掉落 |
| `entity_drops` | `true` | 实体掉落 |

```yaml
world:
  world_rules:
    time: night                # day / night / 数字 tick；⚠ 不写【不改世界时间】
    storm: false               # 是否雷雨
    keep_inventory: true
    pvp: false                 # 玩家之间能否互相伤害（false = 副本内队友之间不掉血）
    advance_time: false
```

除 `time` / `storm` / `border` 三个保留键外，**这一段里的其余键都会被当成 GameRule 写入**，所以：

- **名字写错不报错，只是那条规则不生效**（`GameRule.getByName` 是精确大小写查表）。插件做了多级容错
  （原样查 → 补 `minecraft:` → 驼峰转下划线 → 去命名空间/下划线归一化），`keep_inventory` /
  `keepInventory` / `KEEP_INVENTORY` 都能命中；旧名另有映射（`doDaylightCycle` → `advance_time`、
  `doWeatherCycle` → `advance_weather`、`doMobSpawning` → `spawn_mobs`、`naturalRegeneration` →
  `natural_health_regeneration`、`announceAdvancements` → `show_advancement_messages`）。
- `doFireTick` 在 26.x **已移除且无等价项**，会被报成「未知规则」（刻意不映射到别处）。
- 生效结果会打印在日志与 `/ld doctor` 里：「已应用 N 条，未知规则 N 条，失败 N 条」，**改完一定要看这行**。
- 值类型由代码按 `GameRule.getType()` 分派（`random_tick_speed` 是整数，其余多为布尔），
  类型不支持的值记入「失败」而不是崩服。
- **`pvp: false` 是关闭"队友互相伤害"的正确方式**：26.x 起 pvp 就是每条世界自己的 GameRule，
  插件在建实例世界时写入（早于传送玩家）。它挡的是**直接攻击**（近战/弓箭/长矛/狼）；
  玩家引爆炸药与伤害药水不受这条管。

**边界有两个键**：`world.border` 与 `world.world_rules.border` 都能用，优先级后者更高，写一个即可。

### `requirements` 段 —— 进入要求

> **这四项「不写 = 不判定」**：`min_level` / `max_level` / `min_players` / `max_players`
> 把行注释掉、写成 `min_players:`（留空）、或整个 `requirements` 段删掉，
> 该项就**完全不参与校验**，不会套用任何内置默认值。
> 只写一半也允许：只写 `min_players` 就是"上不封顶"，只写 `max_level` 就是"下不设限"。
>
> 判断依据是"这一项能不能拦住人"：`min_level: 0`、`max_players: 0` 这类值
> 拦不住任何人，界面上按"不限"显示（`/ld info` 里显示"人数: 不限 / 等级: 不限"）。
>
> ⚠️ **历史行为已变**：旧版本这四项有兜底默认值 `1` / `100` / `1` / `4`，
> 所以注释掉 `max_level: 100000` 不是"放开等级"，而是把上限**收窄到 100 级** ——
> 而且界面上照样显示"等级 1-100"，看不出那是默认值还是自己写的。现已修正。

| 键 | 默认值 | 说明 |
|---|---|---|
| `min_level` / `max_level` | **不判定** | 等级区间；不写就不判等级 |
| `min_players` / `max_players` | **不判定** | 人数区间；不写就不判人数 |
| `cooldown` | `0` | 再次进入的冷却（秒），`0` = 无冷却 |
| `money_cost` | `0` | 入场费用（需 Vault），按**每人**结算 |
| `stamina_cost` | `0` | 体力消耗（需主配置开启 `stamina`，⚠️ 未实现） |
| `required_items` | 空 | 门票，格式 `物品ID:数量` |
| `item_check_mode` | `ALL` | `ALL` 所有成员都需持有 / `LEADER` 仅队长持有 |
| `required_permissions` | 空 | 进入所需权限节点，可自定义任意节点名 |
| `placeholder_conditions` | 空 | PAPI 条件，格式 `"%占位符%" 运算符 值`，运算符 `>= <= > < == !=`；每个在线成员都需满足 |
| `daily_limit` | `0` | 每日进入次数上限，`0` = 不限；重置时刻见 `dungeon.daily-reset` |

**注意 `cooldown` / `money_cost` / `daily_limit` 与上面四项的规则不同**：
它们的 `0` 本身就是"不生效"，没有"未配置"一说，所以照旧用 `0` 关闭即可，
不需要注释掉。换句话说，"注释掉 = 不判定"只适用于**区间型的门槛**
（人数、等级），因为它们没有一个能表示"不判"的数字。

### `blacklist` 段 —— 副本内限制

| 键 | 说明 |
|---|---|
| `commands` | 副本内禁用的指令（**不带前导斜杠**） |
| `items` | 禁用/禁止带入的物品。进入前还会检查头盔/胸甲/护腿/靴子槽，**穿着黑名单装备会被拒绝进入** |

### `time` 段 —— 时间限制

| 键 | 默认值 | 说明 |
|---|---|---|
| `limit` | `1800` | 秒，`0` = 不限时。⚠ 默认 **1800 秒（30 分钟）**，想让副本不限时必须显式写 `0` |
| `timeout_action` | `FAIL` | `FAIL` 标记失败并触发失败脚本；`KICK` 直接踢出玩家 |

### `instance` 段

| 键 | 默认值 | 说明 |
|---|---|---|
| `max_instances` | `-1` | 同时运行的最大实例数，`-1` = 无限制 |

### `revive` 段 —— 复活系统

**有键才启用**：写了 `auto.delay` 就是要自动复活，没写就是不要（不存在 `enabled: true`）。

| 键 | 默认值 | 说明 |
|---|---|---|
| `count` | `0` | 复活次数，`-1` = 无限，`0` = 禁止。⚠ 默认**禁止复活**，想要复活必须显式给次数 |
| `count_mode` | `shared` | `shared` 全队共用一个池 / `independent` 每人各自计数 |
| `auto.delay` | 未启用 | 自动复活延迟（秒） |
| `auto.at` | `spawn` | 落点：`spawn` 出生点 / `inplace` 原地 / `区域.点位` |
| `ally.cast_time` | 未启用 | 队友读条秒数 |
| `ally.range` | `4.0` | 队友救援距离 |
| `ally.consume_count` | `true` | 队友救起是否消耗次数 |
| `ally.at` | `inplace` | 落点 |
| `on_revive` | 空 | 复活成功后执行，`@trigger` = 被复活者 |
| `on_exhausted` | 空 | 复活成功且**剩余次数刚变为 0** 时执行一次（人已站起，副本继续 —— 这不是"结束"） |

三种方式**可以同时开启，谁先成立谁生效**；`count` 与它们是「与」的关系：`count: 0`（含不写）
等于禁止复活，`auto` / `item` / `ally` 配了也不生效。次数池是唯一的"资源"：
自动复活、道具、队友救起（`consume_count: true`）都从同一个池里扣。

#### 次数为 0 时不会再提示"还有救"

倒下提示只列**真能成功**的路（`ReviveService.planDowned()`，纯函数；可跑 `bash tools/verify-revive-prompt.sh` 看规则）：

| 次数为 0（池子用光）时 | 行为 |
|---|---|
| 自动复活 | **不挂倒计时**，不再发「N 秒后自动复活」 |
| 道具复活（`consume_count: true`） | **不显示**「点击使用 xx 复活」按钮（否则道具被扣、人却没起来） |
| 队友救起（`consume_count: true`） | 读条到点被拒（「该玩家已没有复活次数」），不算"有人能来救" |
| 道具 / 队友救起（`consume_count: false`） | 照常提示、照常能救 —— 次数为 0 也成立 |
| 都不成立 | 只发「&c复活次数已用完&7 —— 没有可用的复活方式了」，紧接着按"确认阵亡"处理 |

#### 次数耗尽 / 全队阵亡之后会发生什么

| 事件 | 触发时机 | 副本会怎样 |
|---|---|---|
| `on_exhausted` | 某次复活**成功**、剩余次数刚变成 0 | **继续**：人被救起来了，只是再倒下就没机会了。适合发提示 |
| `all_death` | 全队都「已阵亡」、没人能再起来 | 先跑 `scripts.yml` 的 `all_death` 脚本；**跑完后若仍无活人，插件自动判失败并在 10 秒后把所有人传回主世界** |

```yaml
# scripts.yml
all_death: |-
  action.title('@all', '&c&l全队阵亡', '&7副本失败，正在退出…');
  action.fail('全队阵亡');   // 判失败：跑 fail 钩子 → 10 秒后全员退出
  // action.revive('@all');   // 或者给一次"复活赛"，那就不会判失败
```

> 次数用光后自动复活失败，日志是 **`INFO`** 级（`[复活] 玩家 自动复活失败：复活次数已耗尽…`）
> —— 这是配置按预期生效，不是故障。真正的 `WARN` 只留给一种：`count: 0` 却还留着 `auto` 倒计时
> （配置自相矛盾，倒计时永远不可能成功）。

## 6.3 `monsters.yml` 怪物组（波次）

```yaml
groups:
  wave_1:
    spawn_timing:
      type: AUTO_START      # 见下表
      delay: 0              # DELAYED 时的延迟秒数
    condition: []           # 可选：条件成立才刷
    on_start: |-            # 刷怪前执行
      announceWave(1, '第一波', '清理所有敌人');
    on_end: |-              # 该组清空后执行
      action.message('@all', '&a第一波已清除！');
      action.wait('3秒');
      action.spawn_group('wave_2');
    monsters:
      - id: Zombie
        location: '0,64,-10'
        amount: 3
        level: 1
```

**`spawn_timing.type` 取值**

| 值 | 含义 |
|---|---|
| `AUTO_START` | 地牢开始时自动刷新 |
| `DELAYED` | 地牢开始后延迟 N 秒刷新 |
| `TRIGGERED` | 指定怪物组完成后自动触发（配合 `trigger_group`，**与 `spawn_timing` 同级**） |
| `MANUAL` | 手动用 `action.spawn_group()` 触发 |
| `SCRIPTED` | 由脚本控制 |

**推荐写法（不用写脚本）：第一波 `AUTO_START`，后续波次 `TRIGGERED`。**

```yaml
groups:
  wave_1:
    spawn_timing:
      type: AUTO_START        # 进本立刻刷
    monsters:
      - { id: Zombie, location: '0,64,-10', amount: 3 }

  boss:
    spawn_timing:
      type: TRIGGERED
    trigger_group: wave_1     # ⚠ 写在组这一层，不要写进 spawn_timing 里面
    on_end: |-
      // Boss 清空 = 通关
      action.complete_dungeon();
    monsters:
      - { id: Husk, location: '0,64,-20', amount: 1, boss: true }
```

> `trigger_group` 的位置很容易写错：它读的是**组这一层**的键。
> 写进 `spawn_timing:` 里面不会报错，但那一组永远不会被触发 —— 玩家打完第一波后
> 就卡住了，而且没有任何提示，是新手最常见的一个坑。

> 想精确控制节奏（例如"等玩家踩了踏板再放下一波"）时，再用
> **`MANUAL` + 上一波的 `on_end` 调 `action.spawn_group('下一波')`**。

**怪物 `id` 的解析规则**（按顺序尝试）

1. 装了 MythicMobs 时，**优先当成 MM 怪物 ID**（如 `DZ_僵尸`、`Elite_Guard`）
2. 否则按原版实体名解析，大小写不敏感，也支持 `DZ_ZOMBIE` 这类带前缀的写法
   （依次尝试整名、大写、最后一段下划线之后、第一段下划线之前）

**组级增强字段（全部可选）**

| 字段 | 说明 |
|---|---|
| `zone` | 组默认区域，成员可用 `point` 引用该区域的点位 |
| `repeat.interval` | 重复生成间隔（tick） |
| `repeat.max` | 重复次数上限（**必须有**，否则无限增援） |
| `repeat.wait_cleared` | 前一轮没清完就跳过本轮（不计入轮次） |

**成员级增强字段（全部可选）**

| 字段 | 说明 |
|---|---|
| `point` | 引用 `区域.点位`；写 `区域.点位` 可跨区域 |
| `amount: "3-6"` | 区间随机，单成员单次上限 32 |
| `chance: 30` | 30% 概率出现 |
| `delay: 60` | 延迟 60 tick 生成 |
| `boss: true` | 击杀触发 `boss_kill` 任务并推进阶段 |
| `when: "getVar('难度') >= 3"` | JS 表达式，不成立则跳过 |
| `replace_with: Elite_Guard` | `when` 成立时改用这个 ID |

## 6.4 `stages.yml` 阶段流程机

给副本一条主线「清怪 → 开门 → Boss → 结算」，**完全事件驱动，没有定时器轮询**。
不建这个文件 = 副本行为与以前完全一致。

```yaml
入口: 清怪

清怪:
  名称: '&e清理前厅'
  通关条件: "dungeon.isGroupCleared('wave_1')"   # JS 表达式，返回真值即完成
  超时: 300                                       # 秒，0 或不写 = 不限时
  开始脚本: |-
    action.title('@all', '&e第一阶段', '&7清理所有敌人');
    action.spawn_group('wave_1');
  通关脚本: |-
    action.setblock('20,64,0,AIR');
  超时脚本: |-
    action.fail('前厅超时');
  下一阶段: Boss战

Boss战:
  通关条件: "dungeon.isGroupCleared('wave_2')"
  下一阶段:                       # 分支写法：按列表顺序判定，第一个成立的命中
    - 目标: 隐藏房
      条件: "getVar('找到密道') == 1"
    - 目标: 结算                   # 无条件兜底
```

字段：`名称`、`通关条件`、`超时`、`开始脚本`、`通关脚本`、`超时脚本`、`下一阶段`。

- `下一阶段` 写单个名字 = 无条件跳转
- 写列表 = 按顺序判定分支，**都不成立则走无条件兜底**
- 没有兜底则视为最终阶段，副本直接通关
- 跳转最多 8 跳，防止配置写出死循环

## 6.5 `zones.yml` 区域与命名点位

**最大价值：坐标只写一次**，怪物组 / 交互点 / 传送脚本都引用同一份，改图时只改这个文件。

单副本最多 **64 个区域**，只支持长方体（AABB），不支持球形/多边形。

```yaml
战斗区:
  名称: '&e前厅战斗区'
  范围: '-20,60,-30 ~ 20,80,10'   # 两点顺序随意
  默认开启: true
  进入脚本: |-
    action.message('@trigger', '&e你进入了前厅战斗区');
  离开脚本: |-
    action.message('@trigger', '&7你离开了前厅战斗区');
  点位:
    中心: '0,64,-10'
    落点: '0,64,0,0,0'            # 带朝向的点位用于传送
```

`默认开启: false` 的区域开局不生效，由脚本 `action.enable_zone('区域名')` 打开。

## 6.6 `obstacles.yml` 障碍物

**一组方块，脚本可以让它出现/消失** —— 开门、关门、能量屏障、封锁 Boss 房都靠它。
「关闭」= 方块出现（挡路），「开启」= 方块消失。

单副本最多 **64 个障碍物**；单个障碍物一次最多写 **32768 格**（超了加载期就在 `/ld doctor` 里报，运行期拒绝执行）。

外层键写 `障碍物:` 或 `obstacles:` 都认（也可以像 `zones.yml` 那样直接把障碍物名写在根节点）；
键名写错就是「这份配置不存在」—— 脚本里 `create_obstacle('X')` 只会在控制台留一行 warning。

### 两种定义方式（二选一）

两个都写、一个都不写，都会在加载期报 issue 并跳过该条 —— 不猜。

#### 区域模式（推荐）

先用魔棒在游戏里把门洞画成一个区域（`/ld edit` → 菜单的「区域与点位」），这里只填材质：

```yaml
障碍物:
  Boss门:
    区域: Boss门洞            # 引用 zones.yml 里画好的区域
    材质: IRON_BARS           # 关闭时铺什么
    默认状态: 开启            # 开启(默认) = 副本开始时不存在；关闭 = 开始就铺好
    # 开启材质: AIR           # 选填；不写 = 恢复原方块（见下）
    关闭时: |-
      action.sound('@all', 'BLOCK_IRON_DOOR_CLOSE');
    开启时: |-
      action.message('@all', '&a大门已打开');
      action.sound('@all', 'BLOCK_IRON_DOOR_OPEN');
```

关闭时把该区域的**范围盒整盒铺实**（连着空气一起填）—— 所以门洞画成一个薄盒子最合适，
`1×3×1` 就是一扇 3 格高的门。区域画得越大，一次写入的方块越多，超过 32768 格直接拒绝。

#### 方块清单模式

形状不规则（缺口的墙、斜门）时逐格写，材质写在每行第 4 段：

```yaml
障碍物:
  暗门机关:
    方块:
      - '20,64,0,STONE'
      - '20,65,0,STONE'
      - '20,66,0,STONE'
    默认状态: 关闭
    开启材质: AIR
```

### 字段表

| 键 | 默认 | 说明 |
|---|---|---|
| `区域` / `zone` | — | 引用 `zones.yml` 的区域；与该区域的范围与**删除同步**（区域没了会在 `/ld doctor` 里报「引用的区域不存在」） |
| `方块` / `blocks` | — | `'x,y,z,材质'` 清单，坐标向下取整，每行可给不同材质；上限 32768 行 |
| `材质` / `关闭材质` / `material` | — | 区域模式必填：关闭时铺什么 |
| `开启材质` / `open_material` | 空 | 开启时改成什么；**不写 = 恢复原方块快照** |
| `默认状态` / `default_state` | `开启` | `关闭`（也认 `closed`）= 副本开始就铺好，且**不跑「关闭时」脚本** |
| `关闭时` / `on_create` / `on-create` / `创建时` | 空 | 铺完方块之后跑的脚本 |
| `开启时` / `on_delete` / `on-delete` / `删除时` | 空 | 清完方块之后跑的脚本 |

### 快照与「开启材质」

副本开始那一刻（玩家传送之前），插件把障碍物覆盖到的方块**存一份快照**（连朝向、含水状态一起存）。
开启时：

- **没写** `开启材质` → 恢复快照：障碍物只是"盖在"地图上，撤销就回到原样；
- **写了** `开启材质`（哪怕写 `AIR`）→ 全部改成那个材质。

快照只在内存里，副本结束随实例世界一起丢掉 —— 实例世界本来就是模板的一次性副本，不需要还原到磁盘。

### 谁让门关上？—— 触发写在别的文件里

障碍物**不带**任何"玩家碰到就关"的配置，因为那件事现有能力就能表达，而且更灵活：

```yaml
# zones.yml —— 走进门口就封锁
Boss房门口:
  范围: '-5,64,-5 ~ 5,70,5'
  进入脚本: |-
    action.create_obstacle('Boss门');
    action.title('@all', '&c大门已关闭');
  离开脚本: |-
    action.remove_obstacle('Boss门');
```

```yaml
# tasks.yml —— 每 10 秒开合一次的机关门
机关门任务:
  类型: LOOP
  间隔: 10
  脚本: |-
    action.toggle_obstacle('机关门');
```

脚本动作见 [7.4.8](07-脚本开发指南.md#748-世界--工具--流程)；`dungeon.isObstacleClosed('Boss门')` 可以在条件表达式里读状态。

> 障碍物覆盖到的区块会在开本时**自动加载并打上票据常驻**（最多 128 个区块）——
> 实例世界关掉了自动保存，区块一旦被卸载，写进去的方块就没了（表现为"门自己又回来了"）。
> 所以障碍物尽量放在玩家会去的战斗区里，别放到几百格外没人去的角落。

## 6.7 `interacts.yml` 交互点

| `type` | 触发时机 |
|---|---|
| `RIGHT_CLICK_BLOCK` | 右键方块 |
| `LEFT_CLICK_BLOCK` | 左键方块 |
| `BREAK_BLOCK` | 破坏方块 |
| `PLACE_BLOCK` | 放置方块 |
| `STEP_ON` | 踩踏 |
| `ENTER_REGION` | 进入区域 |
| `RIGHT_CLICK_ENTITY` | 右键实体 |

`once` 默认 `true`（每个玩家只能触发一次）。

```yaml
interacts:
  机关按钮:
    type: RIGHT_CLICK_BLOCK
    once: false
    parameters:
      location: '3,64,3'
      triggered_message: ''          # 已触发过的提示
    script: |-
      action.message('@trigger', '&e你按下了机关按钮');
      action.setblock('0,64,5,AIR');

  能量核心:
    type: PLACE_BLOCK
    once: true
    parameters:
      location: '0,64,-10'
      required_block: DIAMOND_BLOCK  # 必须放置指定方块
      fail_message: '&c需要放置钻石块才能激活！'
      triggered_message: '&c能量核心已经被激活过了'

  陷阱区域:
    type: ENTER_REGION
    once: false
    parameters:
      min: '-15,63,-15'
      max: '-10,68,-10'
```

## 6.8 `tasks.yml` 任务

```yaml
tasks:
  # 定时任务：在副本运行到指定秒数时执行
  countdown:
    type: 定时                        # 也接受 schedule
    times:
      300: |-
        action.message('@all', '&e还剩 5 分钟！');
      60: |-
        action.sound('@all', 'ENTITY_ENDER_DRAGON_GROWL');

  # 循环任务：每隔固定秒数执行
  buff_timer:
    type: loop
    interval: 60
    script: |-
      action.apply_potion('@all', 'SPEED', '10s', 0);

  # 事件任务
  wave_complete_task:
    type: event
    trigger: wave_complete
    trigger_target: wave_1
    script: |-
      action.message('@all', '&a第一波已完成（事件任务）');
```

## 6.9 `rewards.yml` 奖励

```yaml
rewards:
  # ---------- 固定奖励 ----------
  通关奖励:
    items:
      - type: item          # item = 原版物品；mythic_item = MythicMobs 物品
        id: DIAMOND
        amount: 5
    money: 1000
    exp: 500
    commands:
      - "give %player% golden_apple 3"

  # ---------- 随机奖励（权重轮盘 + 保底）----------
  随机宝箱:
    type: random
    保底:
      次数: 30              # 抽 30 次没出「传说」，第 30 次必出
      必出: 传说
      软保底起始: 10        # 从第 10 次开始给目标项提权，0 = 不启用
      软保底增幅: 2.0       # 每次未出，目标项权重 ×该值
      计数域: 副本          # 副本 = 按 副本ID:奖励名 计数；全局 = 跨副本共用
    options:
      普通: { weight: 70, items: [{ type: item, id: IRON_INGOT, amount: 10 }] }
      稀有: { weight: 25, items: [{ type: item, id: DIAMOND, amount: 3 }] }
      传说: { weight: 5,  items: [{ type: mythic_item, id: epic_weapon, amount: 1 }], money: 5000 }
```

保底计数**跨场次持久化**（存在数据库里），所以玩家反复刷同一个副本时保底是累计的。

## 6.12 「已解析但未生效」的字段

下面这些键**代码里会解析、但没有任何运行期读取点**。配了不会有任何效果 ——
列在这里免得你反复调试一个根本不会生效的开关。
（本表逐条用「该字段的访问器在 `src/main/java` 里有没有非配置类调用者」核实过。）

| 字段 | 实际情况 | 替代做法 |
|---|---|---|
| `sweep` 整段 | ❌ 完全未实现 | — |
| `chest_rewards.yml` 整份 | ❌ 完全未实现，奖励不会发放 | 用 `rewards.yml` |
| `leaderboard.*` | ❌ 完全未实现 | — |
| `statistics.*` | ⚠️ **只有 `track-healing` 生效**（控制是否累计治疗量）。`enabled` / `auto-show` / `track-damage` / `display-duration` 都未被读取 —— 伤害其实一直在统计，也没有"副本结束自动展示"的实现 | 统计面板用 PlaceholderAPI 变量自行搭 |
| `database.type: YAML` | ⚠️ 建库逻辑只区分 `MYSQL` 与"其他"，**其他一律走 SQLite**。写 `YAML` 依然生成 `data.db` | 想零配置就用 `SQLITE` |
| `world.concurrent-limit` | ⚠ 只在超过时**发提示**，不做排队/阻塞（见 6.1 该行说明）；写 `0` = 不限 | — |
| `monsters` 组级 `trigger_script` | ❌ 解析后无人读取 | 用 `on_start`/`on_end` 或 `tasks.yml` 的事件任务 |
| `performance.max-block-writes-per-tick` | ❌ 键已删除：它是给旧「障碍物」系统的**分帧写入队列**用的。重做的障碍物改成同步写入 + 单次上限（见 6.6），不再有"每 tick 预算"这个概念 | — |
| `monsters` 的 `spawn_timing.type: SCRIPTED` | ⚠️ 与 `MANUAL` **行为完全一致** | 写哪个都一样 |
| 阶段条件不因「玩家进出区域」重判 | ⚠️ `ZoneManager` 没有接到阶段机 | 在区域的 `进入脚本` 里手动 `action.complete_stage()` / `goto_stage(...)` |
| `stamina.*` 与 `requirements.stamina_cost` | ❌ 完全未实现 | 用 Vault 金币或门票物品做限制 |
| `world.queue-timeout` | ❌ 未生效 | — |
| `death_check_mode` | ⚠️ 只在 `/ld info` 里显示，不影响判定 | 全灭行为由 `revive` 段决定 |
| `interacts` 的 `required_block` | ⚠️ **仅对 `PLACE_BLOCK` 类型生效** | 其它类型的前置条件用 `script` 里自己判断 |
| `rewards.yml` 随机奖励 `options.<选项名>` 里的 `type` | ❌ 选项的写法由**字段**决定（有 `commands` 就是命令、有 `items` 就是物品），`type` 写了不读 | 按字段写即可；`type:` 只在奖励本身（`type: fixed/random`）和 `items[]` 里有效 |
| `world.border` | ✅ 已修复为回退值 | 与 `world.world_rules.border` 二选一即可 |
| 队伍的 `lootMode` / `expShareMode` / `shareScope` / `storage` / `joinMethod` | ❌ **已彻底移除**（不再是"解析了没读取"，而是连字段都从界面上撤掉了）。`Party` 类里仍保留这些字段与枚举，但没有任何读取者；`shareScope` 连设置入口都没有过。队伍现在只负责"组人 + 一起进本" | 掉落物与经验一律走原版规则；需要额外的分配逻辑就在副本脚本里用 `player`/`dungeon` API 自己做 |

> 表中 ✅ 那条是本次修复的：`world.border` 之前是个**从未被读取的死字段**，
> 而示例配置和注释一直在教大家写它，照着配等于没配。现在它作为
> `world_rules.border` 的回退值真正生效。

> 队伍那几个字段的处理方式和别的"未生效字段"不同：它们**曾经出现在 GUI 上**。
> 一个永不生效的配置项只坑到看文档的服主，而一个点得动、点了不生效的菜单按钮
> 会坑到所有玩家（他们会以为自己调对了分配方式）。所以这次不是"标注未实现"，
> 而是把入口（GUI 设置项、`/ld party settings` 子项、PAPI 变量、事件层的分配调用）
> **整条链路删掉**。详见 [5.4](05-GUI菜单.md) 与 [4.4](04-指令手册.md)。

## 6.13 改完配置怎么生效

| 改了什么 | 怎么生效 |
|---|---|
| 插件 `config.yml` | `/ld reload` |
| 副本配置（`dungeons/<id>/*.yml`） | `/ld reload` |
| 副本配置，但用**游戏内编辑模式**改的 | `/ld edit save` 或 `/ld edit test` —— **写盘后会自动全量重新解析，等于替你敲了一次 `/ld reload`**，不用再手动 reload |
| `gui.yml` | `/ld menu reload`（或 `/ld reload`） |
| 地图模板 | `/ld template reload` |
| 地图**地形**（挖/放的方块） | 编辑会话里 `/ld edit save` 会异步同步回模板，`/ld edit test` 是同步等待；用 `/ld template import` 导入的走导入流程 |
| **已经开着的副本实例** | **不受影响**，新配置对下一次开本生效 |

改完建议跑一次 `/ld doctor`，它会校验配置、脚本条件表达式与模板是否就绪。
