# 十二、游戏内编辑模式
> [← 十一、附录：目录结构与文件清单](11-附录.md) · [总目录](../05-使用说明.md)
## 12.1 这是什么
`/ld edit` 让你**在游戏里改副本**：进一个专门的「编辑世界」，用手里的 7 件工具标位置、画范围，用聊天按钮和 GUI 菜单选目标、改键值，改完 `/ld edit save` 写回 YAML。
- **它改的就是同一批文件** —— `dungeons/<副本ID>/` 下的 `config.yml`、`zones.yml`、`interacts.yml`、`monsters.yml` 等，等价于你拿文本编辑器改 YAML，只是位置由「点方块」给出、键由菜单列出来，不用记坐标格式和键名。价值集中在**坐标类内容**（出生点、区域范围、点位、交互点、怪物刷新点）—— 这些手写坐标很痛苦，靠工具点两下就好。
- **适合谁**：服主 / 管理员。需要 `liudungeon.admin`（默认仅 OP）。
- **两者可以混用**：编辑模式不锁文件，你照样可以直接改 YAML，改完 `/ld reload`。

> 什么时候**不**用编辑模式：批量改数值、复制粘贴大段配置、用 Git 管理配置、写复杂脚本 —— 这些用文本编辑器更快。

## 12.2 前置条件
| 条件 | 说明 | 不满足时的提示 |
|---|---|---|
| `liudungeon.admin` | 默认仅 OP | 「需要管理员权限（liudungeon.admin）」 |
| 副本存在 | `/ld list` 能查到 | 「未找到副本 X」。**还没有副本就先建一个**：`/ld create <副本ID> [模板名]` |
| 副本配了模板 | `config.yml` 的 `world.template` 非空 | 「副本 X 没有配置模板世界（world.template）」 |
| 模板目录存在 | `plugins/liudungeon/maps/<模板名>/` | 「模板世界不存在: X，请先 /ld template import X」 |
另外两条硬限制（见 [12.10](#1210-注意事项)）：同一副本同一模板同时只能一个人编辑；你自己同时只能有一个编辑会话。
## 12.3 完整走查：从 enter 到 exit
### 第 1 步：`/ld edit enter <副本ID>`
命令 `/ld edit enter example`。聊天栏（标题栏）依次出现 4 行：`进入编辑模式 — 副本 example（模板 forgedungeon）`、工具说明两行（哪件工具干什么、钟在背包第 9 格）、流程提示 `改 → /ld edit save 写盘 → /ld edit test 进本试玩 → /ld edit enter example 回来继续改 → /ld edit exit 收工`。随后是**编辑面板**（聊天栏，全是可点按钮）：`⟦ 编辑: example \| 待保存 0 \| 目标: 无 ⟧` / `[💾保存] [↩撤销] [⚙菜单] [👁可视化]` / `[🎮试玩] [❓帮助] [🚪退出]`。落点 = **`config.yml` 的 `world.spawn`**，也就是玩家进本时站的那个点（没配这个键时才退回模板世界自己的出生点；坐标若卡在方块里会自动挪到最近能站的一格），背包里多出 **7 件工具**（钟固定放第 9 格，其余按空位依次塞入；已有的不重复发）。模板被多个副本共用、或当前有运行中的实例时，多两条 ⚠ 警告（见 12.10）
### 第 2 步：拿到 7 件工具
进入时自动发放（进入前的原背包内容不动）；掉线重连、`/ld edit enter` 恢复会话时**补发**；退出、试玩时自动回收。**工具不能丢弃**（丢不掉，会提示）；在编辑世界外面右键会提示「编辑工具只能在编辑世界里使用。」完整行为见 [12.5](#125-工具速查表7-件工具)
### 第 3 步：改 —— 三种改法
命令 `/ld edit open`。三种改法都要先有「编辑目标」（地形方块除外）：①**选目标 → 对着世界点**（最常用）：在菜单 / 聊天面板里选一个目标，然后用**选区魔棒**画两个角（范围型）或**点位标记器**右键方块（单点型）；②**聊天面板按钮**：`[💾保存] [↩撤销] [⚙菜单] [👁可视化] [🎮试玩] [❓帮助] [🚪退出]`，以及查询/删除列表里的 `[设为目标]` `[✔删除]`；③**GUI 菜单**：`/ld edit open`、`/ld edit panel` 上的 `[⚙菜单]` 按钮，或右键背包第 9 格的**编辑会话菜单钟**。选目标后聊天栏会明确告诉你下一步用哪件工具 —— 范围型：`编辑目标: 区域范围 大厅 → 用 选区魔棒 左键角1 + 右键角2`；单点型：`编辑目标: 点位 大厅.终点 → 用 点位标记器 右键方块`。改一步，面板上的「待保存 N 项」就 +1（≥10 项时面板会加一句「（建议保存）」）
### 第 4 步：`/ld edit save` 写盘
命令 `/ld edit save`。`已保存 2 个文件的变更，副本配置已重新加载。原文件备份在 bak/example_edit_*/`。只有**被改过的文件**会写盘、会进备份；返回的数字是**文件数**，不是变更步数。保存后副本配置**全量重新解析**，不需要 `/ld reload`。地形改动在保存时**异步**同步回 `maps/<模板名>/`（这一次不剪空区块 —— 世界还开着，不能动区块文件；留到 `/ld edit exit` 时统一清，见 [12.12](#1212-地图体积为什么会被撑大)）。没有待保存变更时提示「没有需要保存的变更。」YAML 是经 Bukkit 重新写出的：**注释会保留**（Paper 1.18+），但多行脚本统一写成块样式、空行排布可能与原来略有差别 —— 数值语义不变
### 第 5 步：`/ld edit test` 试玩
命令 `/ld edit test`。流程：**有未保存变更就先保存 → 把地形同步回模板（同步等待完成）→ 关闭编辑会话 → 走正常开本流程进本**；输出 `已保存并同步模板，正在开本试玩… （试玩后 /ld edit enter example 恢复编辑）`。然后就是正常进本（人数 / 等级 / 冷却 / 费用校验都会走，见[三、五分钟上手](03-五分钟上手.md)），工具在试玩前已被回收，所以试玩时手里没有编辑工具。保存失败时试玩会中止：`保存失败，试玩中止（见上方报错）。`；你人已经在一个副本里时：`你已经在副本里了，试玩入口取消。` —— **编辑会话和地形都不会被动**，先 `/ld leave` 出本再重试一次。试玩是**真的开了一个实例**：退出实例用 `/ld leave`，然后 `/ld edit enter example` 回去继续改
### 第 6 步：`/ld edit enter <副本ID>` 回来继续改
命令 `/ld edit enter example`。从编辑会话中掉线、或者去试玩之后，用同一条指令恢复，输出 `已恢复编辑会话 — example（未保存变更 3 项）`。工具补发、面板重发、可视化任务重新挂上；如果你不在编辑世界里会被传送回去。**未保存的变更还在**（缓冲在会话对象里，没随世界卸载丢掉）。恢复只认**同一个副本**：此刻正在编辑别的副本时会提示「你正在编辑 X，请先 /ld edit exit。」
### 第 7 步：`/ld edit exit` 收工
命令 `/ld edit exit`。没有未保存变更：直接退出，`已退出编辑模式。`，你被传送回进入编辑世界前的位置，工具回收。有未保存变更：**不会直接退**，而是给出 4 个可点按钮 `[💾先保存再退出] [↩撤销一步] [🗑放弃并退出] [✖留在编辑]`（「放弃并退出」走的是 `/ld edit exit confirm` —— 丢掉全部未保存变更）。退出时**地形改动总是同步回模板**（不需要先 save）：世界卸载后目录在后台复制回模板，复制成功后删除会话世界目录；同步之前会**先剪掉空区块**（探索范围撑出来的那些纯空气区块），聊天栏会告诉你剪了多少、省了多少，见 [12.12](#1212-地图体积为什么会被撑大)

**关于编辑世界：**

| 项 | 值 |
|---|---|
| 世界名 | `ld_<副本ID>_edit`（副本 ID 里的非字母数字下划线会被去掉，名字超 60 字符会截断） |
| 内容 | `maps/<模板名>/` 的一份**文件级拷贝** |
| 时间 / 天气 | 时间固定 6000（正午）、无雨 |
| 世界规则 | 关闭怪物生成、昼夜循环、天气循环、生物破坏方块 |
| 舒适度 | 不受任何伤害（含摔落/火焰）、饥饿不下降（进食照常） |
| 地图改动 | **挖 / 放方块就是直接改地图**，不受工具与撤销缓冲限制（见 12.9） |

## 12.4 三种改法
| 改法 | 入口 | 适合改什么 | 特点 |
|---|---|---|---|
| 选目标 + 点世界 | 菜单 / 聊天栏选目标 → 魔棒 / 标记器 | 出生点、区域范围、点位、交互点位置与范围、怪物刷新点、整组连续标记 | 坐标由「点哪里」决定，最不容易写错 |
| 聊天面板按钮 | 进入时 / 每次操作后自动重发 | 保存、撤销、试玩、可视化开关、退出、查询结果里设目标或删除 | 不用记指令，一眼看到「待保存几项 / 当前目标」 |
| GUI 菜单 | `/ld edit open` / 钟 | 浏览与新建区域、点位、交互点、怪物组、怪物条目、脚本与结构、待保存变更清单 | 分页列表，能看全貌 |

| 按钮 | 执行的指令 | 说明 |
|---|---|---|
| `[💾保存]` | `/ld edit save` | 把缓冲写回 YAML（旧文件先备份到 `bak/`） |
| `[↩撤销]` | `/ld edit undo` | 撤销最近一条变更 |
| `[⚙菜单]` | `/ld edit open` | 打开编辑主菜单（= 背包里的钟） |
| `[👁可视化]` | `/ld edit viz` | 开/关粒子可视化（当前状态写在按钮悬停里） |
| `[🎮试玩]` | `/ld edit test` | 保存 → 同步地形 → 直接进本试玩 |
| `[❓帮助]` | `/ld edit help` | 全部子指令速查 |
| `[🚪退出]` | `/ld edit exit` | 退出编辑（有未保存变更会先提醒） |
| `[设为目标]` | `/ld edit goto <列表代号> <序号>` | 出现在**信息查询器**的结果里 |
| `[✔删除]` | `/ld edit delhit <列表代号> <序号>` | 出现在**关联删除器**的结果里 |
> 查询/删除列表带「列表代号」：删掉一项后序号会前移，所以旧按钮会被拒掉并提示「列表已过期…请再右键一次方块刷新。」删完请重新右键。
## 12.5 工具速查表（7 件工具）
| # | 工具（物品名；用物品标记识别，改名或同名的都冒充不了） | 材质 | 左键 | 右键 | 潜行 + 右键 |
|---|---|---|---|---|---|
| 1 | `⟪ 选区魔棒 ⟫` | `BLAZE_ROD` 烈焰棒 | 左键方块 = **角 1** | 右键方块 = **角 2** | 同右键（无特殊行为） |
| 2 | `➤ 点位标记器` | `ARROW` 箭 | 无 | 右键方块 = 把方块中心写进**当前编辑目标**；右键空气 = 写**你站的位置**（朝向取当前视角） | 同右键 |
| 3 | `👁 信息查询器` | `ENDER_EYE` 末影之眼 | 无 | 右键方块/空气 = 列出此处登记的一切，每条带 `[设为目标]` | 同右键 |
| 4 | `➹ 点位罗盘` | `COMPASS` 指南针 | 无 | 右键 = 传送到**下一个**点位（先找你最近的那个，再跳它的下一个，循环） | 打开**区域列表**菜单 |
| 5 | `✖ 关联删除器` | `BONE` 骨头 | 无 | 右键方块/空气 = 列出此处登记项，每条带 `[✔删除]` | 同右键 |
| 6 | `☠ 怪物放置器` | `SPAWNER` 刷怪笼 | 无 | 右键（地面/空气）= 在**脚下选点** + 自动打开**选怪菜单**；沿用当前怪物组，没有就自动新建 `wave_N`（MANUAL 触发）。菜单里可开「**每次右键新建组**」：开了以后每次右键都新建一组，并预放一只 `HUSK`（见 12.5.1） | 同右键（不再有特殊行为） |
| 7 | `⚙ 编辑会话菜单` | `CLOCK` 钟 | 无 | 右键 = 打开编辑主菜单 | 同右键 |


| 工具 | 细节 |
|---|---|
| 魔棒 | 角 1 / 角 2 谁先谁后都行，两点齐了才成框；当前目标是范围型时**两角齐了自动写入**并重发面板（`已写入: 区域范围 大厅`）。右键时如果还没设角 1，会提示「左键还要先设一个角1」。魔棒选区会同时用于多个范围型目标，但**写入只发生在当前目标上** |
| 标记器 | 右键**方块**：位置取那个方块，水平坐标 +0.5（方块中心）、**Y 就是该方块的 Y**；右键**空气**：位置取**你站的地方**（脚下那格的中心，坐标保留小数）。朝向都是**你的视角朝向**。空气这一路是给「出生点 / 带朝向的点位 / 世界中心」准备的：站在目标位置、视角摆好，对着空气右键即可 —— 不用为了让射线碰到方块去找一个能点的方块（脚下是空气、地毯、隐形平台时根本没得点）。出生点写满 5 段 `x,y,z,yaw,pitch`；命名点位**原值是几段就写几段**（3 段不带朝向、5 段带朝向）；**世界中心只写 `x,z`**（边界是竖直的圆，高度没有意义，所以你站在第五层点也是对的）。没有目标时提示「先选一个编辑目标（⚙菜单 或聊天面板）」 |
| 信息查询器 / 关联删除器 | 点空气时会射线拾取 **8 格内**的方块。查询器给出的 `[设为目标]` 只在有可编辑目标时出现；删除器给出的 `[✔删除]` 只在可删除项上出现。障碍物只能从这里**删除**（它既可能是"区域名 + 材质"，也可能是一串坐标，都不是魔棒能表达的形状） |
| 可视化（`/ld edit viz`） | 画出：出生点（末影粒子柱）、世界中心（不灭图腾粒子柱，比出生点那根高 —— 它只有水平坐标，高度借用出生点）、区域点位、区域范围（橙色线框）、交互点（绿柱 / 绿框）、怪物刷新点（火焰柱）、**障碍物（红色线框；方块清单模式还会逐格加光柱）**、当前魔棒选区（紫色） |
| 罗盘 | 点位列表包含**出生点**与**世界中心**（列表里显示为 `出生点` / `世界中心`；世界中心没配时不出现）以及 `zones.yml` 里的全部命名点位（显示为 `区域.点位`）。副本一个点位都没有时提示「这个副本还没有任何点位」 |
| 怪物放置器 | 右键 = 三件事一步到位 —— ①在**你站的位置**记一个刷怪点；②确定归属组：沿用当前怪物组（上次选怪时切到的组），没有当前组就自动新建 `wave_1`、`wave_2`…（MANUAL 触发，可在组详情里改）；③自动打开**选怪菜单**：两个来源按钮 **原版怪物**（对应刷怪蛋图标）和 **MythicMobs怪物**（列出全部内部名，未装 MM 时置灰）。在列表里**点一只加一只**，位置都是刚才选的点，加完留在列表继续点；47 格直达「组条目列表」调数量/等级/位置。选怪菜单中间还有 **切换 / 新建 wave 组**按钮：点已有组 = 切为当前组并回选怪菜单；➕ = 自动建 `wave_N` 并切换 —— 铺多波怪时不用退出菜单跑命令。底部 **23 格**是「**每次右键新建组**」开关（开了每次右键都新建一组并预放一只 `HUSK`，见 12.5.1），**21 格**直达当前组的**怪物条目**（改位置 / 改数量等级 / **逐只删除**），**25 格**是**删除当前怪物组**（含脚本，二次确认） |

#### 12.5.1 怪物放置器：「每次右键新建组」开关

选怪菜单底部 **23 格**（拉杆）一个开关，决定**下一次右键往哪一组加怪**：

| 开关 | 右键一次会发生什么 | 什么时候用 |
|---|---|---|
| **关**（默认，火把图标） | 沿用当前怪物组；没有当前组才新建 `wave_N`（**空组**，等你挑怪） | 同一个刷怪点要放好几只 / 好几波怪 |
| **开**（拉杆图标） | 每次都新建一个 `wave_N`（找第一个空闲编号），并切为当前组，组里**已经放好一只 `HUSK`**（位置 = 这次右键选的点） | 一波怪一个组，铺十来波时不用每次先进菜单切组 |

开着时为什么预放一只怪：这种用法就是"一次右键 = 一波怪"，空组既没有内容、
`/ld doctor` 也会把它当成写坏的配置报出来。默认怪是最普通的近战怪 `HUSK`，站在你右键
选的那个点上 —— 想换别的怪，进条目详情改 ID/数量/等级，或直接再点几只别的怪进去
（都是追加，不会顶掉这只）。**只有"开"这条会预放**：关着的时候"没有当前组 → 自动新建"
仍然是空组，那是"先建组再挑怪"的用法。

按下的那一刻会有一条聊天栏确认（「以后每次右键都新建一个 wave 组」/「恢复为沿用当前怪物组」），
选怪菜单里的信息牌也会显示当前状态。**这个开关是会话级的**：属于这一次编辑会话，
`/ld edit exit` 退出后回到默认的「关」，但掉线重连、`/ld edit enter` 恢复会话时保留。

> ⚠️ 开着的时候，右键**一定**会新建组 —— 包括你本来只想往刚才那组里再加一只怪的时候。
> 加错组了不要紧：`/ld edit undo` 撤掉这一步（新建组也是一条可撤销的变更）。
| 全部工具 | **工具的默认行为全部被取消**：右键箭不会射出去、别的默认交互也不会触发。潜行右键与普通右键对魔棒 / 标记器 / 查询器 / 删除器 / 钟是**同一个行为**，别以为潜行能「取消」 |
### 两种叫法对照
| 物品名 | 面板里的简称 | 平时怎么叫都行 |
|---|---|---|
| `⟪ 选区魔棒 ⟫` | 魔棒 | 魔棒、选区魔棒 |
| `➤ 点位标记器` | 标记器 | 标记器、点位标记器 |
| `👁 信息查询器` | 查询器 | 查询器、信息查询器 |
| `➹ 点位罗盘` | 罗盘 | 罗盘、点位罗盘 |
| `✖ 关联删除器` | 删除器 | 删除器、关联删除器 |
| `☠ 怪物放置器` | 怪物放置器 | 放置器 |
| `⚙ 编辑会话菜单` | 钟、菜单 | 钟、菜单钟、编辑会话菜单 |
### 查询器 / 删除器的匹配规则（为什么"站在区域里也能命中"）
| 登记类型 | 命中条件 | 说明 |
|---|---|---|
| 出生点 | 坐标**精确相等** | 要站在出生点那一格 |
| 世界中心 | 水平坐标**精确相等**（竖直方向不管） | 站在圆心那一格的任意高度都算命中 —— 中心只有 `x,z` |
| 区域 | 坐标**落在范围的 AABB 内** | **站在区域内部任意一格右键都能命中**，不必对准角点 |
| 命名点位 | 坐标**精确相等** | — |
| 交互点 | 位置型精确相等；范围型落在 `min`~`max` 内 | 与区域同理 |
| 怪物刷新点 | 坐标**精确相等**（`point` 引用会先解析成坐标） | 引用点位时按点位坐标算 |
| 障碍物 | 区域模式：落在该区域的 AABB 内；方块清单模式：坐标在清单里 | 只能**删除**，不能设为编辑目标（障碍物是"区域名+材质"，魔棒画不出区域名） |
所以"我明明站在大厅里，查询器却列出了整个大厅区域"是对的；而点位/刷新点必须站准那一格，差一格就查不到（用 `Shift+右键` 删除、或 `/ld edit tp` 传送过去最稳）。
## 12.6 命令速查：`/ld edit` 全部子指令
主指令 `/ld edit`，权限 `liudungeon.admin`（默认仅 OP）。**除 `status` 与 `help` 外全部只能由玩家执行** —— 控制台执行会得到「编辑会话只能由玩家使用。」不带参数执行 `/ld edit` 等同 `/ld edit panel`（重发会话面板）。
### 会话
| 子指令（中文别名） | 参数 | 作用 |
|---|---|---|
| `enter`（`进入`） | `<副本ID>` | 进入编辑世界。已有同副本会话 = **恢复**（未保存变更还在）；已有别的副本会话 = 拒绝 |
| `exit`（`quit`、`退出`） | `[confirm\|确认]` | 退出。有未保存变更且没写 `confirm` 时只给 4 个可点按钮，不退出 |
| `save`（`保存`） | — | 把缓冲写回 YAML（旧文件先备份），随后全量重载配置 |
| `test`（`试玩`） | — | 保存 → 同步地形回模板（同步等待）→ 关会话 → 正常开本进本 |
| `status`（`状态`） | — | 列出全部编辑会话（谁在编辑、哪个副本、哪个模板、待保存几项）。**控制台可用** |
| `help`（`帮助`） | — | 子指令速查（控制台可用） |
### 缓冲
| 子指令（中文别名） | 参数 | 作用 |
|---|---|---|
| `undo`（`撤销`） | — | 撤销最近一条变更（从磁盘重读缓冲 + 重放其余变更） |
| `discard`（`放弃`） | — | 丢弃**全部**未保存变更，回到磁盘上的配置 |
| `cancel`（`取消输入`） | — | 取消没填完的聊天输入 / 书本文本挂起 |
| `panel`（`面板`） | — | 重发聊天栏面板 |
| `viz`（`visualize`、`可视化`） | — | 开/关粒子可视化（线框、点位标记等） |
### 目标 / 新增 / 删除 / 传送
| 子指令（中文别名） | 参数 | 作用 |
|---|---|---|
| `target`（`目标`） | 见下表 | 选/清编辑目标。不带参数只显示当前目标 |
| `add`（`新建`） | 见下表 | 新建区域 / 点位 / 交互点 / 实体交互 / 怪物组 / 怪物条目 |
| `del`（`delete`、`删除`） | 见下表 | 删除区域 / 点位 / 交互点 / 怪物组 / 怪物条目 |
| `tp`（`传送`） | `<区域> <点位>` | 传送到某个命名点位（原值带朝向时连朝向一起设） |
| `goto` | `<列表代号> <序号>` | 把查询器列表里的第 N 项设为编辑目标（序号从 1 开始） |
| `delhit` | `<列表代号> <序号>` | 删除查询结果里的第 N 项（序号从 1 开始） |

| `target` 的目标类型（中文别名，大小写不敏感） | 参数 | 写什么 |
|---|---|---|
| `spawn`（`出生点`） | — | `config.yml` 的 **`world.spawn`**（含朝向；`dungeon.spawn` 不生效，见下） |
| `center`（`世界中心`） | — | `config.yml` 的 **`world.center`**（世界边界的圆心，只写 `x,z` —— 边界是竖直的圆，用不上高度） |
| `zonebounds`（`区域范围`） | `<区域ID>` | `zones.yml` 该区域的 `范围`（魔棒） |
| `zonepoint`（`点位`） | `<区域ID> <点位名>` | 该点位坐标（标记器） |
| `newzone`（`新建区域`） | `<新区域名>` | 新建区域 + 范围（魔棒） |
| `newzonepoint`（`新点位`） | `<区域ID> <新点位名>` | 新建点位（标记器） |
| `interact`（`交互点`） | `<交互点ID>` | 交互点 `location`（标记器） |
| `interactbounds`（`交互范围`） | `<交互点ID>` | 交互点 `min`/`max`（魔棒） |
| `newinteract`（`新建交互`） | `<新交互点ID> <类型>` | 新建交互点（范围型走魔棒，其余走标记器） |
| `monster`（`怪物`） | `<组ID> <第几只>` | 该只怪的刷新位置（标记器）。**序号从 1 开始** |
| `group`（`整组`） | `<组ID>` | 整组连续标记：标记器每点一次依次写给第 1、2、3… 只，循环 |
| `clear`（`清除`） | — | 清除当前编辑目标 |
交互点类型取值：`RIGHT_CLICK_BLOCK`、`LEFT_CLICK_BLOCK`、`BREAK_BLOCK`、`PLACE_BLOCK`、`STEP_ON`、`ENTER_REGION`、`RIGHT_CLICK_ENTITY`。**只有 `ENTER_REGION` 是范围型**（用 `min`/`max`），其余全部用 `location`。

| `add` 类型（中文别名） | 参数 | 行为 |
|---|---|---|
| `zone`（`区域`） | `<区域名>` | 把目标设为「新建区域」，再用魔棒画两个角 |
| `point`（`点位`） | `<区域> <点位名>` | 把目标设为「新点位」，再用标记器右键 |
| `interact`（`交互点`） | — | 启动新建向导：输入 ID → 点按钮选类型 → 定点或画范围 |
| `interactentity`（`实体交互`） | `<交互点ID>` | 输入实体类型（类型固定 `RIGHT_CLICK_ENTITY`），**随后还要用标记器右键「实体站的那一格」** —— 运行期是按实体所在方块坐标匹配的，不标位置这个交互点不会生效 |
| `group`（`怪物组`） | `<组ID>` | 立刻新建空组（默认 `MANUAL` 触发），随后可在菜单里加怪 |
| `monster`（`怪物`） | `<组ID> <mm\|mc> <怪物ID> [数量]` | 追加一条怪物条目；数量默认 1。`mm`=MythicMobs、`mc`=原版。省略 `mm\|mc` 时生成侧先试 MythicMobs 再回退原版。加完目标自动切到这只怪 |

| `del` 类型（中文别名） | 参数 | 备注 |
|---|---|---|
| `zone`（`区域`） | `<区域ID>` | 删整个区域（含点位）。被怪物条目引用时会提示引用数 |
| `point`（`点位`） | `<区域ID> <点位名>` | 被怪物条目引用时会提示引用数 |
| `interact`（`交互点`） | `<交互点ID>` | — |
| `group`（`怪物组`） | `<组ID>` | 含组内全部怪物与脚本 |
| `monster`（`怪物`） | `<组ID> <第几只>` | 序号从 1 开始 |
### 脚本文本 / 结构 / 菜单
| 子指令（中文别名） | 参数 | 作用 |
|---|---|---|
| `script`（`脚本`） | `<文件> <路径…>` | 翻开书本编辑该 YAML 路径上的多行脚本。`functions.js` **不用写路径**（整份文件编辑） |
| `delsection`（`删除节`） | `<文件> <路径>` | 删除某个配置节（进缓冲，可 undo） |
| `interacttype`（`交互类型`） | `<交互点ID> <类型>` | 改交互点类型，并自动迁移参数（范围型清 `location`，位置型清 `min`/`max`） |
| `open`（`菜单`） | `[菜单键]` | 打开某套菜单，不带参数 = `main`。Tab 补全给 `main` / `zones` / `interacts` / `monsters` / `structure` 与 `points:<区域>`；按钮用的内部键（`pending`、`pickmob[:vanilla\|mythic]`、`pickwave`、`group:<组>`、`entries:<组>`、`interact:<ID>`、`list:<文件>#<路径>`）手打同样能用 |
可编辑文件名（白名单，写别的会被拒）：`config.yml`、`zones.yml`、`obstacles.yml`、`interacts.yml`、`monsters.yml`、`stages.yml`、`tasks.yml`、`rewards.yml`、`chest_rewards.yml`、`scripts.yml`、`functions.js`。
### 真实示例
```
/ld edit enter example                        # 进入编辑
/ld edit target spawn                         # 目标 = 出生点；拿标记器右键地面 → 写进 world.spawn
/ld edit target center                        # 目标 = 世界中心；站到地图中心右键地面 → 写进 world.center
/ld edit target zonebounds 大厅               # 目标 = 区域范围；魔棒左键角1、右键角2 → 写进 大厅.范围
/ld edit target monster wave1 3               # 目标 = wave1 组第 3 只怪；标记器右键地面 → 写进该条目的 location
/ld edit add monster wave1 mm SkeletonKing 2  # 加 2 只 MythicMobs 怪到 wave1
/ld edit add group wave2                      # 新建空组 wave2（MANUAL）
/ld edit target newzone boss_room             # 起名后魔棒画两个角 = 新建区域
/ld edit add interact door1                   # 新建交互点向导（ID → 类型 → 位置）
/ld edit interacttype door1 ENTER_REGION      # 改成范围型，然后用魔棒画 min/max
/ld edit script monsters.yml groups.wave1.on_start   # 翻书编辑 wave1 的开始时脚本
/ld edit script functions.js                  # 整份 JS 函数库翻书编辑
/ld edit tp 大厅 终点                          # 传送到 大厅.终点
/ld edit del point 大厅 终点                   # 删除该点位（进缓冲，可 undo）
/ld edit target clear                         # 清除目标
/ld edit save                                 # 写盘
/ld edit test                                 # 保存并进本试玩
/ld edit enter example                        # 试玩完回来继续改
/ld edit exit                                 # 收工（有未保存变更会先给你 4 个按钮）
/ld edit status                               # 看全部会话（控制台也能跑）
# ── 中文别名一样能用 ──
/ld edit 进入 example
/ld edit 目标 点位 大厅 终点
/ld edit 删除 点位 大厅 终点
/ld edit 保存
```
> **名字规则**：新建区域 / 点位 / 怪物组 / 交互点 ID 时，名字**不能为空、不能含点号 `.`、不能含空格**。点号在配置路径里是分隔符（`a.b` 会被拆成两级结构），空格会被指令分词截断。不合规会当场拒绝并说明原因。
### Tab 补全
`/ld edit` 的补全做前缀匹配、不区分大小写。第一段补全全部子指令（含中文别名）；`enter` 补副本 ID；`target`/`add`/`del`/`open` 会按上下文补区域、点位、交互点、怪物组、怪物序号；`add monster <组> mm <前缀>` 补 MythicMobs 内部名，`mc <前缀>` 补全部可生成的原版实体；`script` 补可编辑文件名。补全里给不出的中文别名**照样能敲**。

### 键名兼容：编辑器会「沿用文件里已有的写法」
| 内容 | 候选键（先有的先用） | 都不存在时用（编辑器不另造第二套键） |
|---|---|---|
| 区域范围 | `范围` → `bounds` | `范围` |
| 区域点位 | `点位` → `points` | `点位` |
| 交互点参数段 | `parameters` → `参数` | `parameters` |
| 交互点位置 | `location` → `位置` | `location` |
| 交互点范围 | `min` → `最小点` / `max` → `最大点` | `min` / `max` |
| 交互点类型 | `type` → `类型` → `右键方块` | 新建时写 `type` |
| 交互点仅一次 | `once` → `仅一次` | `once` |
另外一条**扁平布局兜底**：交互点如果没写 `parameters` / `参数` 段，参数就直接写在交互点根上。编辑器会跟着这个布局走 —— 只有**全新的**交互点才新建 `parameters` 段。（无脑加 `parameters` 会让原本写在根上的 `min`/`max` 立刻「消失」，`ENTER_REGION` 交互点会被整点丢弃。）
> ⚠ **删区域 / 点位会牵连怪物条目**：怪物条目引用点位用的是字符串 `区域.点位`（键 `point` / `点位`）。删掉被引用的目标后，那些条目会**静默失效**（不报错、就是刷不出怪）。`/ld edit del zone` 与 `del point` 会先统计并提示「有 N 个怪物条目引用了…」，删完请跑 **`/ld doctor`** 查全部引用问题。

> ⚠ **`zones.yml` 用了 `区域:` 分节写法的副本，别在编辑模式里新建区域**。编辑器的区域清单读的是根级键；如果你的 `zones.yml` 把区域写在 `区域:`（或 `zones:`）节下面，编辑器**看不到**这些区域，新建出来的区域会写到根级 —— 而解析器优先读那个分节，于是新区域「配了却没生效」。这种情况请用文本编辑器维护 `zones.yml`，或者先把它整节改成根级写法再用编辑模式。
### 配置文件两种写法都支持
| 文件 | 外层节名（解析器认的） | 没有外层节时（解析器与编辑器完全一致，不用为编辑模式改写文件） |
|---|---|---|
| `zones.yml` | `区域` / `zones` | 区域直接写在根上（文档主推这种，编辑器新建也用根级） |
| `interacts.yml` | `交互` / `interacts` | 交互点直接写在根上（**扁平写法同样能编辑**）；文件是全空时才按 `interacts:` 新建 |
| `monsters.yml` | `groups` / `怪物组` / `waves` / `波次` | **没有根级回退** —— 怪物组必须在外层节里，编辑器新建时写 `groups:` |
| `stages.yml` / `tasks.yml` / `chest_rewards.yml` | `阶段` / `stages`、`tasks` / `任务`、`chests` / `宝箱` | 走"脚本与结构"的通用编辑器，从根节点逐层点进去即可 |
怪物条目本身也有两种写法：列表形态 `monsters: [ {id: …} ]`（主推）与子段形态 `monsters: { 甲: {id: …} }`（也认中文 `怪物:`）。编辑器两种都能读，**写回时沿用文件原来的写法**，不会把子段形态悄悄改成列表。
## 12.9 安全网：缓冲、备份、撤销、草稿
### 改动只进内存缓冲
- 所有配置改动（标位置、改键值、新建、删除、脚本）**先写进会话的内存缓冲**，不碰磁盘。面板上的「待保存 N 项」就是这个缓冲的长度。**只有 `/ld edit save` 才写盘**；保存 = 备份旧文件 → 写回被改过的文件 → 全量重新解析配置。
- **例外：地形方块**。挖方块 / 放方块是直接改编辑世界的地图，**不进缓冲、不能 undo**。编辑世界是模板的一份拷贝，所以模板在 save/exit 同步前不受影响；但一旦同步，那部分地形改动就没有缓冲可撤了。
- **另一个例外：试玩**（`/ld edit test`）会先保存并同步地形 —— 这是它的定义，不是副作用。
### 旧文件备份到哪
| 备份 | 路径 | 什么时候产生 |
|---|---|---|
| 保存备份 | `plugins/liudungeon/bak/<副本ID>_edit_<yyyyMMdd-HHmmss>/` | 每次 `save`（含 `test` 里的保存）。**只备份这一次被改到的文件**，内容是**改动前**的原文 |
| 草稿 | `plugins/liudungeon/bak/<副本ID>_edit_draft_<yyyyMMdd-HHmmss>/` | 掉线超时（10 分钟）、关服、插件 disable 时，若还有未保存变更 |
没有备份目录 = 当时没有未保存变更。备份只针对副本目录下的 YAML / `functions.js`，**不包含地形（世界文件）**。
### 撤销 / 丢弃 / 待保存变更清单
| 手段 | 行为 | 范围 |
|---|---|---|
| `/ld edit undo` | 撤销最近**一条**变更 | 一条。可以连按 |
| GUI「查看待保存变更」里左键第 N 步 | 撤销**它 + 它之后的全部步骤** | 一步之后的全部 |
| `/ld edit discard` 或 GUI「全部放弃」 | 丢弃全部未保存变更，回到磁盘上的配置 | 全部 |
| `/ld edit exit confirm` | 丢弃全部未保存变更并退出编辑 | 全部 |
撤销的实现是「从磁盘重读缓冲 + 重放剩余的变更」，所以撤销**不会**影响已经保存到磁盘的内容。
### 保存失败怎么办
- `save` 抛错时聊天栏给出：`保存失败（原文件已备份，未改动）: <原因>`，同时把完整堆栈写进服务端日志。
- 备份发生在写回**之前**，所以备份目录里是上一次的完好内容 —— 用它覆盖回去即可复原。
- 保存失败时 `/ld edit test` 会中止（`保存失败，试玩中止（见上方报错）。`），不会拿半成品开本。
- 常见原因是磁盘满 / 文件被占用。处理完再 `/ld edit save` 一次即可（缓冲还在，不用重做）。
### 掉线 / 关服会落草稿
| 场景 | 会发生什么 |
|---|---|
| 编辑中掉线 | 会话**保留 10 分钟**，挂起的聊天输入与书本文本被清掉，工具回收。重连后用 `/ld edit enter <同一个副本>` 恢复（未保存变更还在） |
| 掉线超过 10 分钟（周期检查触发） | 未保存变更**落草稿**到 `bak/<副本ID>_edit_draft_<时间戳>/`，然后会话关闭、地形同步回模板。日志里有一条 `编辑会话超时关闭: <副本ID>（未保存变更草稿: 路径）` |
| 关服 / 插件被卸载（onDisable） | 未保存变更落草稿，然后收尾（世界卸载、会话表清空、工具回收）。日志里有 `关服时编辑会话未保存，已落草稿: 路径`。地形**不会**在这次收尾里同步回模板 |
| `/ld edit status` | 掉线中的会话会显示「（掉线 N 分钟后丢弃）」 |
草稿目录里的文件是**当时缓冲的完整内容**，可以用文本编辑器对照着搬回 `dungeons/<副本ID>/`，也可以直接 `/ld edit enter` 重新改一遍。注意草稿**不会**自动回收。
## 12.10 注意事项
### 编辑世界
- 世界名 `ld_<副本ID>_edit`（副本 ID 只保留字母数字下划线）。**进入时如果这个世界的名字已经被加载**，会拒绝进入并提示「疑似上次异常残留，请重启服务端后重试」—— 正常退出/试玩/关服都会卸载它，出现这句说明上次异常了。
- 进入时会先**删掉同名残留目录**再复制模板，所以上次异常中断留下的目录不会污染这一次。加载失败时会清掉半成品拷贝并提示；`Bukkit.createWorld` 返回 null 时提示看日志。
- 地形同步回模板是**文件级覆盖**：会话世界目录 → `maps/<模板名>/`。同步**不删除**模板里的多余文件，所以中途失败最多是旧区块残留，不会把模板弄空。同步失败时日志会写明会话世界目录路径，并提示可手动复制回 `maps/<模板名>`。
- 别手动删编辑世界目录 —— 用 `/ld edit exit`。
### 互斥
| 限制 | 提示 |
|---|---|
| 你自己同时只能有一个编辑会话 | 「你正在编辑 X，请先 /ld edit exit。」 |
| 同一副本不能被两个人同时编辑 | 「副本 X 正在被 Y 编辑。」 |
| 同一模板不能被两个会话同时占用（Bukkit 不允许同目录挂两个世界） | 「模板 X 已被另一个编辑会话占用（共用模板的副本不能同时编辑）。」 |
### 共享模板的副本会一起变
进入时如果模板被多个副本引用会提示（改的是模板，**所有引用同一个模板的副本，地形和坐标都跟着变**）：

```
⚠ 模板被 3 个副本共享（example, example2, example3），此处改动对它们全部生效。
```
### 编辑期间 `/ld enter` 照常可用
- 模板本体直到 save / exit 同步前都没有被任何世界占用，所以**不锁开本**。
- **已经在跑的实例完全不受编辑影响**（它们有各自的世界拷贝）。**新开的实例**会用编辑后的模板 —— 开本复制模板前，插件会先把编辑世界刷一次盘（保证拷到的是完整一致的区块），所以**即使你还没 save，新实例拿到的地形也可能已经包含你刚挖/放的方块**，而副本配置（YAML）仍然是你最后保存的那一版。
- 进入时若有运行中的实例，会提示「当前有 N 个运行中的实例，它们不受编辑影响；新开的实例将使用编辑后的模板。」
### 名字不能含点号 / 空格
新建区域、点位、怪物组、交互点 ID 时名字不能为空、不能含 `.`、不能含空格（原因见 12.6 末尾）。已有配置里如果本来就有带点号的名字（阶段的 ID 也在校验范围里），那种键**无法用菜单路径定位**（Bukkit 的原生限制），也别在编辑模式里重命名它 —— 用文本编辑器处理。
### 哪些操作会牵连引用
| 操作 | 牵连 |
|---|---|
| 删除区域 / 点位 | 怪物条目里 `point` / `点位` 引用该目标的条目**静默失效**（删除前会提示引用数） |
| 重命名配置节（属性编辑器） | 其它文件里对这个路径的引用不会同步改 |
| 改交互点类型 | 参数会自动迁移（范围型清 `location`、位置型清 `min`/`max`），但**已有脚本内容不动** |
| 改怪物 ID | 不影响位置；MythicMobs 名字写错的话 `/ld doctor` 查不出来（见 [10.4](10-排错与常见问题.md#104-怪物不生成)） |
改完这类操作，跑一次 **`/ld doctor`**（或 `/ld export <副本ID>`）复查引用。
## 12.11 常见问题
| 症状（编辑模式独有的；完整排查体系见 [十章](10-排错与常见问题.md)） | 原因 | 处理 |
|---|---|---|
| 进入时提示「编辑世界 ld_xxx_edit 已被加载（疑似上次异常残留）」 | 上次异常（崩溃、kill -9、热重载）留下了加载中的世界 | **重启服务端**。别自己删目录试运气，世界对象还在内存里时删目录只会更乱 |
| 进入时提示「复制编辑世界失败」/「加载编辑世界失败」 | 磁盘满、模板目录权限、模板损坏 | 看服务端日志里的堆栈；先 `/ld template info <模板名>` 确认模板健康，必要时 `/ld template repair <模板名>` |
| 改了半天，`save` 了但游戏里没变化 | ① 忘了 `save`（面板上「待保存 N 项」还是红的）；② 看的是**已经在跑的实例**（它不受编辑影响） | 先 `/ld edit panel` 看数字，再 `save`；然后 `/ld enter` 开个新实例验证 |
| `save` 之后配置又变回去了 | 有人/有程序在编辑模式外面同时改了同一个文件 | 看 `bak/<副本ID>_edit_*/` 里保存前的内容；编辑期间别和文本编辑器同时改同一份 YAML |
| 菜单打开是空的 | 正常：这个副本确实还没有区域 / 交互点 / 怪物组。空列表会在中间显示一行提示 | 点底部的 `49`（`➕ 新建…`）。区域列表为空时提示会让你先建区域再用魔棒画角 |
| 点了菜单按钮没反应 | ① 点的是灰玻璃填充格或纯展示格；② 点的是列表里的条目但用了没绑定的键（见各菜单的左/右键说明）；③ 聊天栏的 `[设为目标]` 是**上一次查询**留下的，已被判过期 | 看聊天栏有没有「列表已过期…请再右键一次方块刷新」之类的提示；重新右键一次方块 |
| 点了「删除」但东西还在 | 删除只进缓冲，没写盘 | `/ld edit save` 才真正生效；面板上数字会告诉你还有几项 |
| `/ld edit save` 报「保存失败」 | 磁盘满 / 文件被占用 | 原文件已备份未改动，处理完再 save 一次（缓冲还在） |
| 背包满了，编辑用的书掉了 | 书本编辑器放不下时会**把书丢在你脚下**并提示 | 捡起来继续编辑；或者清出 1 格空位再点 `编辑脚本（书）` |
| 聊天里说什么都不发出去 | 会话正等待聊天输入（新建向导、输入数值等），下一条非指令消息会被当成输入吞掉 | `/ld edit cancel` 取消挂起的输入；注意**打开任何 GUI 也会自动清掉挂起输入** |
| 签了别的书却被当成脚本提交 | 挂着书本文本编辑时，签署任何一本书都会被捕获 | 这是编辑会话期间的预期行为。`/ld edit cancel` 可取消 |

| 提示「模板 X 已被另一个编辑会话占用」 | 你在编辑**另一个共用同一模板的副本** | 先 `/ld edit exit`，再进入你要改的那个副本 |
| 提示「你正在编辑 X，请先 /ld edit exit」 | 你自己同时只能有一个会话 | 同上。注意：**同一个副本**的 `enter` 是恢复会话，不会报这个 |
| 掉线后回来会话没了 | 掉线超过 10 分钟，会话已超时关闭 | 去 `plugins/liudungeon/bak/<副本ID>_edit_draft_*/` 找草稿，或 `/ld edit enter` 重新改。地形在超时收尾时已同步回模板 |
| 工具拿不出来 / 丢了 | 进入、恢复会话时自动发放；退出、试玩时自动回收；工具**不能丢弃** | `/ld edit enter <同一个副本>` 会补发。拿在手里却提示「这不是你的编辑会话工具」= 那个会话已经结束了 |
| 控制台执行 `/ld edit enter` 没反应 | 除 `status` / `help` 外，全部子指令只能由玩家执行 | 用游戏内管理员账号执行；控制台只用 `/ld edit status` 查会话 |
| 编辑世界里有怪物 / 天色变了 | 正常情况不会：怪物生成、昼夜循环、天气循环、生物破坏方块都被关掉了，时间固定正午 | 如果确实出现，说明世界规则设置抛异常了（代码里对个别 gamerule 失败是静默忽略的），看日志里 `编辑世界加载失败` 附近的信息 |
| 进了一次编辑模式，地图文件胖了好几倍 | 视野内的区块被"加载即生成"，空区块也占 4KB 扇区 | 出本时会自动剪掉（聊天栏会告诉你省了多少）。已经胖了的模板用 `/ld template trim <模板名>` 清一次。原理见 [12.12](#1212-地图体积为什么会被撑大) |
| `voidgen` 这类虚空模板剪枝后体积没变 | 它的每个区块都有一层基岩，剪枝认为那是**内容**（可能正是地图地板），所以保留 | 这是刻意的保守行为。要变小只能手动删用不到的 `region/*.mca`，或先确认那层基岩不是地图地板，见 [12.12](#1212-地图体积为什么会被撑大) |
| `/ld template trim` 报 `r.0.0.mca 大小异常` | 那个文件的长度不是 4KB 的整数倍。**先看告警里的目录名**：`region/` 和 `poi/` 下都可能有 `r.0.0.mca`，出问题的常常是 `poi/` 那份而不是你正在看的 region 那份 | 1.4.6 起会自动补齐重写；实在补不了的（真被截断）按提示从 `bak/template_trim_*` 恢复，见 [12.12](#1212-地图体积为什么会被撑大) |

## 12.12 地图体积为什么会被撑大
**一句话**：只要进一次编辑模式，玩家视野范围内的区块就会被「加载即生成」；而 region 文件按**4KB 扇区**分配、**一个空区块最少占 1 个扇区**，所以体积只跟**区块个数**有关 —— 跟区块里有没有东西无关。服务端默认 `view-distance=10`，一次进入就是 21×21 = 441 个区块起步，飞一圈还能翻倍。

| 项（实测 2026-09-16，服主的 huanying 模板 `hydl`） | 数值 |
|---|---|
| 模板体积 | 3.77 MB（`region` 3.6 MB / 4 个 `.mca`） |
| 有数据的区块 | 879 个（region 820 + poi 59） |
| 其中**纯空气**的 | **668 个** —— 3.77 MB 里 2.62 MB 是它们 |
| 真正放过方块的 | 211 个（`region` 152 + `poi` 59） |
> `poi` 那 59 个区块**没有被剪**：它们里面有真实的记录（村民工作站点、蜂巢、传送门…），那是内容不是垃圾。剪枝的判据只看"有没有东西"，不看"看起来该不该有"。
> 这些空区块原本会跟着「会话世界整体覆盖回模板」一起进模板，于是**每编辑一次就胖一圈**。
### 现在怎么处理
1. **出本自动剪**：`/ld edit exit`、`/ld edit test`、掉线超时收尾、关服收尾这四条路，都会在**卸载世界之后、同步回模板之前**把空区块剪掉。玩家会看到 `已剪掉 668 个空区块（省 2.62MB）`，控制台记一行 INFO。
   - 为什么必须卡在这两个动作之间：服务端加载世界时自己缓存着 region 文件，此刻重写会让它的缓存指向旧偏移 → 区块损坏；而「同步回模板」是把会话世界整个覆盖过去，剪在这里 = 模板也收不到空区块。
   - `/ld edit save`（世界还开着的那次保存）**不剪**，只同步；留到出本时一起清，体积不会因此多出来。
2. **已有模板手动剪**：`/ld template trim <模板名|all> [--no-backup]`，默认先把 `region/poi/entities` 备份到 `plugins/liudungeon/bak/template_trim_<模板>_<时间>/` 再动手。
3. **少生成**：编辑世界的视距由 `config.yml` 的 `edit.view-distance` 控制（默认 6，`0` = 跟随服务端），出生点区块也改成不常驻（以前是"出生点周围一直开着"）。
### 判空口径：只删「真的什么都没有」的
region 区块要**同时**满足才判空：所有 section 的调色板只有空气、没有 `block_entities`（箱子/告示牌/刷怪笼…）、没有 `entities`（盔甲架/掉落物…）、没有结构起点。`poi` / `entities` 目录按各自的空记录判断。

**凡是看不懂的一律保留**：1.13 之前的老格式区块（带 `Level` 的）、数字 id 调色板、解压或解析失败、region 头自相矛盾 —— 全部按原样保留，绝不猜着删。因此：
- 你手放过的方块**不可能**被剪掉（判据是"全空气"，放过就一定存在非空气方块）；
- 剪枝是纯文件操作，**不碰区块内容**（压缩过的负载原样搬运），也不会改变任何方块；
- 剪错了能救：`/ld template trim` 的备份在 `bak/template_trim_*/`，把里面的 `region/` 覆盖回 `maps/<模板>/` 即可。
### 「大小异常」与扇区尾部补齐
`.mca` 的长度必须是「8KB 文件头 + N 个 4KB 扇区」。长度对不上只有两种来源：

1. **插件早期的写回忘了补零**：`writeBack` 只写「4 字节长度 + 载荷」，文件就短了一截
   （实测 `maps/<模板>/poi/r.0.0.mca` = 8306 字节 = 8192 头 + 4 + 110）。**数据是全的，只是没补齐**。
   这个 bug 在 1.1.1 开发期验证剪枝时就发现并当场修掉了，但**当时被写坏的文件留了下来** ——
   修好的一版只会"不再写坏"，救不了已经坏的那份。
2. **文件真的被截断**：复制被打断、磁盘满。

第 1 种现在（1.4.6 起）会被自动修好：把尾部补零到扇区边界并重写（`8306 → 12288` 字节），区块内容一个字节都不变；
区块多、连头部偏移都已经错了的那种，会按**紧凑布局**（从 8KB 头开始、按每个区块自己声明的长度一段段走）
把位置还原出来 —— 两道验证同时成立才动手：**正好走到文件末尾**、且**每一段都能解压成合法 NBT**。
第 2 种仍然一个字节都不碰，照旧报出来让人去翻备份。

补齐后体积会**略微变大**（8306 → 12288 就是 +4KB），那是把文件修回合法形状的代价，不是又胖了。
告警里的目录名是有效的：`region/` 和 `poi/` 下都可能有 `r.0.0.mca`，报出来的那个才是出问题的文件。

### 它不影响副本运行
空区块只存在于「地图文件」这一层；副本实例是模板的一次性拷贝，跑完就删。剪枝只是让模板回到"只包含真正放过方块的地方"。
