# 一、它是什么

> [总目录](../05-使用说明.md) · [二、安装与依赖 →](02-安装与依赖.md)

liudungeon 是一个**临时世界制**的地牢副本插件：玩家进本时把一张地图模板克隆成一个
独立世界，出本时整个删掉。同一张地图可以同时开多个互不干扰的实例。

## 特性

| 模块 | 能力 |
|---|---|
| **临时世界副本** | 模板克隆 → 加载 → 出本删除，支持并发多实例；带区块票据保证副本内区块不被卸载 |
| **波次刷怪** | 怪物组（波次）编排，支持 MythicMobs 怪物、原生怪物、NBT 装备、掉落表、触发器条件 |
| **阶段流程机** | 阶段串行/跳转/分支条件，最多 8 跳防死循环 |
| **区域系统** | 命名区域 + 区域内外事件（进入/离开触发脚本） |
| **障碍物** | 可开关的方块组（门/屏障/封锁），开启时自动恢复原方块；用区域画范围、材质填一行即可 |
| **交互点** | 7 种交互类型（点击方块/踩踏/靠近/破坏/放置/NPC/范围） |
| **任务系统** | 定时 / 循环 / 事件驱动的脚本任务 |
| **奖励系统** | 固定奖励 + 权重随机 + 保底计数（跨场次持久化） |
| **复活系统** | 自动倒计时 / 复活道具按钮 / 队友潜行读条救起，三种可任意组合；道具名可改成中文（`revive.item.display-name`） |
| **队伍系统** | 组队、邀请（聊天栏一键接受/拒绝）、踢人、转让队长、公开队伍；队长可**强制结束副本并重开**（无需队员同意，也可用 `/ld restart`）或**退出副本（同时退队）** |
| **GraalJS 脚本** | 完整的 JavaScript 编排能力，隔离类加载器 + 语句上限防死循环（⚠ `script.sandbox: true` 当前**不可用**，见 7.8.1） |
| **GUI 菜单** | 副本列表（可按 `priority` 优先级排序，默认 10，数字小的靠前）、队伍管理、选人、二次确认，标题图标文案全可配 |
| **持久化** | SQLite（默认）/ MySQL，冷却、每日次数、保底计数 |
| **副本内防护** | **默认禁止玩家破坏/放置方块**（`world.allow_build`），桶、点火、骨粉催熟也一并拦住；`interacts.yml` 的机关点不受影响。另有命令黑名单、物品黑名单（穿着禁用装备拒绝进本）、防逃逸（末影珍珠/紫颂果） |
| **软依赖集成** | MythicMobs / Vault / PlaceholderAPI / WorldGuard / Multiverse-Core / WorldEdit |

上面这些**不影响其余功能**，可以直接无视。

> **曾经也在这一列里的队伍分配功能，已经彻底删掉了。**
> 战利品分配模式（`lootMode`）、经验共享（`expShareMode`）、共享范围（`shareScope`）、

> 现在：**GUI 的四个设置项、`/ld party settings` 的四个子项、
> `%liudungeon_party_loot/exp/scope%` 三个变量、以及 `DungeonListener` 里那段
> 掉落物/经验分配代码全部移除**。队伍只剩"组人 + 一起进本"这一件事。
> （字段与枚举仍保留在 `Party` 类里，方便将来真的要实现时直接接手。）

`plugin.yml` 里还声明了 **9 个纯预留的权限节点**，分两类（完整说明见
[4.7 权限节点](04-指令手册.md#47-权限节点)）：

| 类型 | 节点 | 说明 |
|---|---|---|
| 无对应指令 | `liudungeon.use.sweep` / `.leaderboard` / `.stats` / `.viewstats` / `.confirm` | 根本没有这些子指令 |
| 有指令但代码不校验 | `liudungeon.use` / `.leave` / `.list` / `.info` / `.running` | 指令存在，但**本来就不需要权限**，给节点也不会放开什么 |

另外还有若干**单个字段**级的"配了没反应"（如 `monsters.yml` 组级的 `trigger_script`），完整清单见
[6.12 「已解析但未生效」的字段](06-配置文件详解.md#612-已解析但未生效的字段)。

## QueDP 有、本插件**有意不做**的功能

> ### 先明确一件事：本插件**不追求**与 QueDP 完全对等
>
> liudungeon 的原则是**只做有用且必要的**。QueDP 有些功能用处不大、或者复杂度不划算，
> **就刻意不做** —— 下面这份清单**不是待办列表，也不是"还差多少"**，
> 而是「**你从 QueDP 搬配置时，哪些地方会不一样**」。
>
> 清单里每一项都是**经过取舍后决定不做**的。除非有人明确提出需求，
> 否则不会被当成"补齐 QueDP"的任务。想看真正在计划内的，见
> [`04-开发进展记录.md` 第三节](../04-开发进展记录.md)。

### action 级别的差异

把 QueDP 官方 Wiki 与 API jar 里的动作总览
**逐名**对着 `ActionApi.java` 核了一遍：QueDP 列出 **68 个** action 名字（含别名），
本插件实现了其中 **52 个**，另外 **16 个不做**。

| 分类 | 不做的 action | 为什么不做 / 怎么办 |
|---|---|---|
| 特效 | `firework` | 通关放烟花 | `action.sound` + `action.particle`；或 `action.command('@all', 'summon firework_rocket ...')` |
| 特效 | `bossbar` | Boss 血条 | ⚠ 无直接替代。用 PAPI 变量搭计分板，或交给 MythicMobs |
| 战斗 | `absorption` | 吸收血量（金色护盾） | `action.apply_potion('@all', 'ABSORPTION', '30秒', 2)` |
| 战斗 | `velocity` | 给玩家一个推力（击退/弹射） | ⚠ 无直接替代 |
| 模块 | `split` | 分流（把一波拆到多个分支） | 用阶段分支 + 多个怪物组自己编排 |
| 模块 | `add_bonus` | 奖励加成倍率 | ⚠ 无替代，本插件无"奖励加成"概念 |
| NPC | `spawn_npc` `npc_talk` `npc_walk` `npc_follow` `npc_equip` `npc_shop` `npc_choice` `npc_quest` | NPC 生成 / 对话 / 行走 / 跟随 / 装备 / 商店 | ⚠ **整个 NPC 系统未实现**。装了 Citizens 的话用 Citizens 自己的脚本/命令做 |
| NPC | `track_task` `complete_task` | 任务追踪与完成 | 用 `tasks.yml` 的事件任务 + `setVar` 自己记 |

> **NPC 系统是明确不做的一整块。** QueDP 自带完整 NPC 系统（生成/对话/商店/任务），
> 本插件不做 —— 理由是"用用处不大 + 与 Citizens 功能重叠"。`/npc_choice` 只是
> 保留的占位指令（任何输入都回"尚未实现"），**不要据此以为 NPC 功能正在开发**。
> 需要 NPC 就用 Citizens 自己的命令/脚本。

### 模块级别的差异

下面这些是**连配置入口都没有**的整块能力。同样**不是待办** ——
它们是"取舍后不做"，列出来只为让你在迁移时知道**哪里会不一样**：

| 不做的模块 | QueDP 里的形态 | 本插件现状 | 怎么办 |
|---|---|---|---|
| **计时竞速（speedrun）** | `modules.speedrun`：分段打点、个人最佳、实时差值 | ❌ 无 `modules:` 解析，无任何竞速代码 | 用 PlaceholderAPI + 外部插件自己搭计时 |
| **奖励加成倍率（bonus）** | `modules.bonus`：按条件算倍率，作用于金钱/经验/物品数量 | ❌ 无。`add_bonus` action 也没有 | ❌ 无替代，只能改奖励配置本身 |
| **全局掉落库** | `plugins/QueDP/loot/*.yml` + 奖励里 `引用: [库名]` | ❌ 无。`rewards.yml` 只能内联写 | 把公共掉落复制到每个副本 |
| **NPC 系统** | 生成/对话/行走/跟随/装备/商店/任务（10 个 action） | ❌ 完全没有。`/npc_choice` 是占位指令 | 装了 Citizens 就用 Citizens 自己的命令/脚本 |
| **网页可视化编辑器** | 官方提供在线编辑配置 | ❌ 无（本项目正在做） | 手改 YAML |
| **世界预热池** | `world.prewarm.*`：预复制实例世界 | ❌ 无（有并发上限 + 出生点区块预加载，但不是池） | — |
| **`%player_world%` 接管** | 副本内把"世界名"显示成中文副本名 | ❌ 无 | 用 `%liudungeon_*%` 自搭 |
| **更多占位符** | `{player.kills}` / `{player.deaths}` / 裸写 `{变量名}` / `{player.level * 2}` 表达式求值 | ⚠ 只实现了 `{player.name}` / `{trigger.name}` / `{player.level}` / `{player.health}` 与 `{var:名}` | 用 `getVar()` 拼字符串 |
| **`/dg admin` 的 13 个子指令** | `forceenter` / `cleanup` / `stats` / `stamina` / `reset` / `cooldown clear` / `webeditor` / `pity` / `daily` / `loot` / `module` 等 | ⚠ `/ld` 只有 22 个根子指令，上述均无 | 部分有等价物（`/ld kill`、`/ld reload`） |

> **迁移前看一眼就行**：上面每一行都意味着"QueDP 配置里写了、搬过来会静默失效"。
> 但它们**不会**因为"QueDP 有"就被补上 —— 有需要请单独提。
>

> **为什么这一节要单独拎出来说**：从 QueDP 搬过来的脚本如果调用了上面任何一个，
> **不会崩、不会报错页** —— 只会抛一个 `TypeError: action.xxx is not a function`，
> 然后被引擎当普通脚本异常**吞掉**（控制台一条 warning，同一处只报一次）。
> 玩家侧的表现是"某段演出没放出来""某个机关没反应"，属于最难查的一类问题。
>
> 搬运脚本前先扫一遍：
>
> ```bash
> grep -nE "action\.(firework|bossbar|absorption|velocity|split|add_bonus|spawn_npc|npc_|track_task|complete_task)" 你的脚本
> ```
>
> 这个清单会随开发更新；`/ld export <副本>` 的 `checks` 段也能帮你抓出脚本里
> 引用了不存在配置键的错误（但**抓不出**调用了不存在的 action —— 那是另一类检查）。

## 几个设计取舍（了解这些能少踩坑）


- **不用 NMS 建世界器。** 走「模板目录克隆 + `Bukkit.createWorld`」路线，
  因此**不需要为每个 MC 版本维护模块**，实测加载耗时 1 秒内。
- **第三方依赖不打进插件 jar。** 全部写在 `plugin.yml` 的 `libraries:` 里由 Paper 下载，
  插件 jar 只有 **0.5MB**（详见 [安装与依赖](02-安装与依赖.md#二安装与依赖)）。
- **脚本引擎用隔离类加载器加载。** 避免与 MythicMobs 内嵌的 Truffle 冲突，
  也避免重定位破坏 Truffle 的 JNI 符号。
- **WorldGuard 只做只读探测。** 副本世界用完即删，向 WG 注册 region 会留下垃圾数据；
  保护类行为改由世界规则（GameRule）接管。
