# 二、安装与依赖

> [← 一、它是什么](01-它是什么.md) · [总目录](../05-使用说明.md) · [三、五分钟上手 →](03-五分钟上手.md)

## 2.1 环境要求

| 项 | 要求 |
|---|---|
| 服务端 | Paper / Leaf **1.21 及以上**（开发与实测环境：Leaf 26.2-112、Paper 26.2-121；**Leaf 26.1.2 已适配**——世界布局、GameRule 命名、API 面与 26.2 同代，见开发记录 §二十九） |
| Java（运行） | **21 或更高** —— 插件产物是 Java 21 字节码（class 主版本 65） |
| Java（编译） | ⚠ **必须 JDK 25** —— `paper-api 26.2` 的 class 主版本是 **69（= Java 25）**，JDK 21 的 `javac` 读不了它。见 [11.3 相关文档](11-附录.md#113-相关文档) 的构建说明 |
| 内存 | 无额外要求；副本世界会随实例数增长占用磁盘 |

## 2.2 安装

1. 把 `liudungeon-<版本>.jar` 放进服务器的 `plugins/` 目录。
2. **确认服务器能访问 Maven 仓库**（只需首次，见下）。
3. 启动服务器。

> ⚠️ **不要**在服务端运行期间用 `cp` 覆盖插件 jar。
> `cp` 对已存在文件是「截断 + 原地重写同一个 inode」，而运行中的 JVM 已经打开了这个 jar，
> 句柄读到的字节会和内存里的索引对不上，**此后才第一次被加载的类统统失败**
> （表现为莫名其妙的 `NoClassDefFoundError`）。
> 正确做法是先写到临时文件再 `mv` 过去（换 inode），然后重启。

## 2.3 依赖库：为什么 jar 只有 0.5MB

插件的所有第三方依赖都声明在 `plugin.yml` 的 `libraries:` 段，由 Paper 在插件加载前
自动下载到**服务器根目录的 `libraries/`**：

```
com.zaxxer:HikariCP:5.1.0              数据库连接池
org.xerial:sqlite-jdbc:3.49.1.0        SQLite 驱动
org.graalvm.*:*(11 个)                  GraalJS 24.1.1 脚本引擎
```

这是 Paper 原生机制，很多插件（Citizens / CoreProtect / HuskHomes …）都这么用。

**首次启动需要联网下载一次**，之后走 `libraries/` 缓存不再下载。

> ⚠️ **依赖解析失败时 Paper 不会降级，而是直接跳过加载整个插件**：
> ```
> Could not load plugin 'liudungeon-1.0.2.jar': Error resolving libraries
> ```
> 国内服务器默认源（Google 托管的 Maven Central）经常超时，**强烈建议换镜像**。
> 在启动脚本的 `java` 后面加参数（Leaf 用第一个，Paper 用第二个，前者优先）：
>
> ```bash
> java -DLeaf.library-download-repo=https://maven.aliyun.com/repository/central \
>      -jar leaf-26.2-96.jar nogui
> ```
>
> ```bash
> java -Dorg.bukkit.plugin.java.LibraryLoader.centralURL=https://maven.aliyun.com/repository/central \
>      -jar paper-26.2-121.jar nogui
> ```
>
> 其他可用镜像：`https://repo.huaweicloud.com/repository/maven/`、
> `https://mirrors.cloud.tencent.com/nexus/repository/maven-public/`

**离线部署**：把 11 个 GraalJS 构件按 Maven 本地仓库布局放进 `libraries/` 即可完全不联网。
布局是 `libraries/<groupId 点换斜杠>/<artifactId>/<version>/<artifactId>-<version>.jar`，
另外放一个 `_remote.repositories` 文件（内容形如 `js-language-24.1.1.jar>central=`）。
或者更简单：把 11 个 jar 直接丢进 `plugins/liudungeon/libs/`，
插件会依次从 `libraries/` → `plugins/liudungeon/libs/` → 插件 jar 内资源 三个位置找。

## 2.4 软依赖

全部通过反射做类隔离访问，**缺任意一个都不影响插件启动**：

| 插件 | 作用 | 缺失后果 |
|---|---|---|
| **MythicMobs** | 刷自定义怪物 | 只能用原生怪物；`monsters.yml` 里写 MythicMobs 怪物名会刷不出来 |
| **Vault** | 金币扣费 | 入场费用与金钱奖励失效 |
| **PlaceholderAPI** | 提供 `%liudungeon_*%` 变量 | 变量不可用；也可用作进入条件 |
| **WorldGuard** | 只读探测模板内 region 并告警 | 无告警；不影响副本运行 |
| **Multiverse-Core** | `/ld template import` 时列出已登记世界 | 少一个地图来源，可手动放目录 |
| **WorldEdit** | WorldGuard 的依赖 | 同 WorldGuard |
| **Citizens** | ⚠ **仅列在 `plugin.yml` 的 `softdepend`，代码零引用**（全仓库 grep 不到 `Citizens`） | 没有影响。交互点的 `RIGHT_CLICK_ENTITY` 用的是**原版实体类型**，与 Citizens 无关 |
| **LuckPerms** | ⚠ **同上：仅列在 `softdepend`，代码零引用** | 没有影响 |

## 2.5 首次启动生成的文件

```
plugins/liudungeon/
├── config.yml                   插件主配置
├── gui.yml                      GUI 菜单配置
├── data.db                      SQLite 数据库
├── dungeons/
│   └── example/                 示例副本（说明.md + 9 个配置文件，首次启动自动生成）
│       ├── config.yml
│       ├── monsters.yml  stages.yml  zones.yml
│       ├── interacts.yml tasks.yml
│       ├── rewards.yml   scripts.yml functions.js
│       └── （chest_rewards.yml，见 6.10）
├── maps/                        地图模板目录（空）
└── libs/                        脚本引擎依赖释放目录（通常为空，依赖走 libraries/）
```

示例副本目录**只在不存在时生成**，不会覆盖你改过的内容。
它自带一份 `说明.md`（30 秒速览：流程 / 每个文件干什么 / 想改什么去哪），里面的 `monsters.yml` 只有两波怪、`scripts.yml` 只有 5 行有效脚本 —— 照抄就能跑通。
