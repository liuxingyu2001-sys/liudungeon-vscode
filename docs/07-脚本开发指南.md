# 七、脚本开发指南

> [← 六、配置文件详解](06-配置文件详解.md) · [总目录](../05-使用说明.md) · [八、地图模板管理 →](08-地图模板管理.md)

liudungeon 用 **GraalJS** 跑 JavaScript 编排副本流程：生命周期、波次、阶段条件、交互点、任务里的 JS 片段全部走同一套引擎。本章所有方法签名、字段名、触发时机均**逐字取自源码**（`script/ScriptEngine.java`、`script/action/ActionApi.java`、`script/action/DungeonApi.java`、`dungeon/DungeonLifecycle.java`、`dungeon/GroupSpawner.java`、`dungeon/stage/StageMachine.java`、`dungeon/ReviveService.java`、`config/DungeonRegistry.java`），可放心照抄。凡**源码级已知限制**（文档承诺与当前实现不一致、或调用后不会生效的地方）都用 ⚠ 标出，并给出自查方法。

> **做副本不一定要写脚本。** 只靠配置就能跑通的主线是「第一波 `AUTO_START` → 后续波次 `TRIGGERED`（`trigger_group` 写在**组这一层**）→ 最后一波的 `on_end` 调一次 `action.complete_dungeon()`」，奖励在 `scripts.yml` 的 `complete` 钩子里用一行 `action.grant_reward(...)` 发出去 —— 内置示例就是这样，一共 5 行有效脚本。脚本真正的价值在**分支与复用**：条件判断、随机、循环、把一段逻辑封装成函数。建议顺序：先把配置跑通（[三、五分钟上手](03-五分钟上手.md)）与 [十二、游戏内编辑模式](12-游戏内编辑模式.md)，需要「如果……就……」时再回来读本章。

## 7.1 执行模型（先读这一节，能省一半排错时间）

| 项 | 实现 |
|---|---|
| 引擎 | GraalJS **24.1.1**（`js-language` + `truffle-*`，共 11 个 jar） |
| 加载方式 | 由 `ScriptEngineLoader` 释放到 `plugins/liudungeon/libs/`，再用 **`parent = null` 的 `URLClassLoader`** 加载，与 MythicMobs 内嵌的 Truffle 完全隔离；宿主只能通过反射操作它 |
| 每次执行 | **新建一个 `Context`** → 注入宿主对象 → `eval` → 立刻 `close()`（try-with-resources，不跨调用复用） |
| 多行脚本 | 被包成 `(function(){ ... })()`，因此**可以写 `return` 提前退出** |
| 条件表达式 | 被包成 `( 表达式 )`，**只能是一条表达式**，不能带 `;`、不能写多条语句 |
| 函数库 | `dungeons/<id>/*.js` 全文在**每次执行时重新注入**（`Source` 有编译缓存） |
| 执行线程 | **专用脚本线程池（3 个守护线程）**，脚本提交后异步执行，不占主线程。脚本里的每个 `action.*` 会在内部跳回主线程执行 Bukkit 操作；`action.wait` / `wait_clear` 只睡脚本线程，**不会卡服务器**。例外：条件表达式（`condition` / `when` / 通关条件）为了拿到返回值仍在调用线程同步求值 |
| 执行顺序 | 同一实例的多段脚本异步并行，先后靠脚本自身的 `wait` 控制；生命周期钩子（init→start→阶段→自动怪物组、complete/fail→切终态、exit→出本清理）由完成回调串联，顺序与同步版一致 |
| 终态保护 | 实例一旦进入 `COMPLETED / FAILED / CANCELLED / ENDING`，`ScriptEngine.eval` 直接 `return null`：**之后新发起的脚本与条件一律不执行、也不报错** |

**跨脚本状态只能用变量，不能用 JS 全局变量。** 每次执行都是一个全新的 `Context`，`var` 定义的全局量、`functions.js` 里定义的函数都不会保留下来。要跨脚本传值请用 `setVar()` / `getVar()`。

**脚本能写在哪（触发点一览）**

| 文件 | 字段 | 性质 | 触发者（`player` / `trigger`） |
|---|---|---|---|
| `scripts.yml` | `init` / `start` | 生命周期 | 队长（开本者） |
| `scripts.yml` | `complete` / `fail` / `exit` | 生命周期 | **无**（`null`）⚠ 见 7.2 |
| `scripts.yml` | `player_death` / `all_death` | 生命周期 | 死亡的那名玩家 / 无（`null`） |
| `monsters.yml` | 组 `condition`（条件）· 组 `on_start` / `on_end`（脚本）· 条目 `when`（条件） | 条件 / 脚本 | 无 |
| `stages.yml` | `通关条件` / 分支 `条件`（条件）· `开始脚本` / `通关脚本` / `超时脚本`（脚本） | 条件 / 脚本 | 无 |
| `zones.yml` | `进入脚本` / `离开脚本` | 脚本 | 进入/离开的玩家（另见 7.7 区域占位符） |
| `interacts.yml` | `脚本` | 脚本 | 交互的玩家 |
| `tasks.yml` | 定时 / 循环 `script` | 脚本 | 无 |
| `tasks.yml` | 事件 `script`（`monster_kill` / `boss_kill` / `wave_complete`） | 脚本 | 击杀者（可能为 `null`，`wave_complete` 恒为 **`null`**） |
| `config.yml` 的 `revive` 段 | `on_revive` / `on_exhausted` | 脚本 | 被复活的玩家 |
| 指令 | `/ld script <JS>` | 调试 | 执行指令的玩家（必须在副本内） |

⚠ **`init` 的时机与注释不一致（以代码为准）**：`DungeonDefinition.ScriptBundle` 注释写「世界创建完成后、玩家传送前」，但 `DungeonLifecycle.loadAndStart` 里 `init` 是在**玩家全部传送进副本、区域系统 resync 之后**执行（代码注释也承认“实践上放传送后能拿到玩家上下文”），所以 `init` 里可直接用 `@all` 和 `player`。 语法自查：`/ld doctor`（静态语法校验，只覆盖怪物组 `condition` 与 `start` 条件，见 7.6）· `/ld script <JS>`（副本内立即执行一段脚本，最方便的探针）。

### 7.1.1 脚本怎么写（统一这一种排版）

脚本字段（上表里所有"性质 = 脚本"的字段）统一写成**块标量 `|-`**：
```yaml
# scripts.yml
complete: |-
  action.title('@all', '&a&l通关！', '&7奖励已发放');
  action.grant_reward('@all', '通关奖励');
  action.exit_dungeon();
```

| 约定 | 说明 |
|---|---|
| 一行一条语句 | 顺序就是执行顺序，从上往下读 |
| **行尾加分号** | 不加也能跑（JS 会自动补分号），统一加上是为了改行时不用回头补 |
| 注释用 `//` | `|-` 块里是**纯 JavaScript 文本**，写 YAML 的 `#` 会变成 JS 语法错误 |
| 不要给整行加引号 | 块里的 `"action.title(...)"` 本来只是一个**字符串字面量**：不报错但什么都不会做。现在执行前会自动剥掉这种整行外层引号（含老列表写法带进块里的引号），照常执行；但别依赖它，行内字符串自己的引号别丢 |
| 只有一条语句也照这样写 | 以后要加第二条时不用换结构 |

> **老写法仍兼容**：`complete:` 下写成 `- "action.title(...)"` 列表也能跑（`Keys.getStringList` 三种形态都收：YAML 列表 / 单个字符串 / 多行块 `|-`），老配置不用动；但列表每项都得自己加引号，且**多行脚本的报错行号对不上**（每项都算独立的一段），新写的都按上面的块写法。

## 7.2 生命周期钩子（scripts.yml）

`scripts.yml` 共 **7 个钩子**。键名固定为英文（**没有中文别名**），只有两处例外：`start` 支持中文子键 `条件` / `脚本`，也可把脚本直接写在 `start` 下（`start: |-` 的 `|-` 块，此时没有条件）；`player_death` / `all_death` 也接受连字符写法 `player-death` / `all-death`。

| 钩子 | 触发时机（源码位置） | 可拿到的上下文 | 备注 |
|---|---|---|---|
| `init` | `DungeonLifecycle.loadAndStart`：世界加载 + 世界规则 + **玩家传送完毕** + 区域 resync 之后；在 `start` 之前 | `action`、`dungeon`、`player`/`trigger` = 队长 | 适合改天气/时间/GameRule、播准备提示 |
| `start` | 紧随 `init`。先跑 `condition`（**全部为真才执行** `script`，空列表视为通过），条件不满足只记 info 日志并跳过 | 同上 | 适合播开场标题、`action.spawn_group('wave_1')` |
| `complete` | `DungeonLifecycle.complete()`：**先跑脚本，再** `setState(COMPLETED)` | `action`、`dungeon`；`player` 不存在 | 发奖、结算演出、`action.exit_dungeon()` 写这里 |
| `fail` | `DungeonLifecycle.fail()`：**先跑脚本，再** `setState(FAILED)` | 同上 | 失败结算写这里 |
| `exit` | `DungeonLifecycle.exitAll()` 最开头，**玩家还在副本里**、传送回主世界之前 | 同上（无触发者） | 通关/失败路径下 ⚠ 不执行；`/ld kill`、超时踢出、关服清理等路径会执行 |
| `player_death` | `ReviveService`：玩家倒下并已被切成旁观者、倒下提示已发、`auto` 倒计时**在"次数还有"时已挂号之后**（次数为 0 时不挂号，提示也只会说"次数已用完"，见 [6.2 的 `revive` 段](06-配置文件详解.md)） | `player`/`trigger` = 倒下的人 | 在这里调 `action.revive('@trigger')` 可立即复活；脚本跑完后系统会重新判断是否算“确认阵亡”。⚠ 别在这里 `action.fail()` —— 副本进终态后每 tick 驱动器就停了，`revive` 段永远没机会生效 |
| `all_death` | `ReviveService.checkAllDeath()`：**全员都处于 DEAD**（还有人 `DOWNED` 待复活就不算）时，只触发一次 | 无触发者 | 先执行脚本；**跑完后如果仍然没有一个活人、副本也还在运行，插件会自动 `fail` 并退出**（全灭的队伍不该被留在副本里）。想自定义就在脚本里 `action.fail('原因')` 或 `action.revive('@all')` |

> **进场提示由你自己的脚本发，插件一句都不发**（1.1.3 起删掉了进本时自带的"创建中"/"开本成功"两句聊天栏提示）：说什么、用什么样式（聊天栏 / 标题 / 音效）全由副本作者决定，写在 `init` 或 `start` 里即可 —— 内置示例的 `start` 就是 `action.title('@all', '&6&l示例副本', '&7消灭所有敌人')`。插件侧只保留控制台日志（`副本实例已启动: ...`）与出错提示（创建失败、退费、排队）。

### ⚠ 钩子必须在「切成终态之前」执行（顺序写反会静默失效）

这是本节最值得记住的一条源码约束。`ScriptEngine.eval` 的第一件事是终态守卫（`if (instance != null && instance.state().isTerminal()) return null;   // 已结束的实例：不再执行脚本，防止操作正在卸载的世界`），而 `DungeonState.COMPLETED` / `FAILED` 都属于 `isTerminal()`。所以**只要钩子在 `setState(...)` 之后调用，脚本就会被守卫直接丢弃**：不报错、不打日志，写在里面的发奖与结算全部不执行，控制台里只有一行「副本通关」。当前实现已经把顺序改对（`complete()` / `fail()` 都是先 `scripts.complete()` / `scripts.fail()`，再 `setState`），`tools/EditLogicVerify.java` 里有断言盯着这个顺序（`complete` 里脚本调用早于 `setState(COMPLETED)`、`fail` 里早于 `setState(FAILED)`），改动时会被自检拦下。

**验证钩子真的在跑（1 分钟）**：给 `complete` 加上 `log('=== complete 钩子执行了 ===');` 与 `action.grant_reward('@all', '通关奖励');` 两行，进本后 `/ld script action.complete_dungeon()`，控制台会打出 `[脚本] === complete 钩子执行了 ===`，奖励也会真的发出去。

⚠ **仍然受终态限制的是 `exit`**：通关/失败收尾路径（`complete`/`fail` 里 `syncLater(..., 20L * 10)` 的 10 tick 兜底 `exitAll`）进入 `exitAll` 时实例已是终态，所以 `exit` 钩子不执行；只有 `/ld kill`、超时踢出、关服等**从非终态**进入 `exitAll` 的路径才会执行。需要"玩家被送回主世界"的收尾逻辑，请写在 `complete` / `fail` 钩子里（用 `action.exit_dungeon()`）。

**其他带脚本的钩子**（写在别的文件里，时机见上表与相关章节）：

| 钩子 | 触发链 |
|---|---|
| 怪物组 `on_start` | `startGroup` 建完生成队列后，**每组只触发一次**（`startScriptFired`），即使 `condition` 之后条件变化、重复生成多轮也不会再跑 |
| 怪物组 `on_end` | 组“全灭”或“跳过”时触发一次（`endScriptFired`）；`action.skip_group` 也会触发 |
| 阶段 `开始脚本` | 进入阶段时执行，**同一阶段只执行一次**（`startedStages` 去重，`goto_stage` 回来不会重播）；`action.restart_stage()` 会重置并重跑 |
| 阶段 `通关脚本` | 条件成立、推进之前执行 |
| 阶段 `超时脚本` | 每 tick 驱动器检查 `超时` 秒数，**只触发一次**（`stageTimeout:<阶段id>`）；脚本里不处理就会停在原阶段 |
| 阶段分支 `条件` | 按列表顺序取第一个成立的；无条件项作为兜底；都不成立且无兜底 = 视为最终阶段 → 自动 `complete()` |
| 复活 `on_revive` | 复活成功后（`config.yml` 的 `revive.on_revive`） |
| 复活 `on_exhausted` | 复活成功且**剩余次数变为 0** 时（`revive.on_exhausted`） |
| 事件任务 | `monster_kill`（每次击杀）、`boss_kill`（击杀 `boss: true` 的条目，同时写入变量 `bossKilled_<组名>`）、`wave_complete`（**只触发一次**） |

## 7.3 全局变量与内置函数

`ScriptEngine.eval` 每次执行时注入下列名字（`ref.put(...)`）：

| 全局名 | 注入条件 | Java 类型 | 说明 |
|---|---|---|---|
| `action` | **总是注入** | `com.liu.liudungeon.script.action.ActionApi` | 动作 API，见 7.4。实例为 `null` 时大部分方法内部直接 `return`（空操作） |
| `dungeon` | `instance != null` 时注入（实际调用点都传了实例，等同总有） | `com.liu.liudungeon.script.action.DungeonApi` | 状态查询 API，见 7.5 |
| `player` | **仅当有触发者时注入** | `org.bukkit.entity.Player`（宿主对象） | 没有触发者时该名字**不存在**，直接引用会抛 `ReferenceError` |
| `trigger` | 同上，与 `player` 是**同一个对象** | `org.bukkit.entity.Player` | 历史兼容名 |
| `__builtins` | 总是注入 | `ScriptEngine.BuiltinHelper` | 内部实现，不建议直接使用 |

**什么时候没有 `player`**：`complete` / `fail` / `exit` / `all_death`、组 `on_start` / `on_end` / `condition`、条目 `when`、全部阶段脚本与条件、`tasks.yml` 的定时与循环任务、`wave_complete` 事件任务。

安全写法：`if (typeof player !== 'undefined') { action.message('@trigger', '&7只有你能看到这句'); }`

**内置函数**（由 `BUILTIN_PRELUDE` 在每次执行时展开为全局函数，写法对齐 QueDP）：

| 函数 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `getVar` | `getVar(name)` | 变量值；**不存在时返回数字 `0`** | 变量以副本实例为作用域，出本即销毁 |
| `setVar` | `setVar(name, value)` | 无 | `value == null` 等价于删除该变量 |
| `log` | `log(message)` | 无 | 打控制台 `[脚本] <message>` |
| `parseTime` | `parseTime(str)` | `long`（**tick**） | 见下方时间格式 |
| `playerName` | `playerName()` | 触发者名字；无触发者返回 `''` | 等价于 Java 侧的空安全写法 |

**陷阱：`getVar` 用 `0` 当“不存在”的哨兵值。** 所以 `getVar('x') === null` 永远不成立，而 `getVar('x') === 0` 在未设置时反而成立；`dungeon.getVariable('x')` 同理。判断“有没有设过”请自己约定一个不可能的哨兵值（如 `-1` 或 `'none'`）。

**时间字符串格式**（`Text.parseTimeToSeconds` / `parseTimeToTicks`，作用于 `action.wait`、`action.apply_potion`、`action.world_time`、`parseTime()`）：

```
3s / 3秒         → 3 秒
5m / 5分 / 5min  → 300 秒
2h / 2时         → 7200 秒
100t / 100tick   → 5 秒（tick 按 20/s 折算）
500ms / 500毫秒  → 0.5 秒
纯数字（如 90）   → 按秒
```
⚠ **单位必须紧跟数字，且只能用上表这几种最短写法**：`3秒钟`、`5分钟`、`10 seconds` 这类写了多余字/复数形式的都会解析失败并**静默返回 0**（`action.wait` 直接不等，`apply_potion` 只给 1 tick 的时长）。写 `3秒` / `3s` 最保险。

**Java 集合不是 JS 数组**：`dungeon.getPlayerNames()` / `getGroupNames()` / `getZones(player)` 返回 **`java.util.ArrayList` 快照**（每次调用新建，非实时视图），只能 `.size()` / `.get(i)`，**不能**用 `.forEach()`、`.join()`、`.length`、`[i]`：

```js
var names = dungeon.getPlayerNames(), line = '';
for (var i = 0; i < names.size(); i++) line += (i ? ', ' : '') + names.get(i);
action.message('@all', '&7队员: &f' + line);
```

### 7.3.1 函数库 `functions.js` —— 写一次，到处调用

副本目录下**每个 `.js` 文件**都会被读入，里面的函数就是本副本的"公共函数"：任何脚本里**直接写函数名**就能调用，不用 `import`、不用 `action.` 前缀。
```js
// dungeons/<副本ID>/functions.js
function 喊话(内容) { action.message('@all', '&e' + 内容); }
function 记进度(说明) {
    var 当前进度 = getVar('进度') + 1;   // 变量不存在时 getVar 返回 0 → 第一次是 1
    setVar('进度', 当前进度);
    喊话('进度 ' + 当前进度 + '：' + 说明);   // 函数之间直接互相调用
}
```
```yaml
# scripts.yml —— 调用处：只写函数名
start: |-
  action.title('@all', '&6示例副本', '&7消灭所有敌人');
  记进度('进入副本');
```

**函数名与变量名用中文完全可以**（JavaScript 支持中文标识符），中英混写也行。唯一的例外是**条件表达式**：`条件:` / `condition:` 里的文本会先做一次中文关键词替换（`是`→`true`、`否`→`false`、`击杀数`→`dungeon.getTotalMobKills()` …，完整清单见 [7.6.3](#763-中文条件的-6-个坑)），所以**名字里不要出现**：

> 是 · 否 · 击杀数 · 存活怪物 · 剩余怪物 · 在线人数 · 存活玩家 · 死亡人数 · 队伍人数 · 运行时间 · 副本时间 · 并且 · 或者

即 `function 是否通关()` 在**普通脚本**里没问题，但**在条件里**会被改坏（变成 `true否通关()`）—— 想给条件用，名字取干净一点（例如 `副本已完成()`）。 三条容易踩的点：

三个容易踩的点：函数**不跨脚本保留状态**（每次执行都是新的 Context，跨脚本传值用 `setVar` / `getVar`）· 没有触发者时函数里不要直接用 `player`，先判断 `typeof player !== 'undefined'` · **同名函数以最后读入的文件为准**（多个 `.js` 的读取顺序由文件系统决定 —— 只放一个 `functions.js` 最稳）。 内置示例 `dungeons/example/functions.js` 里放着四个可直接抄的中文函数（`喊话` / `记进度` / `报还剩几只` / `私聊`），想用就把整个文件拷进自己的副本目录。

## 7.4 `action.*` API 完整清单

以下签名逐字来自 `ActionApi.java`。**所有方法都返回 `void`**（只有 `resolveSelector` / `applyPlaceholders` 有返回值，见 7.4.8）。第一个参数是玩家选择器时，取值见 [7.7](#77-选择器与占位符)。

> ⚠ **从 QueDP 迁移先看这条**：QueDP 的 68 个 action 名字里本插件**有意不做 16 个**（`firework` / `bossbar` / `absorption` / `velocity` / `split` / `add_bonus` 以及**整套 10 个 NPC action**）—— 调用它们会抛 `TypeError` 并被引擎静默吞掉。**这不是待办列表**，是取舍结果；完整差异见 [一、QueDP 有、本插件有意不做的东西](01-它是什么.md#quedp-有本插件有意不做的功能)。
> **命名规则**：方法名一律以 **QueDP 原生名**为准（`grant_reward`、`world_time`、`monster_group`…），另有短别名（`reward`、`time`、`spawn_group`、`tp`…），两者完全等价 —— 对照表见 [7.4.6](#746-阶段--奖励)。

### 7.4.1 消息类

| 方法 | 说明 |
|---|---|
| `message(String text)` | 同上，选择器缺省为 `@all`。例：`action.message('@all', '&e你好')` |
| `message(String selector, String text)` | 给选择器命中的玩家发消息。**不带插件前缀**，支持 `{占位符}` 与 `&` 颜色 |
| `broadcast(String text)` | 全服广播（在线玩家 + 控制台），**带 `config.yml` 配置的前缀**。例：`action.broadcast('&6公告')` |
| `title(String titleText)` | 标题（全员、无副标题） |
| `title(String selector, String titleText)` | 标题（无副标题 —— 副标题不需要就别凑第三参） |
| `title(String selector, String title, String subtitle)` | 标题 + 副标题。例：`action.title('@all', '&6&lBOSS 降临', '&7小心脚下')` |
| `actionbar(String selector, String text)` | 动作栏（物品栏上方那行）。例：`action.actionbar('@all', '&7剩余 3 只')` |

### 7.4.2 副本流程控制

| 方法 | 说明 |
|---|---|
| `complete()` / `complete_dungeon()` | 标记通关。⚠ 由 `complete` 钩子承担结算的写法当前不生效，见 7.2 |
| `fail(String reason)` | 标记失败。`fail()` 等价于 `fail('未指定原因')` |
| `fail_dungeon(String reason)` | `fail` 的别名 |
| `exit_dungeon()` | 把所有玩家传送回主世界（**不结算**），立即执行 |
| `leave_dungeon()` | `exit_dungeon` 的别名 |

例：`action.complete_dungeon();` 通关 · `action.fail_dungeon('前厅超时');` 失败 · `action.exit_dungeon();` 只传出不改状态。

### 7.4.3 怪物组（波次）

| 方法 | 说明 |
|---|---|
| `spawn_group(String group)` | 生成一个怪物组；**组不存在只打 warning**，不会抛错 |
| `spawn_group(String group, double multiplier)` | 带数量倍率（作用于每个条目的数量，`Math.max(1, Math.round(amount * multiplier))`） |
| `monster_group(String group)` | `spawn_group` 的别名 |
| `random_spawn_group(String... groups)` | 从若干组里随机生成一个 |
| `random_monster_group(String... groups)` | `random_spawn_group` 的别名（QueDP 也有这个名字，两个都认） |
| `stop_repeat(String group)` | 停止该组的重复生成（保留现有怪物，把轮次推到上限） |
| `cancel_group(String group)` | 清掉该组存活怪物并**标记为已完成** |
| `clear_group(String group)` | `cancel_group` 的别名 |
| `skip_group(String group)` | 标记完成但**不生成**怪物，仍会跑该组 `on_end` |

例：`action.spawn_group('wave_2')` · `action.spawn_group('elite', 2.0)`（数量 ×2）· `action.random_spawn_group('宝箱房A', '宝箱房B')`。

⚠ **`cancel_group` 之后该组无法再启动**：`stopGroup()` 会把 `tracker.completed = true`，而 `startGroup` 对已完成的组直接 `return false`（日志只有 debug 级）。需要“临时清场后还能再刷”请改用 `skip_group` + 新建组，或干脆不清。

⚠ **已被 `condition` 拦下的组不会自动重试**：`condition` 只在 `spawn_group` 被调用的那一刻求值一次；如果写的是“存活怪物 <= 5”这类随时间变化的条件，脚本需要在合适的时机**再次调用 `spawn_group`**（例如放到 `on_end` 链或循环任务里）。

### 7.4.4 交互点 / 区域

| 方法 | 说明 |
|---|---|
| `trigger_interact(String interactId)` | 等价于触发者亲自触发了该交互点（选择器默认 `@trigger`） |
| `trigger_interact(String selector, String interactId)` | 让选择器命中的玩家各触发一次 |
| `enable_zone(String zoneId)` | 开启区域（进出脚本开始生效）；区域不存在时打 warning |
| `disable_zone(String zoneId)` | 关闭区域 |
| `create_obstacle(String obstacleId)` | **关闭障碍物**：把方块铺上（挡路）。⚠ 名字是 QueDP 的 `create`，语义是"关闭"，别写反 |
| `remove_obstacle(String obstacleId)` | **开启障碍物**：清掉方块、恢复原方块快照 |
| `toggle_obstacle(String obstacleId)` | 切换开关状态（适合 `tasks.yml` 的循环任务做机关门） |
| `teleport_zone(String selector, String zoneId)` | 传送到该区域名为 `落点`（回落 `spawn`）的点位，再回落区域中心；传送后会自动 resync 玩家区域状态 |
| `teleport_point(String selector, String pointRef)` | 传送到命名点位 `区域.点位`（也支持 `x,y,z`） |

> 开关门/屏障有两种做法：**几格方块**逐个 `action.setblock('x,y,z,AIR')`（见 7.4.8）；**一整片、而且希望开完能还原**的用 [6.6 的障碍物](06-配置文件详解.md#66-obstaclesyml-障碍物)（插件自动拍快照，「开启」时恢复原方块，不用自己记住原来是什么）。

例：`action.create_obstacle('Boss门')` 关闭（铺方块挡路）· `action.remove_obstacle('Boss门')` 开启（恢复原方块）· `action.enable_zone('隐藏房区域')` · `action.teleport_point('@all', '前厅.落点')` · `action.trigger_interact('@all', '能量核心')`。

`trigger_interact` 会走完整的触发校验：**`仅一次`、`需要物品`、`需要物品名称`都会生效**（不支持时给玩家发 `失败消息` / `已触发消息`）；但它**不校验位置，也不校验 `需要方块`**（`需要方块` 只在 `PLACE_BLOCK` 类型的真实放置事件里校验）。

### 7.4.5 复活

| 方法 | 说明 |
|---|---|
| `revive(String selector)` | 复活目标，**扣一次复活次数**，落点按 `config.yml` 的 `revive` 段 |
| `revive(String selector, boolean consume, String location)` | 指定是否扣次数与落点：`spawn`/`出生点`（安全落脚点）、`inplace`/`原地`（倒下位置）、`区域.点位`；传 `null` 用配置默认（`revive.auto.at`） |
| `add_revive(int amount)` | 给**触发者**加复活次数，并给触发者发 `&a复活次数 +N` |
| `add_revive(String selector, int amount)` | 给选择器命中的玩家加次数（无提示） |
| `set_revive(int value)` | 把**触发者**的复活次数设为 `value` |

复活失败的原因只进 `debug` 日志（`action.revive … 失败`），玩家侧看不到。常见失败：`该玩家当前不需要复活`（不是 `DOWNED` 状态）、`复活次数已耗尽`、`副本未启用复活系统`。 常用写法（`player_death` 钩子：全队仍有存活者时立刻拉起倒下的人，不扣次数）：
```yaml
player_death: |-
  action.message('@all', '&c{player.name} 倒下了！');
  if (dungeon.getAlivePlayerCount() >= 1) { action.revive('@trigger', false, 'inplace'); }
```

### 7.4.6 阶段 / 奖励

| 方法 | 说明 |
|---|---|
| `complete_stage()` | 跳过通关条件，直接完成当前阶段（会跑该阶段 `通关脚本` 并按分支推进） |
| `goto_stage(String stageId)` | 跳到指定阶段，**不执行当前阶段的通关脚本**；目标不存在时打 warning 并停在原地 |
| `restart_stage()` | 重进当前阶段（会**再跑一次**该阶段 `开始脚本`） |
| `grant_reward(String selector, String rewardName)` | 给选择器命中的玩家各发一份奖励 |
| `grant_reward(String rewardName)` | 等价于 `grant_reward('@all', rewardName)` |
| `reward(…)` | **同上的别名**，两个重载都有 |

> **为什么主名是 `grant_reward` 而不是 `reward`**：本插件的目标是**完全替换 QueDP**，所有 `action.*` 方法名都以 QueDP 的**原生名**为准（旧配置里的脚本原样搬过来就能跑）；改名会让所有现存 QueDP 脚本失效，因此只能**加别名**。反过来 `random_monster_group`（QueDP 的另一个名字）也已作为别名补上。**短别名是这套 API 的既定风格**，不是特例：

QueDP 原生名（主名）→ 短别名：`complete_dungeon()`→`complete()`、`fail_dungeon(reason)`→`fail(reason)`、`leave_dungeon()`→`exit_dungeon()`、`monster_group(group)`→`spawn_group(group)`、`clear_group(group)`→`cancel_group(group)`、`apply_potion(...)`→`potion(...)`、`world_time(t)`→`time(t)`、`grant_reward(...)`→`reward(...)`、`teleport(selector, locationRef)`→`tp(selector, locationRef)`。 例：`action.goto_stage('隐藏房')` · `action.complete_stage()` · `action.grant_reward('@all', '通关奖励')`（与 `action.reward('@all', '通关奖励')` 完全等价）。

⚠ `stages.yml` 的连跳保护上限是 **`MAX_CHAIN_JUMPS = 8`**：脚本/条件连续推进超过 8 次会暂停阶段机并 warning（通常意味着某个通关条件恒为真）。`goto_stage` 会把连跳计数清零后重新开始，`restart_stage` 不计数。

### 7.4.7 玩家与特效

| 方法 | 说明 |
|---|---|
| `teleport(String selector, String locationRef)` | 传到 `区域.点位` 或 `x,y,z[,yaw,pitch]`；解析失败只打 warning；传送后自动 `resyncPlayer` 重判区域 |
| `tp(String selector, String locationRef)` | `teleport` 的别名（短名），行为完全一致 |
| `give_item(String selector, String material, int amount)` | 给物品，材质用 Bukkit `Material` 名；**背包满了会掉在地上**，不会静默丢 |
| `heal(String selector)` | 回满血（按 `MAX_HEALTH` 属性） |
| `set_health(String selector, double health)` | 设置血量，自动夹在 `[0.5, 最大生命]` |
| `damage(String selector, double amount)` | 造成伤害 |
| `gamemode(String selector, String mode)` | `survival` / `creative` / `adventure` / `spectator`（大小写不敏感） |
| `apply_potion(String selector, String effectName, String duration)` | 加药水，默认 I 级，`duration` 用时间字符串 |
| `apply_potion(String selector, String effectName, String duration, int amplifier)` | 加药水，`amplifier = 0` 即 I 级 |
| `potion(String selector, String effectName, String duration)` / `potion(..., int amplifier)` | `apply_potion` 的别名 |
| `clear_potion(String selector)` | 清空全部药水效果 |
| `give_exp(String selector, int amount)` | 给经验 |
| `set_walk_speed(String selector, double speed)` | 设行走速度，夹在 `[-1, 1]`（⚠ 出本**不再**自动还原，见 [6.1](06-配置文件详解.md#出本时到底还原了什么)） |
| `freeze(String selector)` | 冻结（行走/飞行速度归零） |

| `sound(String selector, String soundName)` | 播放音效，音量音高默认 `1.0` |
| `sound(String selector, String soundName, double volume)` | 带音量（音高默认 `1.0`） |
| `sound(String selector, String soundName, double volume, double pitch)` | 带音量音高 |
| `particle(String selector, String particleName, String locationRef)` | 在 `locationRef` 处放粒子（默认 1 个） |

| `lightning(String locationRef)` | 闪电（带伤害） |

### 7.4.8 世界 / 工具 / 流程

| 方法 | 说明 |
|---|---|
| `world_time(String timeRef)` | 世界时间。`day/noon/night/midnight`（中文同义）或 **tick 数**（同 `/time set 6000`，可写 `6000t`）；要按秒写就带单位（`300s`） |
| `time(String timeRef)` | `world_time` 的别名 |
| `weather(String weather)` | `clear/rain/thunder`，也接受 `晴/晴朗/雨/下雨/雷/雷暴` |
| `gamerule(String rule, String value)` | 设 GameRule（只对副本世界生效）；不生效时打 warning 说明原因 |
| `setblock(String locationRef, String material)` | 设置单个方块（`applyPhysics = false`） |
| `command(String selector, String command)` | **以控制台身份**执行命令；`selector` 为空则只执行一次且**不做替换**；否则对每个目标把 `{player.name}`/`{player}` 换成其名字各执行一次 |
| `player_command(String selector, String command)` | **以玩家身份**执行（走 `performCommand`，受权限限制）；只替换 `{player.name}` |
| `set(String name, Object value)` | 设脚本变量（`setVar` 的对象化别名） |
| `wait(String time)` | 等待。只睡**脚本线程**（服务器 TPS 不受影响），上限 10 分钟，见 7.8；实例在等待期间结束时脚本就地终止 |
| `wait_clear(String group)` | 轮询等待某组被清空，间隔 250 ms，**最多 10 分钟**，超时打 warning；实例结束会立即返回 |
| `stop()` | 立即中断当前脚本（抛控制流异常）。⚠ 见 7.10 第 4 条 |
| `resolveSelector(String selector)` | 选择器 → `Set<Player>` |
| `applyPlaceholders(String text)` | 替换文本占位符（7.7） |

⚠ **`world_time` 的数字按“秒”解释**：`action.world_time('6000')` 得到的是 120000 tick，而不是正午。要正午请写 `action.world_time('noon')`。
⚠ **只有 `message`/`title`/`actionbar`/`broadcast` 会替换文本占位符**。`command()` 只替换 `{player.name}`/`{player}`，`player_command()` 只替换 `{player.name}`——`{dungeon.time}`、`{var:x}`、`{random:...}` 在命令里**不会**被替换。
⚠ **`command()` 不做参数转义**：脚本把玩家可控字符串（如 `{var:...}`）拼进命令时存在指令注入风险，请自行白名单/校验。 例：`action.time('midnight')` · `action.weather('thunder')` · `action.gamerule('keep_inventory', 'true')` · `action.command('@all', 'dbuff choose {player.name}')`（每个玩家各执行一次，名字已替换）· `action.set('难度', 3)` · `action.wait('3秒')`（只等脚本自己的下一步，服务器照常跑）。

## 7.5 `dungeon.*` API 完整清单

`DungeonApi.java` 的方法除 `setVariable` 外**全部是只读查询**（条件表达式会被频繁求值，有副作用会重复执行）。

| 方法 | 返回 |

## 7.6 条件表达式

### 7.6.1 能写条件的 5 个位置

| 位置 | 字段 | 求值时机 | 触发者 |
|---|---|---|---|
| `scripts.yml` | `start.condition`（也接受中文键 `条件`） | 开本时，**全部为真**才跑 `start.script`；空列表 = 通过 | 队长 |
| `monsters.yml` | 组 `condition`（别名 `条件`） | `spawn_group` 被调用的瞬间；不满足则**本次不生成**，日志 `info` 记一条 | 无 |
| `monsters.yml` | 条目 `when`（别名 `条件`） | 构建生成队列时**逐条目**求值 | 无 |
| `stages.yml` | `通关条件`（`complete_when`） | **事件驱动**：阶段机启动 / 怪物组完成或被跳过 / 交互点触发 / `goto_stage()` / 每次进入新阶段之后。⚠ **不是每 tick，也不含"区域进出"与"阶段超时"** —— 见 [7.11 步骤 5](#步骤-5把流程交给阶段机stagesyml) | 无 |
| `stages.yml` | 分支 `条件` | 阶段推进时按顺序判定，第一个成立的命中 | 无 |

返回值判定规则（`ScriptEngine.evaluateExpression`）：`boolean` 直接取值；`number` 非 0 为真；`string` 等于 `true`/`1`/`yes`（大小写不敏感）为真；**其它一切情况（含语法错误、运行异常）都按 `false` 处理，只记一次告警**。

### 7.6.2 中文自然语言条件（`translateCondition`）

QueDP 的生产配置里 `condition` 直接写中文（如 `- 存活怪物 <= 5`）。`存活怪物` 对 GraalJS 是个未定义标识符 → `ReferenceError` → 被“按 false 处理”的策略吞掉 → **表现为条件永远为假、怪物组永远不生成，但表面上不报错**。为此引擎在求值前做一层关键词替换（`ScriptEngine.translateCondition`，按表中**声明顺序**做 `String.replace`，长的在前）：

| 中文写法 | 替换为 | 语义 |
|---|---|---|
| `存活怪物数` / `存活怪物` / `剩余怪物` | `dungeon.getTotalAliveMonsters()` | **全副本**存活怪物数 |
| `总击杀` / `击杀数` | `dungeon.getTotalMobKills()` | 全副本累计击杀 |
| `在线玩家数` / `在线人数` / `队伍人数` | `dungeon.getOnlinePlayerCount()` | 在线成员数 |
| `存活玩家数` / `存活玩家` | `dungeon.getAlivePlayerCount()` | 未死亡成员数 |
| `死亡玩家数` / `死亡人数` | `dungeon.getDeadPlayerCount()` | 已死亡成员数 |
| `运行时间` / `副本时间` | `dungeon.getRunningTime()` | 已运行秒数 |
| `是` | `true` | 布尔字面量 |
| `否` | `false` | 布尔字面量 |
| `并且` | `&&` | 逻辑与 |
| `或者` | `\|\|` | 逻辑或 |

所以下面这些都是合法条件：
```yaml
condition:
  - 存活怪物 <= 5                                   # → dungeon.getTotalAliveMonsters() <= 5
  - 存活怪物 <= 0 并且 运行时间 < 600                # 全清且 10 分钟内
  - 击杀数 >= 30 或者 是                            # 恒真（演示用）
  - 在线玩家数 >= 1 && dungeon.getTotalMobKills() > 10   # 中英混写也支持
```

**中文条件只支持上表这些词 + 常规 JS 运算符**（`>= <= > < == != === !== && || !`、算术 `+ - * / %`、括号、数字）。**不支持**全角符号（`≥`/`≤`/`＝`）、文字运算符（`小于`/`大于`/`等于`）、区间（`3~5`）、中文数字（`三`），也**没有**带参数的函数式中文 —— `存活怪物` 一律等于全副本总数，想只算某一波请直接写 `dungeon.getAliveMonsterCount('wave_2') <= 0`。

### 7.6.3 中文条件的 6 个坑

1. **`存活怪物` 是全副本总数，不是当前组的数量。** 在 `monsters.yml` 里用 `存活怪物 <= 5` 作为“上一波快清完了就刷下一波”的开关时，它看的是**所有组**的存活总数。按组判断请用 `dungeon.getAliveMonsterCount('组名')`。
2. **替换是对整行文本做无差别字符串替换**，字符串字面量也会被改。`getVar('是否通关') == 1` 会变成 `getVar('true否通关') == 1`；`action.message('@all','是')` 这类写在**条件**里的字符串同样会被改。**变量名/字符串里不要出现 `是`、`否`、`怪物`、`击杀数`、`并且`、`或者` 这些词**，改用英文键名（`puzzleSolved`、`hard`）。
3. **翻译只在“条件”里生效，脚本正文里不生效。** `scripts.yml` 的 `script`、各组 `on_start`/`on_end`、阶段脚本等**多行脚本不会被翻译**，那里必须写 `dungeon.getTotalAliveMonsters() <= 5`。把中文条件抄进脚本正文 = 运行时 `ReferenceError` + 静默失败。
4. **条件只能是一条表达式**（会被包进 `(...)`）。`a = 1; a > 0` 这种会直接是语法错误。
5. **语法错误不会中断副本**，只会把该条件当 `false` 并告警一次（同一条错误在同一实例内只告警一次，避免刷屏）。所以“NPC 不动、怪物不出、阶段卡住”时第一件事是 `/ld doctor`。
6. **`/ld doctor` 的静态校验覆盖不全**：它只校验**怪物组 `condition`** 与 **`start.condition`**，**不校验** `stages.yml` 的通关条件/分支条件，也不校验条目 `when`。这几处写错了只能靠日志里的 `脚本语法错误 [condition] 行 N → …` 发现（把 `config.yml` 的 `debug` 设为 `true` 更容易看到）。

**修条件的最快路径**：副本里执行 `/ld script dungeon.getTotalAliveMonsters()` 看实际值，再照着写条件。

## 7.7 选择器与占位符

### 7.7.1 `@xxx` 是“选择器”，不是文本占位符

`action.message('@all', ...)` 里的 `@all` 由 `ActionApi.resolveSelector(String)` 在**调用那一刻**解析成玩家集合（`switch` 分支），不存在任何字符串替换。可用的选择器：

| 写法 | 含义 | 备注 |
|---|---|---|
| `@all` / `@a` / `@所有玩家` | 全部**在线**成员 | |
| `@trigger` / `@p` / `@触发者` | 触发者本人 | 无触发者时为空集 |
| `@others` / `@其他玩家` | 除触发者外的在线成员 | |
| `@nearest` / `@最近` | 离触发者最近的其他成员 | 需要触发者，否则空集 |
| `@random` / `@r` / `@随机` | 随机一名在线成员 | |
| `<玩家名>` | 指定在线玩家（`Bukkit.getPlayerExact`） | **解析不到时回落到触发者**，避免动作静默失效；无触发者则为空集 |

⚠ **`@party` 与 `@party_others` 没有实现**（`ActionApi` 的类注释里列了它们，但 `resolveSelector` 的 `switch` 无对应分支 → 走“玩家名”分支 → 找不到该玩家 → **回落到触发者**）。要发给队伍请用 `@all`（副本成员就是队伍）。选择器传 `null` 时按 `@all` 处理；传空串 `''` 会落到“玩家名”分支 → **回落触发者**（无触发者则空集）；`trigger_interact` 的 `selector` 为空则默认 `@trigger`。

### 7.7.2 `{xxx}` 是文本占位符（`applyPlaceholders`）

只在 `action.message` / `action.title` / `action.actionbar` / `action.broadcast` 四处生效（替换后再交给 Adventure 渲染 `&` 颜色）：

| 占位符 | 值 | 前提 |
|---|---|---|
| `{player.name}` / `{trigger.name}` | 触发者名字 | 有触发者 |
| `{player.level}` | 触发者等级 | 有触发者 |
| `{player.health}` | 触发者血量（四舍五入） | 有触发者 |
| `{dungeon.time}` | 已运行**秒数** | 有实例 |
| `{dungeon.players}` | 在线成员数 | 有实例 |
| `{dungeon.name}` | 副本显示名 | 有实例 |
| `{total_kills}` | 全副本累计击杀 | 有实例 |
| `{var:名字}` | 脚本变量值（不存在替换为空串） | 有实例 |
| `{random:1-100}` | 该区间随机整数 | 每次调用独立掷骰 |
| `{random:甲,乙,丙}` | 随机取一项（选项会 trim） | 同上 |

```js
action.message('@all', '&e{player.name} 触发了机关，全队剩余 {random:1-3} 次机会');
action.broadcast('&6{dungeon.name} 已被攻克！用时 {dungeon.time} 秒，击杀 {total_kills}');
```
区域脚本额外注入的占位符（`ZoneManager.runZoneScript` 在**执行脚本之前**对每一行做替换，不限于消息文本）：

| 占位符 | 值 |
|---|---|
| `{zone}` / `{区域}` | 区域 key |
| `{zone.name}` / `{区域名称}` | 区域显示名（未配置显示名时回落 key） |
| `{from_zone}` / `{来源区域}` | 离开脚本里“刚才所在的区域”，进入脚本里为空串 |

```yaml
# zones.yml
前厅:
  名称: '&e前厅'
  范围: '0,60,-30 ~ 30,80,0'
  进入脚本: |-
    action.message('@trigger', '&e你进入了 {zone.name}');
    setVar('当前区域', '{zone}');
  离开脚本: "action.message('@trigger', '&7你离开了 {zone.name}（来源 {from_zone}）');"
```
⚠ **命令里的占位符是另一套**：`action.command()` 只替换 `{player.name}`/`{player}`，`action.player_command()` 只替换 `{player.name}`；奖励配置里的命令支持 `%player%` 和 `{player}`。`{dungeon.*}`、`{var:}`、`{random:}` 在这些地方**不会**被替换（需要就先在脚本里拼好字符串）。

### 7.7.3 引号：选择器、颜色代码、文本都必须写成字符串

脚本就是 JavaScript，`action.*` 的参数**全是普通字符串**。文档里 `@all`、`&e` 这类写法是为了好读，**照抄进配置就会报错**：

| 想写的东西 | ❌ 常见错法 | ✅ 正确写法 |
|---|---|---|
| 选择器 | `action.title(@all, ...)` | `action.title('@all', ...)` |
| 颜色代码 | `action.title('@all', &e文本)` | `action.title('@all', '&e文本')` |
| 中文文本 / 区域名 / 奖励名 | `action.teleport_zone('@all', 前厅)` | `action.teleport_zone('@all', '前厅')` |

**为什么这个坑特别难查**：`@`、`&`、中文裸词在 JavaScript 里都不是合法操作数，GraalJS 只会说 `Expected an operand but found error` —— 它不会告诉你"少的是引号"；而选择器表与颜色代码示例里又全是不带引号的写法，照着抄就中招。插件会把出错的行、列、原因都打出来（行号是**这段脚本块自己的行号**，脚本块从 `on_start: |-` 的下一行算第 1 行）：

```
[liudungeon] 脚本语法错误 [group.wave_1.on_start] 第 1 行第 14 列 → Expected an operand but found error
  1 | action.title(@all, &e文本, &e文本)
                 ^
  提示（第 1 行）：`@all` 是选择器，必须写成字符串 —— 写成 '@all'（例如 action.title('@all', '文本')）
  提示（第 1 行）：`&e` 是颜色代码，要写在引号里 —— 写成 '&e文本'
```
> 想定位**文件行号**，用编辑器的 LiuDungeon 扩展 —— 它会在写成脚本块的配置里给出同样的提示（诊断）。

### 7.7.4 位置引用格式

`action.teleport(selector, locationRef)`（短名 `tp`）/ `teleport_point(selector, pointRef)` / `setblock` / `particle` / `lightning` / `explosion` 的位置参数接受两种写法（`teleport_zone(selector, zoneId)` 特殊：它直接取区域配置的 `落点` → 回落 `spawn` → 回落区域中心）：

**命名点位**：`区域.点位`（先查 `zones.yml` 的 `点位`，命中就用 `[x,y,z,yaw,pitch]`）；**绝对坐标**：`x,y,z` 或 `x,y,z,yaw,pitch`（缺失项为 0）。

## 7.8 沙箱、超时与限制

`config.yml` 的 `script` 段（默认值取自 `PluginConfig` 与 `resources/config.yml`）：

| 键 | 默认 | 实际作用 |
|---|---|---|
| `script.enabled` | `true` | `false` = **根本不初始化引擎**。此后 `run()` 只打 `脚本引擎不可用，跳过执行: <来源>` 的 warning，条件一律 `false`——依赖条件/阶段的副本会直接卡住（怪物不出、阶段不推进） |
| `script.execution-timeout-ms` | `5000`（最小 `50`） | ⚠ **不是墙钟超时**，只用来折算语句上限：`statementLimit = max(200000, timeoutMs * 200000)`，按默认 `5000` 算即 **1,000,000,000 条（10⁹）**；超限时抛 `脚本超过语句上限已被强制中断（疑似死循环）`。阻塞在宿主调用里的脚本（`action.wait`、`wait_clear`）**不受此限** |
| `script.max-actions-per-second` | `200`（最小 `1`） | ⚠ 名字叫“动作数”，实现里是在 `run()` 开头按**实例**统计的**每秒脚本执行次数**上限，超出丢弃并 warning（`evaluateExpression` 不计入此限流）。写得再多的 `action.*` 调用也只算一次 |
| `script.sandbox` | `false` | 宿主访问策略，见下 |
| `script.on-error` | `LOG` | ⚠ `FAIL_DUNGEON` 与 `DISABLE` **当前未真正实现**：`FAIL_DUNGEON` 只在日志里多打一句“按配置 script.on-error=FAIL_DUNGEON，判定副本失败”，**并不会真的失败副本**；`DISABLE` 在代码里没有任何引用 |

### 7.8.1 宿主访问与 `script.sandbox`

无论哪种模式，`allowHostClassLookup` **恒为 `false`**、`allowCreateThread(false)`、`allowIO(NONE)`、`allowNativeAccess(false)`、`allowCreateProcess(false)`：

✅ 脚本**不能** `Java.type('java.io.File')`、不能读文件、不能起线程、不能起进程、不能反射任意类；⚠ 但注入的宿主对象仍可调用其公有方法：`player.getServer()` → `getPluginManager()` / `dispatchCommand()` / `getWorlds()` 一路可达，`dungeon.getWorld()` 直接给出 Bukkit `World`。**默认（完整模式）下脚本权限≈服务器管理权限**，不要把脚本编辑权交给不可信玩家。

| 模式 | 行为 |
|---|---|
| `sandbox: false`（默认，完整模式） | `HostAccess.ALL`：`action.*`、`dungeon.*`、`player` 全部可直接调用，写法与 QueDP 一致 |
| `sandbox: true`（沙箱模式） | `HostAccess.EXPLICIT`：按 GraalJS 语义**只放行显式导出（`@HostAccess.Export`）的成员** |

⚠ **当前版本请勿开启 `script.sandbox: true`（源码级结论）**：`ActionApi`、`DungeonApi`、`BuiltinHelper` 三个类里**没有任何 `@HostAccess.Export` 注解**（全仓库 grep 为空），而每次执行都要先跑 `BUILTIN_PRELUDE` 里的 `__builtins.getVar` 等宿主调用。因此 EXPLICIT 模式下连内置函数都会被拒绝访问，`action.*` / `dungeon.*` 同样会被拒，**脚本基本全部失效**（表现为大量脚本执行错误）。`config.yml` 注释里“只允许调用带 `@HostAccess.Export` 注解的方法”描述的是设计意图，不是现状。 要把沙箱做成可用的，需要给要暴露的方法补 `@HostAccess.Export` 注解；在那之前，安全边界只能靠“不把脚本编辑权外放”来维持。

### 7.8.2 执行诊断

`/ld doctor` 的【脚本引擎】段会列出：引擎是否可用、依赖来源、执行/失败/超限次数、宿主访问模式、类查找状态、语句上限、函数库缓存数；`/ld script <JS>` 是副本内实时的探针。

**日志关键字**（完整对照表见 [7.13.3](#7133-日志关键字对照表)）：`GraalJS 脚本引擎已就绪（隔离加载 + 已预热）` = 正常启动；`脚本引擎不可用` = 依赖缺失（见 [2.3](02-安装与依赖.md#23-依赖库为什么-jar-只有-05mb)）或 `script.enabled: false`；`脚本语法错误 [condition] 行 N → …` = 条件写错（当 false 处理，同一处只报一次）；`脚本运行时错误 [scripts.start] 行 N → …` = 脚本正文抛异常（同一实例同一处只报一次）；`脚本宿主异常 [scripts.start] → IllegalStateException: …` = 插件 Java 侧抛的异常，**没有行号**；`脚本资源超限（疑似死循环）` = 触发语句上限；`动作频率超限，已丢弃本次脚本执行` = 撞上 `max-actions-per-second`；`加载脚本库失败（副本 X 第 N 个 js 文件）` = `functions.js` 有语法错误。

    action.message('@all', '&a第 ' + n + ' 波完成，该波击杀 &f' + dungeon.getGroupKilled('wave_' + n) + ' &a只');

### 7.9.3 示例 3：通关结算与发奖（当前可用的写法）

`complete` / `fail` 钩子在 `setState(...)` **之前**执行（7.2 的顺序约束），写在最终阶段的「通关脚本」里同样可行 —— 两者都在终态之前，**推荐 `complete` 钩子**（只写一处、且能拿到 `dungeon` 状态）。
推荐的 `complete` 钩子写法（`action.grant_reward` → `action.wait('3秒')` → `action.exit_dungeon()`）与 `rewards.yml` 示例见 [7.11](#711-从零写一份能跑的脚本30-分钟跟着做) 步骤 6。奖励名必须**逐字**匹配 `rewards.yml` 的键（多一个空格、简繁差异都会对不上）：写错只在控制台打 warning 并返回“奖励不存在”，玩家侧毫无提示。

⚠ **`complete()` 的兜底**：结算脚本**执行完毕后**若 10 秒内实例仍是 `COMPLETED`（脚本没主动调 `exit_dungeon()`），会自动 `exitAll` 把玩家传回主世界。需要“通关后再停几秒道别”时三选一：① **`action.wait('3秒')`** —— 推荐，只睡脚本线程、TPS 完全不受影响（兜底从**脚本全部跑完**才开始计时，`wait` 多久都不影响传送）；② **用事件任务**（不阻塞，见下例）；③ **干脆不延迟**：结算脚本只做发奖 + 标题，**不要调 `wait`，也不要调 `exit_dungeon()`**。
```yaml
# dungeons/<id>/tasks.yml —— 某波完成时播道别词（只触发一次，且在怪物组 on_end 之前；无触发者，不要用 player）
tasks:
  道别:
    type: event
    trigger: wave_complete
    trigger_target: wave_3
    script: |-
      action.message('@all', '&7感谢挑战，欢迎再来！');
      action.sound('@all', 'UI_TOAST_COMPLETE');
```

## 7.10 已知限制与坑速查

| # | 现象 | 原因 | 规避 |
|---|---|---|---|
| 1 | `complete` / `fail` 钩子里的脚本毫无反应 | 引擎对终态实例直接不执行，而这两个钩子是 `setState()` 之后才调用的 | 结算写进最终阶段的通关/开始脚本；见 7.2 |
| 2 | 通关/失败时 `exit` 钩子不执行 | `exitAll` 从终态进入，同样被守卫拦下 | 用 `/ld kill`、超时等路径验证；需要固定演出就放阶段脚本 |
| 3 | 脚本里的长 `wait` 不再卡服（旧版全服冻结已修复） | 脚本整体跑在专用线程池（3 线程），`wait` 只睡脚本线程；每个 `action.*` 内部跳回主线程执行 | 大量并发实例都在睡长 `wait` 时会排队等线程（池只有 3 个），超长等待（分钟级）建议仍用 `tasks.yml` 定时任务 |
| 4 | `action.stop()` 会被引擎静默吞掉 | `ScriptStopSignal` 按正常控制流处理：不打日志、不广播、不计入失败数 | 正常用即可；想要“出错可见”就用普通异常。⚠ 旧的判定只沿 `getCause()` 找信号，而 Graal 包宿主异常时**不设 cause**（真身只在 `asHostException()`），所以旧版每一跑都会多出一条 `脚本执行错误 → script stop` —— 已修 |
| 5 | `@party` / `@party_others` 不生效，消息发给了触发者 | 类注释里有、`resolveSelector` 的 `switch` 里没有 → 落到“玩家名”分支 → 回落触发者 | 用 `@all` |
| 6 | 开了 `script.sandbox: true` 后脚本几乎全废 | 三个 API 类都没有 `@HostAccess.Export` 注解，`EXPLICIT` 会把它们全拒掉 | 保持 `false`；不要外放脚本编辑权 |
| 7 | `script.on-error: FAIL_DUNGEON` 设了但副本没失败 | 该分支只打日志，没有调用 `fail()`；`DISABLE` 无任何引用 | 需要“脚本出错即失败”，就在脚本里自己 `try/catch` + `action.fail()` |
| 8 | 条件永远为假、怪物永远不出 | 条件写了中文但用了翻译表以外的词，或语义写错（`存活怪物` 是全副本总数） | 按组判断用 `dungeon.getAliveMonsterCount('组名')`；`/ld script` 打印真实值 |
| 9 | 条件语法错误没有任何报错 | 设计如此：条件出错一律当 `false`，只告警一次 | `/ld doctor`（仅覆盖怪物组条件与 `start` 条件）+ 开 `debug` |
| 10 | 变量名/字符串里带“是/否/怪物”的条件行为诡异 | 中文替换是无差别 `String.replace`，会改字符串字面量 | 变量名与字符串值一律用英文 |
| 11 | 把中文条件抄进 `on_start` / 阶段脚本后报错 | 翻译只在**条件**里生效，脚本正文不翻译 | 脚本里写完整 JS |
| 12 | `getVar('x') == null` 判断不生效 | 未设置的变量返回数字 `0` | 用 `-1` / `'none'` 作哨兵 |
| 13 | 无触发者的钩子里用 `player` 报错 | 这些钩子不注入 `player`/`trigger` | `typeof player !== 'undefined'` 保护 |
| 14 | `action.cancel_group()` 之后这组再也刷不出来 | `stopGroup` 把该组标记为 `completed`，而 `startGroup` 拒绝已完成的组 | 用 `skip_group` 或另建组 |
| 15 | `dungeon.getPlayerNames()` 上 `forEach` / `join` 报错 | 返回的是 Java `List`，不是 JS 数组 | `.size()` / `.get(i)` 循环 |
| 16 | `action.command()` 里的 `{dungeon.time}` / `{var:x}` 没被替换 | 命令路径只替换 `{player.name}`/`{player}` | 先在脚本里拼好字符串再传 |
| 17 | 命令里出现玩家可控内容导致越权执行 | `command()` 不做参数转义 | 拼命令前做白名单校验 |
| 18 | `action.world_time('6000')` 得到的不是正午 | 数字按“秒”×20 折算成 tick | 用 `'noon'` 或 `'白天'` |
| 19 | `action.effect()` 的 `spread` 没效果、`particle` 的 `selector` 不像过滤器 | `effect` 忽略 `spread`；`particle` 只用 `selector` 在 `@trigger` 时兜底定位 | 位置一律用 `locationRef` |
| 20 | 多波同时开着时“存活怪物 <= N”提前成立 | 中文条件统计的是全副本存活数 | 按组条件用 `dungeon.getAliveMonsterCount(组名)` |
| 21 | 多个 `.js` 文件时函数到底以哪个为准不确定 | 函数库用 `dir.listFiles()` 收集，**顺序由文件系统决定** | 只在副本目录里放一个 `functions.js`，或保证文件之间无同名函数 |
| 22 | `action.wait('3秒钟')` 完全不等、药水只持续 1 tick | 时间单位解析失败时**静默返回 0**（只支持 `3s`/`3秒`/`5m`/`5分`/`2h`/`2时`/`100t`/`500ms`/纯数字=秒） | 统一用 `3秒` 或 `3s` |
| 23 | 阶段条件明明成立，阶段却一直不推进 | 通关条件是**事件驱动**的：只有「阶段机启动 / 怪物组全灭或被跳过 / 交互点触发 / `goto_stage()` / 进入新阶段之后」才重新判定，**不是每 tick 轮询**。依赖循环任务里 `setVar()` 的条件不会被重算 | 设完变量后主动 `action.complete_stage()`；或把条件挂在 `dungeon.isGroupCleared(...)` 这类事件源上；详见 [7.11 步骤 5](#步骤-5把流程交给阶段机stagesyml) |
| 23b | 条件里写了"玩家进/出区域"或把超时当触发源 | ⚠ `StageMachine.onZoneChange()` 是**零调用点的死方法**；`tickTimeouts()` 只跑超时脚本、不求值 | 区域条件在 `进入脚本` 里手动 `action.complete_stage()`；超时脚本里自己 `goto_stage`/`fail` |
| 24 | 副本刚开就"通关"了，阶段瞬间跑到底 | 某个阶段通关条件恒为真（如 `"true"`）触发连跳；引擎最多连跳 **8** 个阶段后告警停下 | 检查条件是否写成了恒真；未完成的阶段别写 `"true"` |
| 25 | 二刷时逻辑不对（变量值不对、奖励重复） | 变量与阶段状态都是**副本实例**作用域，二刷是全新实例 | 别依赖"上一把的残留变量"；跨场次的数据要存到外部（经济/统计插件） |

## 7.11 从零写一份能跑的脚本（30 分钟跟着做）

7.1–7.8 是**查表**，这一节是**动手**：做一个能真正跑起来的 `trial`（试炼回廊），每步都有"应该看到什么"和"没看到怎么查"。**完整可抄的文件见 [7.9](#79-完整示例)**，本节只给增量。

> **坐标（`0,64,-10` 之类）全是占位符**，必须换成你自己地图上的真实坐标，否则怪物会刷在虚空里。取坐标最快的方式：站到目标位置执行 `/ld script log(player.getLocation())`，把输出抄进配置。本节路径统一省略前缀 `plugins/liudungeon/`。

### 步骤 0：先把底子铺好（不进本）

**先分清两个目录**（新手最容易搞混的地方）：

| 目录 | 装什么 | 谁生成 |
|---|---|---|
| `plugins/liudungeon/dungeons/<副本ID>/` | **副本配置**：`config.yml` / `scripts.yml` / `monsters.yml` / `stages.yml` … | 你手写（可从 `example` 复制） |
| `plugins/liudungeon/maps/<模板名>/` | **地图模板**：`level.dat` + `region/*.mca` | `/ld template import` 导入 |

**副本 ID 就是 `dungeons/` 下的目录名**，不需要在任何地方"注册"（启动与 `/ld reload` 时自动扫描）。最省事的起步：`cp -r dungeons/example dungeons/trial`，然后改 `dungeons/trial/config.yml` 的 `dungeon.name`、`world.template`（**必须与 `maps/` 下的文件夹同名**）与 `world.spawn`；地图模板导入见 [8.3](08-地图模板管理.md#83-导入)。

验收：`/ld reload` → `/ld doctor`。`doctor` 只看两处：**配置问题**（正常只有 `&a未发现配置问题。`；出现 `&e[trial] N 条问题` 分组就说明该副本有问题）与 **`【脚本语法校验】`**（正常 `&a已校验 N 条条件表达式，全部通过。`）。⚠ 只校验怪物组 `condition` 与 `start.condition`，不覆盖 `stages.yml` 的条件与条目 `when`（见 7.8.2）。`[脚本引擎]` 段应显示引擎可用；`example` 目录本身也会被当成副本加载，不需要就删掉。

> ⚠ 此时**先不要写任何脚本**：让副本能空跑（`/ld enter trial` → 站一会儿 → `/ld leave`）再往下写，能避免"配置错"和"脚本错"混在一起排查。

### 步骤 1：第一个能跑的脚本（5 行）

新建 `scripts.yml`，**先只写 `init`**（最直观）：
```yaml
# dungeons/trial/scripts.yml
init: |-
  log('=== 试炼回廊 init 被执行，实例=' + dungeon.getInstanceId());
  action.message('@all', '&7副本已创建，实例 &f' + dungeon.getInstanceId());
```
`/ld enter trial` 后**应该看到**：游戏内 `副本已创建，实例 a1b2c3d4`；控制台 `[脚本] === 试炼回廊 init 被执行，实例=a1b2c3d4`。

**没看到怎么查**（按这个顺序，90% 的问题在前两步）：

| 现象 | 原因 | 处理 |
|---|---|---|
| 控制台连 `[脚本]` 都没有 | `log()` 没执行，或引擎没起来 | 先看 `/ld doctor` 的 `[脚本引擎]` 段；再看有没有 `脚本引擎不可用` |
| 有 `脚本语法错误 [scripts.init] 行 N` | 引号/括号不配对 | 错误里带行号，直接去那一行 |
| 有 `脚本运行时错误 [scripts.init] 行 N` | 调了不存在的方法或用了 `player` | 见 [7.10](#710-已知限制与坑速查) 第 13 条 |
| 什么都没有，副本也进不去 | 副本根本没被加载 | 副本 ID = `dungeons/` 下的**目录名**（没有 `dungeon.id` 字段，也不需要注册）；`/ld list` 里没有 `trial` 就说明目录名不对或缺 `config.yml`（日志会打 `[trial] 缺少 config.yml，已跳过该目录`） |

### 步骤 2：开场演出与环境设置

把 `init` 扩充成"环境设置"，`start` 单独放"演出"（`init` 的时机是世界加载完、**玩家已经传送进来**之后，所以可以放心用 `@all` 和 `player`，触发者是队长）：

把 `init` 扩充成"环境设置"、`start` 单独放"演出"—— 两段脚本的完整写法照抄 [7.9.1](#791-示例-1开场演出--刷第一波) 即可（把副本名、标题、波次名换掉）。trial 特有的只是环境设置这三行：`action.gamerule('keep_inventory', 'true')`（死亡不掉落）、`action.gamerule('do_mob_spawning', 'false')`（关原版自然刷怪）、`action.gamerule('natural_regeneration', 'true')`。

**验收**：进本瞬间看到大标题 + 音效；环境（白天、不下雨）要**进副本世界**用 `/gamerule keep_inventory` 或 `/ld script log(dungeon.getWorld().getGameRuleValue('keep_inventory'))` 看，**别在主世界看** —— 改的是副本实例世界。

**两个坑**：
1. GameRule 三种写法都归一化：`keep_inventory` ✔ / `keepInventory` ✔ / `minecraft:keep_inventory` ✔。⚠ **`doFireTick` / `do_fire_tick` 在 Paper 26.x 已被移除且没有等价项** —— 写了不会崩，但控制台会打一条 `action.gamerule(...) 未生效：…`；26.x 改名的规则（`doMobSpawning` → `minecraft:spawn_mobs`、`naturalRegeneration` → `minecraft:natural_health_regeneration` 等）插件已内置映射，旧写法继续可用。
2. **`condition` 只能是一条表达式**（不能带 `;`），且**中文关键词会被无差别替换**，变量名里别出现 `是`/`否`/`怪物`（见 [7.6.3](#763-中文条件的-6-个坑)）。

### 步骤 3：刷第一波
```yaml
# dungeons/trial/monsters.yml
groups:
  wave_1:
    spawn_timing: {type: MANUAL}          # 由 start 脚本显式触发
    on_start: |-
      action.message('@all', '&e第 1 波：&f前厅守卫');
    on_end: |-
      action.message('@all', '&a前厅已清空！');
    monsters:
      - {id: Zombie, location: '0,64,-10', amount: '3-5'}
      - {id: Skeleton, location: '5,64,-10', amount: 2}
```

**验收**：标题播完 3–5 只僵尸 + 2 只骷髅出现，全部杀掉后收到"前厅已清空"。上面这段 `monsters.yml` 与 [7.9.1](#791-示例-1开场演出--刷第一波) 的 `wave_1` 同形，把 `id`/`location`/`amount` 换成你自己地图上的值即可。

**怪物不出的排查顺序**：`/ld script dungeon.getTotalAliveMonsters()`（现在场上有几只）→ `/ld script dungeon.getGroupSpawned('wave_1')`（这组刷过几次）→ `/ld script action.spawn_group('wave_1')`（手动刷一次，看控制台报什么）。

| 控制台提示 | 含义 |
|---|---|
| `副本 <短ID> 尝试启动不存在的怪物组「wave_1」（请检查 monsters.yml）` | `monsters.yml` 的键名拼错，或组不在 `groups:` 段下 |
| `怪物组「wave_1」的启动条件未满足，本次不生成。条件: …` | 组上有 `condition` 且当前为假 |
| `无法生成怪物「xxx」：MythicMobs 中不存在该 ID，且不是有效的原版实体名。请检查 monsters.yml 的 id 字段。` | 既不是 MythicMobs 怪物，也不是原版实体名 |
| `怪物组「xxx」的怪物 yyy 无法确定生成位置，已跳过` | 坐标/点位解析不出来（`location` 写错，或 `point` 引用了不存在的点位） |
| `怪物组「xxx」实体数 … 已达上限` | 撞上 `entity-limit`（主配置，默认 400） |
| 什么都没有，但也不出怪 | 多半是坐标不对 —— 怪刷在墙里/虚空，用 `/ld script log(dungeon.getGroupSpawned('wave_1'))` 确认"刷了但没看见" |

> **`id` 的解析规则**：装了 MythicMobs 时优先当 MM 怪物 ID；否则按原版实体名（大小写不敏感，也支持 `DZ_ZOMBIE` 这类带前缀写法）。所以**没装 MM 也能直接跑**。

### 步骤 4：用 `on_end` 链式推进（最稳的编排方式）

不要用"定时器 + 存活判定"推进波次（`存活怪物` 是全副本总数，见 [7.6.3](#763-中文条件的-6-个坑) 坑 1），**用 `on_end` 串**：在第一波 `on_end` 里 `setVar('波次', 2); action.spawn_group('wave_2');`，第二波 `on_end` 里 `action.setblock('20,64,0,AIR')` 开门（完整 YAML 见 [7.9.2](#792-示例-2波次链式推进--变量驱动的隐藏房)）。

> ⚠ **`on_end` 只触发一次**：无论"全灭"还是 `action.skip_group()`，都走 `completeGroup()` / `skipGroup()`，由 `endScriptFired` 去重；`repeat` 重复生成的组**每一轮都算同一个组**，`on_end` 仍只在该组最终完成时触发一次。这是它比"定时轮询存活数"稳得多的原因。

### 步骤 5：把流程交给阶段机（`stages.yml`）

要加**超时**、**分支**、**进度条**时让阶段机接管（完整分支写法见 [7.9.2](#792-示例-2波次链式推进--变量驱动的隐藏房)）：
```yaml
# dungeons/trial/stages.yml（分支、隐藏房的完整写法见 7.9.2）
入口: 前厅
前厅:
  名称: '&e清理前厅'
  通关条件: "dungeon.isGroupCleared('wave_1')"
  超时: 600                                  # 秒
  超时脚本: "action.fail('前厅超时');"
  下一阶段: 精英战
精英战:
  通关条件: "dungeon.isGroupCleared('wave_2')"
  下一阶段: Boss战
Boss战:
  通关条件: "dungeon.isGroupCleared('wave_boss')"
  开始脚本: "action.spawn_group('wave_boss');"
  下一阶段: 结算
结算:                        # 最终阶段：没有"下一阶段" = 走完自动通关
  通关条件: "true"
  开始脚本: "action.complete_dungeon();"
```

**验收**：`/ld status` 的阶段名依次变成 `清理前厅` → `精英守卫` → `首领`；前厅超过 10 分钟不动会失败。

| 机制 | 行为 |
|---|---|
| 通关条件求值频率 | ⚠ **事件驱动，不是每 tick 轮询** —— 见下方⚠ |
| 开始脚本去重 | 同一阶段只跑一次；`action.restart_stage()` 会清掉去重标记并重跑开始脚本，**但不会重新判定通关条件** |
| 没有"下一阶段" | 视为最终阶段 → 自动 `complete()`（所以最后一阶段条件写 `"true"` 即可） |
| 连跳上限 | 单次推进最多**连跳 8 个阶段**（`MAX_CHAIN_JUMPS`），超过就告警并停在原地（防条件恒真把副本一次跑完）。计数只在经 `advance()` 推进时累加；`goto_stage()` 会**清零**后再重新计数，`restart_stage()` 不计数 |

⚠ **阶段通关条件只在"事件"之后才重新判定。** 逐字核对 `dungeon/stage/StageMachine.java` 后，`evaluate(...)` 的调用点**只有这六处**：

| # | 触发点 | 源码位置 |
|---|---|---|
| 1 | 阶段机启动（初始判定） | `start()` |
| 2 | 怪物组**全灭** | `onGroupCleared()` |
| 3 | 怪物组被 **`skip_group` 跳过** | `onGroupSkipped()` |
| 4 | **交互点被触发** | `onInteract()` |
| 5 | 脚本调用 `action.goto_stage(...)` | `gotoStage()` |
| 6 | **每次进入一个新阶段之后**（`complete_stage()` / `goto_stage()` / 连跳的每一步都会落到这里） | `advance()` 末尾 |

**反过来说，下面这些「看着像事件」的东西其实不会触发重新判定**：

| ❌ 不会重判 | 原因 |
|---|---|
| 玩家**进入或离开区域** | `StageMachine.onZoneChange()` 是个**全工程零调用点的死方法**（`ZoneManager.onPlayerMove()` 只跑区域进出脚本，从不通知阶段机） |
| **阶段超时** | `tickTimeouts()` 只跑 `超时脚本`，不调用 `evaluate()` |
| `action.restart_stage()` | 走的是 `enterStage()`，不经过 `advance()` 的求值 |
| 任何每 tick 的定时任务 | 引擎根本没有轮询机制 |

**这意味着**：通关条件若依赖"某个悄悄变化的东西"（循环任务里 `setVar()` 的变量、玩家血量、背包物品），**它不会自己重新判定**，阶段会一直卡住 —— 这是"阶段不动"最隐蔽的原因。**实践建议**：让条件**挂在事件上**（用 `dungeon.isGroupCleared(...)`），或在设完变量后**主动推一把**：

```yaml
setVar('puzzleSolved', 1);
action.complete_stage();     # 或 goto_stage('下一阶段') —— 这两行都必须带分号
```
区域类条件（"区域内有人 ≥ 1"）**必须在 `进入脚本` 里自己推**：`if (dungeon.getZonePlayerCount('机关房') >= 2) action.complete_stage();`。这也是**唯一**需要"定时轮询"的场景 —— 条件确实与六个事件都无关时，用 `tasks.yml` 循环任务检查并调 `action.complete_stage()`；但优先改条件写法。**阶段超时**则是每 tick 由驱动器检查的（`tickTimeouts`），与通关条件无关。

### 步骤 6：结算 —— 写在 `complete` 钩子或最终阶段的「通关脚本」里

两者都在 `setState(COMPLETED)` **之前**执行，都是真正会跑的时机（顺序约束见 [7.2](#72-生命周期钩子scriptsyml)）；推荐 `complete` 钩子（只写一处，且能拿到完整的 `dungeon` 状态）：
```yaml
# dungeons/trial/scripts.yml
complete: |-
  action.title('@all', '&a&l通关！', '&7奖励已发放');
  action.grant_reward('@all', '通关奖励');   // 奖励不会自动发，必须显式调用
  action.wait('3秒');
  action.exit_dungeon();
```
奖励名必须**逐字**匹配 `rewards.yml` 的键：
```yaml
# dungeons/trial/rewards.yml
rewards:
  通关奖励:
    items:
      - {type: item, id: DIAMOND, amount: 5}
    money: 1000
    exp: 500
    commands: ["give %player% golden_apple 3"]
```

**验收**：打完 Boss 收到钻石 + 经验，`/ld leave` 回主世界后**奖励还在**（出本不会还原背包，见 [6.1](06-配置文件详解.md#出本时到底还原了什么)）。**没收到奖励怎么查**：控制台会有 `奖励「通关奖励」不存在` —— 就是名字对不上。

### 步骤 7：失败路径与全员阵亡

**一件必须自己做，一件有兜底**：① **超时失败**必须自己写（已在 `stages.yml` 的 `超时脚本` 里写了 `action.fail('前厅超时')`）；② **全员阵亡**推荐写 `scripts.yml` 的 `all_death` 收尾，但**不写也不会把人留在副本里** —— 脚本跑完后如果没有一个活人，插件会自动判失败并退出：

```yaml
# scripts.yml —— 追加（内置示例就是这么写的）
all_death: |-
  action.title('@all', '&c&l全队阵亡', '&7副本失败，正在退出…');
  action.fail('全员阵亡');   // 跑 fail 钩子 → 10 秒后把所有人传回主世界
  // action.revive('@all');   // 也可以给一次"复活赛"，这样就不会判失败
```
> ⚠ `all_death` **没有触发者**，脚本里不要用 `player` / `@trigger`（给队员发消息用 `@all`）。
> ⚠ 别把"次数耗尽"当成"副本结束"：`revive.on_exhausted` 是在**最后一次复活成功、次数刚归零**时触发的，那时人已经站起来了、副本还在继续 —— 在那里 `action.fail()` 会把还在打的队伍直接判失败。要收尾请写 `all_death`。死亡与复活的完整语义见 [6.2 的 `revive` 段](06-配置文件详解.md#revive-段--复活系统)；两个常用钩子：`on_revive`（复活成功后，触发者=被复活者）、`on_exhausted`（复活成功且剩余次数变为 0 时）。

## 7.12 常用配方库（20 个可复制片段）

片段全部使用 [7.4](#74-action-api-完整清单) / [7.5](#75-dungeon-api-完整清单) 中真实存在的方法，可直接粘贴；`<...>` 处替换成你自己的名字/坐标。

### 7.12.1 波次与战斗

**① 波次链式推进（推荐主结构）**：在 `on_end` 里 `setVar('波次', 2); action.spawn_group('wave_2');` 即可，引擎保证只在"全灭"时触发一次 —— 完整写法见 [7.9.2](#792-示例-2波次链式推进--变量驱动的隐藏房)。

**② 有限增援（同组重复刷，不会无限）**

```yaml
groups:
  wave_1:
    repeat:
      interval: 200        # tick，最小 20
      max: 3               # 必须写，没有无限增援
      wait_cleared: true   # 前一波没清完就跳过本轮（不计入轮次）
    monsters:
      - {id: Zombie, location: '0,64,-10', amount: '2-4'}
```

**③ 按人数动态加难度**

```yaml
# stages.yml
前厅:
  开始脚本: |-
    var n = dungeon.getOnlinePlayerCount();
    var mult = n <= 1 ? 1.0 : (n <= 3 ? 1.5 : 2.0);
    if (n >= 4) action.message('@all', '&c4 人挑战：怪物数量翻倍');
    action.spawn_group('wave_1', mult);      // 倍率作用于每个条目的数量
```

**④ 随机刷一种怪（开盲盒）**：`action.random_spawn_group('variant_a', 'variant_b', 'variant_c');`

**⑤ 精英怪按难度替换**：条目级 `when: "getVar('难度') >= 3"` 配 `replace_with: Stray`（条件成立→换成 Stray，不成立→按原 id 生成），例见 [7.9.2](#792-示例-2波次链式推进--变量驱动的隐藏房)。

**⑥ 分批登场（延迟生成，不卡顿）**

```yaml
    monsters:
      - id: Zombie
        location: '0,64,-10'
        amount: 3
      - id: Zombie
        location: '0,64,-10'
        amount: 3
        delay: 100               # 5 秒后才出这一批
```

### 7.12.2 Boss 战（阶段推进与演出）

**⑦ Boss 出现 30 秒后狂暴**（`dungeon.*` **没有读血量的接口**，所以血量阶段只能靠 MythicMobs 技能或下面这种计时近似）→ **⑧ Boss 死亡时的专属演出**：两者都写进 `tasks.yml`。

```yaml
# tasks.yml
tasks:
  Boss狂暴计时:                        # ⑦ 循环任务：每秒滴答一次，自己数够 30 秒
    type: loop
    interval: 1
    script: |-
      if (getVar('bossEnraged') === 1) return;          // 已经狂暴过 → 退出（防重复）
      if (!dungeon.isGroupActive('wave_boss')) return;  // Boss 还没出场 → 不开始计时
      var t = getVar('bossTimer') + 1;
      setVar('bossTimer', t);
      if (t === 30) {
        setVar('bossEnraged', 1);
        action.message('@all', '&c&l首领狂暴了！');
        action.spawn_group('boss_adds');
      }
  Boss倒下:                            # ⑧ 事件任务
    type: event
    trigger: boss_kill
    trigger_target: wave_boss
    script: |-
      action.title('@all', '&4&l首领被击败', '&7通往终点的门已开启');
      action.lightning('0,64,-26', false);   // false = 只出特效不造成伤害
```
> 想读**真实血量百分比**做多阶段变身，只能走 MythicMobs 的技能系统（MM 里配血量触发器、回调执行 `mm` 技能命令），插件侧没有对应 API。别指望用击杀数反推血量。事件任务 `boss_kill` 的触发者是**击杀者**（可能是 `null`），用 `@all` 最安全。

### 7.12.3 计时与节奏

**⑨ 副本内倒计时提示（不阻塞）** → **⑩ 限时挑战：把剩余时间显示在动作栏**（先在 `init` 里 `setVar('timeLimit', 600);`，与 `config.yml` 的 `time.limit` 保持一致）。

```yaml
# tasks.yml —— times 的键是秒数（整数），值是脚本
tasks:
  倒计时:                              # ⑨ 定点播报
    type: timed
    times:
      60: "action.title('@all', '&c&l1 分钟', '&7前往出口');"
      300: "action.title('@all', '&c&l5 分钟', '&7最后 5 分钟');"
  剩余时间:                            # ⑩ 每秒刷新动作栏
    type: loop
    interval: 1
    script: |-
      var left = Math.max(0, getVar('timeLimit') - dungeon.getRunningTime());
      action.actionbar('@all', '&e剩余时间 &f' + left + ' &e秒');
```
> 定时/循环任务没有触发者（脚本里不要用 `player`），也不占脚本线程池，超长等待优先用它。

> `dungeon.getRunningTime()` 返回**已运行秒数**，配置里的 `time.limit` 是**总秒数**，两者相减才是剩余。每秒一次的 `actionbar` 是"常驻 UI"的标准做法，成本低；但**别用循环任务发聊天消息**（玩家会疯）。

**⑪ 真正的"等 3 秒再继续"**：脚本内 `action.wait('3秒')` 只睡脚本线程、不卡服务器，直接写在脚本里即可；只有需要与「副本开启时刻」对齐（而不是与上一行动作对齐）的延迟才用 `times` 定时任务。

```yaml
start: |-
  action.message('@all', '3秒后开门');
  action.wait('3秒');            // 只等脚本自己的下一步，服务器照常跑
  action.setblock('20,64,0,AIR');
```

### 7.12.4 区域、交互与解谜

**⑫ 进入区域触发伏击（只触发一次）**

```yaml
# zones.yml
埋伏区:
  名称: '&c伏击区'
  范围: '10,60,10 ~ 20,70,20'      # x,y,z ~ x,y,z，两点顺序随意
  默认开启: true
  点位: {落点: '15,64,15,0,0'}
  进入脚本: |-
    if (getVar('ambushDone') === 1) return;    // ← 只触发一次，必须自己守
    setVar('ambushDone', 1);
    action.message('@all', '&c中埋伏了！');
    action.spawn_group('ambush');
```
> ⚠ **区域进出脚本每次进出都会触发**（不是"只能触发一次"）：任何"只做一次"的逻辑（刷怪、发奖、开门）都必须用变量守卫 —— 这是副本脚本里最高频的 bug 来源。范围只支持**长方体**（AABB），不支持球形/多边形；单副本最多 64 个区域，**超出是硬截断**（告警后直接丢弃，不是排队）。

**⑬ 解谜：三个机关全踩下才开门**（三个交互点同形，这里只列一个）

```yaml
# interacts.yml —— 注意每个交互点都要有 type
interacts:
  机关甲:
    type: STEP_ON                 # 踩踏
    once: false                   # 允许反复触发（去重交给变量）
    parameters: {location: '10,64,10'}
    script: |-
      setVar('plateA', 1);
      checkPlates();
```
```javascript
// functions.js
function checkPlates() {
    if (getVar('plateA') === 1 && getVar('plateB') === 1 && getVar('plateC') === 1) {
        if (getVar('doorOpened') === 1) return;     // ← 守卫：只开一次
        setVar('doorOpened', 1);
        action.broadcast('&a三个机关全部启动，石门开启！');
        // 门是一整片、以后还要关回去的话，用障碍物更省事：
        // action.remove_obstacle('石门');     // 开启时自动恢复原方块（见 6.6）
        action.setblock('10,64,10,AIR');
    }
}
```
> `interacts.yml` 的可用 `type`：`RIGHT_CLICK_BLOCK` / `LEFT_CLICK_BLOCK` / `BREAK_BLOCK` / `PLACE_BLOCK` / `STEP_ON` / `ENTER_REGION` / `RIGHT_CLICK_ENTITY`。`once` 默认 `true`（**每个玩家**只能触发一次）；想让全队一起踩机关就设 `once: false` 并自己用变量去重。

**⑭ 需要队友配合的交互（要求附近有人）**

与 ⑬ 写在同一个 `interacts:` 段里，再加一个 `协力机关` 入口（`type: RIGHT_CLICK_BLOCK` / `once: false` / `parameters: {location: '10,64,10'}`），`script` 换成：`if (dungeon.getZonePlayerCount('机关房') < 2) return action.message('@trigger', '&c需要至少 2 人同时站在机关房内');` 之后 `action.message('@all', '&a机关被协力启动了'); action.complete_stage();`

**⑮ 隐藏房（变量驱动的分支）**：`下一阶段` 列表第一项带 `条件`、第二项做兜底即可，例见 [7.9.2](#792-示例-2波次链式推进--变量驱动的隐藏房)。

> **分支按列表顺序取第一个成立的**；无条件项作为兜底；都不成立且无兜底 = 视为最终阶段 → 自动通关。所以**兜底项一定要写**。

### 7.12.5 奖励与结算

**⑯ 按表现发不同奖励**

```yaml
# stages.yml —— 最终阶段的开始脚本
结算:
  通关条件: "true"
  开始脚本: |-
    if (dungeon.getAlivePlayerCount() >= dungeon.getMemberCount()
            && dungeon.getTotalMobKills() >= 30) {
        action.grant_reward('@all', '完美通关');
    } else {
        action.grant_reward('@all', '通关奖励');
    }
    action.complete_dungeon();
```
> ⚠ **奖励只能发一次，别在两个地方各发一遍。** 阶段机在"没有兜底分支"时会把最终阶段的**开始脚本补跑一次**（`advance()` 的收尾逻辑），所以把发奖写成**最终阶段的开始脚本**（如上）只发一次 ✅，同时又在前一阶段的 `通关脚本` 里再发一遍 → **会拿到两份奖励** ❌。选一种，别混。

**⑰ 首通额外奖励（每个玩家只给一次）**

```yaml
结算:
  开始脚本: |-
    action.grant_reward('@all', '通关奖励');
    if (getVar('firstClear') === 0) {
        setVar('firstClear', 1);
        action.grant_reward('@all', '首通奖励');
    }
    action.complete_dungeon();
```
> ⚠ **变量是"副本实例"作用域，出本即销毁** —— 上面的 `firstClear` 只在**这一把**有效，不是"这个玩家永远只给一次"。要做真正的首通请用 `action.command('@all', '...')` 调你已有的统计插件，或让奖励物品自带 Soulbound 类标记。**插件本身不保存玩家战绩**（见 [6.12](06-配置文件详解.md#612-已解析但未生效的字段)）。

**⑱ 失败也要发安慰奖**

```yaml
前厅:
  超时脚本: |-
    action.message('@all', '&c时间耗尽，试炼失败');
    action.grant_reward('@all', '安慰奖');
    action.fail('前厅超时');
```

## 7.13 脚本调试手册

### 7.13.1 三条命令搞定 90% 的问题

`/ld doctor`（静态体检：引擎状态、语法错误、配置完整性）· `/ld status`（副本运行状态：阶段、人数、怪物）· `/ld script <JS>` 是核心工具：**只能由副本内的玩家执行**，触发者就是你自己（所以 `player` 可用）。
```
/ld script log('hello')                            # 打日志
/ld script log(dungeon.getTotalAliveMonsters())    # 看现在有几只怪
/ld script log(getVar('波次'))                      # 看变量当前值
/ld script action.spawn_group('wave_2')            # 手动触发一波
/ld script log(dungeon.getGroupNames())            # 所有组名（打印成 Java 的 [a, b, c]，不是 JSON）
```

### 7.13.2 五步定位法

脚本"没反应"时，**按顺序**问这五个问题，不要跳步：

| 步骤 | 问题 | 怎么查 | 结论 |
|---|---|---|---|
| 1 | 脚本被执行了吗？ | 脚本第一行加 `log('HIT')`，或看控制台有没有 `[脚本]` | 没执行 → 看第 2 步；执行了 → 看第 3 步 |
| 2 | 引擎是活的吗？ | `/ld doctor` 的 `[脚本引擎]` 段；找 `脚本引擎不可用` | 不可用 → 查 [2.3 依赖库](02-安装与依赖.md#23-依赖库为什么-jar-只有-05mb) |
| 3 | 触发条件成立了吗？ | 条件相关的看 `/ld doctor`；事件类的用 `/ld script` 手动触发 | 不成立 → 条件写错，见 [7.6](#76-条件表达式) |
| 4 | 是报错被吞了吗？ | 搜 `脚本语法错误` / `脚本运行时错误` / `脚本宿主异常` | 有 → 按行号改（**宿主异常没有行号**，按异常类名搜源码）；没有 → 第 5 步 |
| 5 | 是干了但看不见吗？ | 用 `/ld script log(...)` 打印中间值 | 常见于坐标错、材质名错、选择器解析成空集 |

### 7.13.3 日志关键字对照表

| 日志 | 级别 | 含义与处理 |
|---|---|---|
| `GraalJS 脚本引擎已就绪（隔离加载 + 已预热）` | INFO | 正常启动 |
| `脚本引擎不可用，跳过执行: <来源>` | WARN | 依赖缺失或 `script.enabled: false`；条件一律当 false → 副本会卡住 |
| `脚本语法错误 [<来源>] 行 N → …` | WARN | 表达式写错，**当 false 处理**，同一处只报一次 |
| `脚本运行时错误 [<来源>] 行 N → …` | WARN | 脚本正文抛异常（JS 侧），同一实例同一处只报一次 |
| `脚本宿主异常 [<来源>] → Java异常名: 消息` + `行号不可用（宿主（Java）异常不带源码位置），本次不打印源码上下文。` | WARN | 插件自己的 Java 代码抛的异常（不是脚本写法问题）。**没有行号**：引擎对宿主异常不给源码位置，所以只报异常类名与消息 —— 拿这个类名去搜源码即可定位 |
| `脚本资源超限（疑似死循环） [<来源>] 行 N → 脚本超过语句上限已被强制中断（疑似死循环）` | WARN | 撞上语句上限（默认 10⁹ 条，几乎只可能是死循环） |
| `动作频率超限，已丢弃本次脚本执行` | WARN | 撞上 `max-actions-per-second`（按实例统计每秒脚本执行次数） |
| `加载脚本库失败（副本 X 第 N 个 js 文件）: …` | WARN | `functions.js` 有语法错误 → 该文件里所有函数都不存在 |
| `怪物组「X」的启动条件未满足，本次不生成。条件: …` | INFO | 组条件为假 |
| `副本 <短ID> 尝试启动不存在的怪物组「X」（请检查 monsters.yml）` | WARN | 组名拼错 |
| `action.<方法> 的<参数>「X」无效` | WARN | 每个方法的文案不同（如 `action.sound 的音效名「X」无效`、`action.give_item 的材质「X」无效`），搜 `无效` 即可 |
| `action.teleport_point: 点位「X」解析失败（请检查 zones.yml 中是否定义了该点位）` | WARN | `zones.yml` 里没有这个点位 |
| `action.teleport 的位置「X」无法解析（应为 区域.点位 或 x,y,z[,yaw,pitch]）` | WARN | `teleport` / `tp` 的位置参数既不是命名点位也不是合法坐标（点位缺失时 `teleport_point` 报的是上一条） |
| `奖励「X」在 rewards.yml 中不存在` | WARN | 奖励名与 `rewards.yml` 的键不匹配 |

> 上表的引文都**逐字取自源码**，可以直接复制去 grep 日志。
> **把 `config.yml` 的 `debug` 设为 `true`** 会打出更多细节（包括 `action.revive` 失败原因）。排错时先开它。

### 7.13.4 二分法：脚本太长找不到哪行错

`行 N` 里的 N 是**出错脚本片段内的行号**，不是文件行号。⚠ **多行脚本的报错行号 − 1 = 你在 `|-` 块里数的行号**：引擎会把多行脚本包一层再执行（`ref.eval("js", "(function(){\n" + code + "\n})()")`，包完你的第 1 行变成第 2 行）；条件表达式是 `"(" + source + ")"` 单行包装，没有这个偏移。片段长时用二分法：从中间劈成两半，各加一句 `log('A')` / `log('B')` → 看哪一半没打出来 → 重复，直到定位到具体一两行。**多行脚本一律用 `|-` 块**（见 [7.1.1](#711-脚本怎么写统一这一种排版)）：写成 `- "…"` 的字符串列表时每项都算独立的一段，行号参考价值就没了。

### 7.13.5 探针模板（贴进 `functions.js`，排错时随叫随到）
```javascript
function hit(tag) { log('HIT ' + tag + ' @' + dungeon.getRunningTime() + 's'); }   // 确认"脚本跑到这里了"
function show(label, v) { log('[' + label + '] ' + v); }                            // 打印任意对象（Java 对象用 + 拼接最稳）
function expect(label, cond) { if (!cond) log('!! 断言失败: ' + label); return cond; }
// 用法： on_end: |- / hit('wave_1.on_end'); / expect('wave_1 已清', dungeon.isGroupCleared('wave_1'));
```

## 7.14 性能与反模式

### 7.14.1 六条硬性规则

| # | 规则 | 原因 |
|---|---|---|
| 1 | **循环任务里不要做重活** | `tasks.yml` 的 `loop` 走 `Bukkit.runTaskTimer`，**跑在主线程**，周期 = `max(1, interval) × 20` tick（`interval` 默认 **60 秒**，不是每秒）；脚本执行时间超过周期会堆积 |
| 2 | **超长等待（分钟级）优先用 `tasks.yml` 定时任务** | `action.wait` 只睡脚本线程、不卡服务器，但脚本线程池固定 3 个线程：大量实例同时睡长 `wait` 时，其它脚本要排队。短等待（秒级节奏点）放心用 `wait` |
| 3 | **条件别做重活、也别指望它自己重算** | 阶段通关条件是**事件驱动**的（阶段机启动 / 怪物组全灭或被跳过 / 交互点 / `goto_stage` / 进入新阶段），不是每 tick 轮询，**"区域进出"与"阶段超时"都不算触发**。依赖"悄悄变化的变量"的条件会一直不成立 |
| 4 | **区域进出脚本必须自我去重** | 每次进出都会触发；无守卫会导致重复刷怪/重复发奖 |
| 5 | **不要跨脚本共享 JS 全局变量** | 每次执行都是新 `Context` → `var` 和函数都不保留，只能用 `setVar`/`getVar` |
| 6 | **`action.command()` 拼命令前必须做白名单校验** | 它不转义参数，玩家可控内容会变成越权执行 |

### 7.14.2 反模式对照

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 用定时任务硬凑脚本内的节奏 | 短节奏直接 `action.wait('5秒')`（只睡脚本线程、服务器照常跑）；只有与开本时刻对齐的延迟才用 `tasks.yml` 的 `times` |
| 用定时轮询判断"怪清完了吗"（`loop` 里每秒查 `dungeon.getTotalAliveMonsters() === 0`） | 用 `on_end` 链式推进 —— 条件成立的那一秒会**反复触发**（直到下一波开始刷），而且"全副本总数"不是你想要的语义 |
| 在循环任务里每秒 `action.message('@all', ...)` | 用 `times` 定点播报（配方 ⑨） |
| 通关条件里做重活（`dungeon.getPlayerNames().size() > 0 && dungeon.getTotalMobKills() > 100`） | 先算好、用便宜的条件（`dungeon.isGroupCleared('wave_boss')`）—— 条件虽不是每 tick 求值，但**每次事件都会重算**（见 [7.11 步骤 5](#步骤-5把流程交给阶段机stagesyml) 的六个触发点，**不含**"玩家进区"与"阶段超时"），做重活还可读性差、容易踩空集 |

### 7.14.3 `action.*` 的异步性（容易误判时序）

脚本在专用线程执行，**所有 `action.*` 方法内部都会跳回主线程执行 Bukkit 操作**（脚本线程等结果，主线程不被占用）：

| 方法 | 异步点 |
|---|---|
| `wait` / `wait_clear` / `stop` / `set` | **不跳线程**：只在脚本线程上睡眠/轮询/改变量（主线程调用时 `wait` 系列直接跳过并告警一次） |
| 其他全部方法 | 脚本线程 → 派发到主线程执行并等待返回；主线程调用（条件、`/ld script`）时立即执行 |
| `teleport` / `tp` / `teleport_point` / `teleport_zone` | 传送在主线程执行，并顺带 `resyncPlayer` 更新区域状态 |
| `create_obstacle` / `remove_obstacle` / `toggle_obstacle` | **同步写方块**：这一行执行完方块就已经在那儿了（旧版障碍物是分帧写入，所以老文档里才有"严格时序要用回调"那种告诫）。代价是单次写入有上限（32768 格），超了会打 warning 并跳过，不会只写一半 |

### 7.14.4 规模参考

| 项 | 实测/设计值 |
|---|---|
| 引擎预热 | 启动时预热，首次执行无额外延迟 |
| 函数库缓存 | `Source` 级编译缓存，`functions.js` 每次执行重新注入但不重新编译 |
| 语句上限 | `max(200000, execution-timeout-ms × 200000)`，`execution-timeout-ms` 默认 `5000` → 上限 **1,000,000,000 条（10⁹）** |
| 执行限流 | `max-actions-per-second`（默认 200）按**实例**统计**每秒脚本执行次数**，超出丢弃 |
| 单世界实体上限 | `entity-limit`（默认 400） |

## 7.15 JavaScript 五分钟速查（给不写代码的服主）

你**不需要系统学 JS**，会下面这些就能写出 90% 的副本脚本。

### 7.15.1 变量与字符串
```javascript
var n = 3; var name = '张三'; var flag = true;      // 数字 / 字符串（单双引号都行）/ 布尔
var text = '击杀 ' + n + ' 只，' + name;             // + 号拼字符串
action.message('@all', '你好');                 // 调方法 = 点 + 括号 + 逗号（2 个参数）
action.title('@all', '标题', '副标题');          // 3 个参数；dungeon.getTotalAliveMonsters() 0 个参数、有返回值
```
⚠ **只用 `var`**，不要用 `let` / `const`（虽然能用，但 `var` 与 QueDP 写法一致，迁移省事）。

### 7.15.2 调方法：就是"点 + 括号 + 逗号"

**对照法**：文档里写 `grant_reward(String selector, String rewardName)`，你写 `action.grant_reward('@all', '通关奖励')` —— **类型不用管，顺序照抄**（示例见 7.15.1）。

### 7.15.3 判断与分支
```javascript
if (dungeon.getAlivePlayerCount() >= 2) { action.message('@all', '两人以上，开启隐藏房'); }
else { action.message('@all', '人数不足，跳过隐藏房'); }
```
比较运算符：`===`（等于）、`!==`（不等于）、`>`、`<`、`>=`、`<=`。

⚠ **判断"有没有设过变量"不要用 `null`，也不要用 `=== 0`**：`getVar` 未设置时返回数字 `0`，而变量可能被设成 `2`、`'yes'`、`true` 等任何值，用 `=== 0` 反推"没设过"会在这些情况下判错。**约定一个哨兵值并在 `init` 里先设好**最稳：
```javascript
setVar('foundSecret', -1);                    // init 里：-1 = 还没找到
if (getVar('foundSecret') === 1) { /* 确实找到了 */ }
```

### 7.15.4 循环（遍历 Java 列表）
```javascript
var names = dungeon.getPlayerNames();       // 这是 Java List，不是数组！
for (var i = 0; i < names.size(); i++)      // 用 .size() 不是 .length
    action.message('@all', '队员：' + names.get(i));   // 用 .get(i) 不是 [i]
```

### 7.15.5 提前退出与防重复
```javascript
if (dungeon.getOnlinePlayerCount() < 2) return;   // 入口守卫：多行脚本支持 return（会被包成 (function(){...})()）
if (getVar('doorOpened') === 1) return;           // "只做一次"的守卫 —— 副本脚本里最常用的模式
setVar('doorOpened', 1);
action.setblock('10,64,10,AIR');
```

### 7.15.6 最常用的 15 个方法（背下来就够写副本了）
```javascript
action.message('@all', '&7文本');            // 发消息（& 是颜色代码）
action.title('@all', '主标题', '副标题');     // 大标题

```

### 7.15.7 报错怎么读

`[liudungeon] 脚本运行时错误 [scripts.start] 行 3 → ReferenceError: player is not defined` 拆开看：`[scripts.start]` = **哪个钩子**出错；`行 3` = 该脚本片段内的**第 3 行**；`ReferenceError: player is not defined` = 用了不存在的名字（这里就是"这个钩子没有触发者"）。常见错误名：

| 错误 | 原因 |
|---|---|
| `ReferenceError: xxx is not defined` | 名字拼错，或该钩子没注入 `player` |
| `TypeError: xxx is not a function` | 方法名拼错（对着 [7.4](#74-action-api-完整清单) 核对），或返回的是 Java 列表却用了 JS 方法 |
| `SyntaxError` | 引号/括号不配对，多写或少写了 `,` |
| `TypeError: Cannot read property ... of null` | 某个查询返回了 `null`（如点位解析失败） |
