# 四、指令手册

> [← 三、五分钟上手](03-五分钟上手.md) · [总目录](../05-使用说明.md) · [五、GUI 菜单 →](05-GUI菜单.md)

## 4.1 指令注册

| 项 | 内容 |
|---|---|
| 主指令 | `/ld` |
| 别名 | `/liudungeon`、`/dungeon` |
| 无参数 | 等同于 `/ld help` |
| 附加指令 | `/npc_choice <序号>`（权限 `liudungeon.use.npcchoice`） |

> **根级子指令几乎没有中文别名** —— 唯一的中文别名例外是 `menu` / `菜单`。
> 英文别名倒有不少：`?`（=`help`）、`gui`（=`menu`）、`team`（=`party`）、`groups`（=`group`）、
> `pdata`（=`player`）、`papi`（=`placeholders`）、`tpl` / `map` / `maps`（=`template`）。
> `列表`、`邀请` 这类中文别名只存在于 `/ld party` 与 `/ld template` 的**二级子指令**里。

## 4.2 玩家指令

| 语法 | 作用 | 权限 |
|---|---|---|
| `/ld help` | 指令总览 | — |
| `/ld list` | 列出所有副本（**不含演示副本** `example` 与 `hide: true` 的） | — |
| `/ld info <副本ID>` | 副本详情与配置问题 | — |
| `/ld enter <副本ID>` | 进入副本（会带上组队成员） | `liudungeon.use.enter` |
| `/ld leave` | 离开副本（**保留队伍**） | — |
| `/ld restart` | **队长**强制结束当前副本并重开一局（全队一起出去，见下） | — |
| `/ld running` | 运行中的实例 | — |
| `/ld revive` | 使用复活道具复活自己 | — |
| `/ld menu`（`gui`、`菜单`） | 打开 GUI 菜单 | `liudungeon.use.menu` |
| `/ld player [玩家]` | 查看冷却/每日/保底数据 | 查自己无需权限；**查别人需要 `liudungeon.admin`** |
| `/ld placeholders`（`papi`） | 列出全部 PAPI 变量 | — |
| `/ld party …`（`team`） | 队伍系统，见 4.4 | `liudungeon.use.party` |

`/ld info` 与 `/ld enter` 的副本参数**既接受 ID 也接受去色后的中文显示名**，
但 Tab 补全只给 ID。

**`/ld restart` —— 队长强制结束并重开**

和队伍菜单里那颗「结束副本」按钮是**同一条代码路径**，给不用 GUI 的队长留的出口。

| 步骤 | 说明 |
|---|---|
| `/ld restart` | 先告诉你"将结束「X」并重开一局（已进行 mm:ss），当前进度会丢失" |
| `/ld restart confirm` | 真结束。Tab 补全会给出 `confirm` |

- **只有队长能用**，非队长会被告知当前队长是谁；无队伍的单人进本，自己就是队长。
- **不需要队员同意**：没有投票、没有"等其它成员点确认"，`confirm` 完立即生效。
  队员会收到一条"队长结束了本副本，正在重建一个新的世界…"的广播。
- **队长本人不必在副本里**。副本是队长开的、费用是他扣的，中途自己 `/ld leave`
  出去之后仍然要能把它结束掉 —— 否则副本会一直占着实例槽位，而唯一有权结束它的人
  却无从下手。

## 4.3 管理指令（全部需要 `liudungeon.admin`，默认仅 OP）

| 语法 | 作用 |
|---|---|
| `/ld status` | 运行状态总览（排障第一站） |
| `/ld doctor` | 配置体检 |
| `/ld doctor --json` | 配置体检的**结构化**版本，写到 `plugins/liudungeon/export/doctor.json`（见 4.9） |
| `/ld export <副本> [--stdout]` | 导出**解析之后**的副本配置 JSON + 交叉引用校验（见 4.9） |
| `/ld create <副本ID> [模板名]` | **新建副本**：建 `plugins/liudungeon/dungeons/<副本ID>/` 并写入插件内置示例的 10 个文件，顺手把 `config.yml` 的展示名与 `world.template` 改成这个副本该有的值（不写模板名则默认与副本 ID 同名），随后自动重载，`/ld list` 立刻能看到。**不碰世界与模板** —— 模板仍要用 `/ld template import <地图名> [模板名]` 导入 |
| `/ld delete <副本>` | **删除副本**：先把整个副本目录备份到 `plugins/liudungeon/bak/<副本ID>_<时间戳>/`，备份成功才删除，并立即从副本列表移除（无需 reload）。还有运行中实例时拒绝删除（先 `/ld kill`）。备份失败则中止，**绝不**删目录 |
| `/ld reload` | 重载全部配置 |
| `/ld group [实例ID]` | 实例全貌：怪物组/阶段/复活/区域/交互点/玩家 |
| `/ld stage [实例ID]` | 阶段流程状态 |
| `/ld spawn <组名>` | 手动启动怪物组（调试） |
| `/ld reward <奖励名>` | 给自己发一份奖励（调试） |
| `/ld kill <实例ID>` | 强制结束实例 |
| `/ld script <JS代码>` | 即时执行一段脚本（调试）。⚠ **只能由玩家执行，且必须在副本内** —— 控制台执行会得到"该指令只能由玩家在副本内执行"，不是权限提示 |
| `/ld edit …` | **游戏内编辑模式**（进入编辑世界，用工具/菜单改副本配置）。全部 20 个子指令见 4.10 |
| `/ld template …` | 地图模板管理，见 4.5 |
| `/ld menu reload` | 热重载 `gui.yml` |
| `/ld revive count [数值]` | 设置自己的复活次数 |

> ⚠️ **安全提示（很重要）**
>
> `/ld script` 会把参数字符串当作 JavaScript 交给脚本引擎执行，而脚本里的
> `action.command(...)` 是以**控制台身份**执行命令的。也就是说：
>
> ```
> /ld script action.command('@all','op 自己')
> ```
>
> 可以直接拿到 OP，进而完全接管服务器。
>
> **该指令以前对全体玩家开放**（只要求"人在副本内"），属于严重漏洞，已修复为
> 需要 `liudungeon.admin`。升级后请确认线上是修复版本。
> 如果你不需要这个调试入口，可以在权限插件里显式拒绝 `liudungeon.admin` 之外的玩家，
> 或直接不要在配置里给任何人这个节点。
>
> 同理，`/ld reload`、`/ld kill`、`/ld spawn`、`/ld reward`、`/ld status`、
> `/ld doctor`、`/ld group`、`/ld stage`、`/ld template` 以前也都没有权限校验，
> 现在统一归入 `liudungeon.admin`。

## 4.4 队伍系统 `/ld party`

整体要求玩家身份与 `liudungeon.use.party` 权限。**控制台只能执行英文的 `/ld party list`**
（判断用的是 `equalsIgnoreCase("list")`）。

| 语法（含中文别名） | 作用 | 限制 |
|---|---|---|
| `/ld party` | 队伍帮助 | — |
| `/ld party create`（`创建`） | 建队 | 已在队伍中会被拒 |
| `/ld party disband`（`解散`） | 解散队伍 | 仅队长 |
| `/ld party invite <玩家>`（`邀请`） | 邀请在线玩家 | 必须在队伍中。**同一队伍重复邀请同一人只刷新有效期**，不报错、不堆叠；被邀请人会收到带 `[接受]` `[拒绝]` 按钮的消息 |
| `/ld party accept [玩家]`（`接受`） | 接受邀请 | — |
| `/ld party reject [玩家]`（`拒绝`） | 拒绝邀请 | — |
| `/ld party kick <玩家>`（`踢出`） | 踢出成员 | 仅队长 |
| `/ld party leave`（`离开`） | 退出队伍 | — |
| `/ld party transfer <玩家>`（`转让`） | 转让队长 | 仅队长 |
| `/ld party name [新队名]`（`队名`） | 改队名；不带参数只显示当前队名 | 仅队长 |
| `/ld party join <队名>`（`加入`） | 申请加入公开队伍 | 必须无队伍 |
| `/ld party list`（`列表`） | 列出公开队伍 | — |
| `/ld party info`（`信息`） | 查看我的队伍 | 必须在队伍中 |
| `/ld party settings …`（`设置`） | 队伍设置，见下表 | 均需队长 |

**`/ld party settings` 子项**

| 子项 | 取值 |
|---|---|
| `join`（`加入方式`） | `invite` / `apply` |
| `open`（`公开`） | 无参数，切换开关 |

> ⚠️ `/ld party join <队名>` **不等于入队**。它只向队长发送申请提示，
> 真正入队仍要队长执行 `/ld party invite`。
> `joinMethod=invite` 与 `apply` 在这里**没有行为差异**，唯一的硬门槛是 `isOpen()`
> （`settings join` 因此实际上只影响 `/ld party info` 与 `/ld party list` 的显示）。

> 📌 `settings` 原有 `loot` / `exp` / `scope` / `storage` 四项，**已全部移除**：
> 前三个只有字段存储，运行期没有任何代码按它们分配掉落物或经验
> （`DungeonListener` 里那段分配代码也已删除），队伍仓库也没有任何界面能取出物品。
> 摆着它们等于承诺一个不存在的功能。

**点一下就能接受邀请**：被邀请人收到的消息末尾带 `[✔ 接受]` / `[✘ 拒绝]`
两个可点击按钮，点击即执行上表里的 `accept` / `reject`（以玩家自己身份发出，
权限与校验完全不变）。不用手打指令 —— 玩家名里有中文或特殊字符时几乎必然打错。
正文与按钮文字可在 `config.yml` 的 `party.invite-message` /
`party.invite-buttons.accept` / `party.invite-buttons.reject` 里改。

## 4.5 地图模板 `/ld template`

统一需要 `liudungeon.admin`。模板存放于 `plugins/liudungeon/maps/`。

| 语法 | 作用 |
|---|---|
| `/ld template [list]`（`列表`） | 列出现有模板 + 可导入的地图来源 |
| `/ld template import <地图名> [模板名] [--overwrite]` | 从世界目录导入为模板 |
| `/ld template delete <模板名>`（`remove`、`删除`） | 删除模板 |
| `/ld template info <模板名>`（`信息`） | 模板详情：大小、区块数、`level.dat` 状态、被谁引用、维度目录 |
| `/ld template repair <模板名>`（`修复`） | **只重写 level.dat，不重新复制地图** |
| `/ld template trim <模板名\|all> [--no-backup]`（`剪枝`、`瘦身`） | 剪掉模板里的**空区块**（纯空气、没有方块实体/实体/结构起点）。编辑模式探索过的地图会塞满这种区块，一个最少占 4KB；默认先把 `region/poi/entities` 备份到 `bak/`。见 [12.10](12-游戏内编辑模式.md#1212-地图体积为什么会被撑大) |
| `/ld template reload`（`重载`） | 重新扫描模板目录 |

## 4.7 权限节点

| 节点 | 说明 | 默认值 |
|---|---|---|
| `liudungeon.use.enter` | 进入地牢 | `true` |
| `liudungeon.use.party` | 队伍系统全部命令 | `true` |
| `liudungeon.use.menu` | 打开 GUI 菜单 | `true` |
| `liudungeon.use.npcchoice` | NPC 对话选项 | `true` |
| `liudungeon.admin` | 全部管理指令 | `op` |
| `liudungeon.bypass.commandblacklist` | 绕过命令黑名单 | `op` |
| `liudungeon.bypass.itemblacklist` | 绕过物品黑名单 | `op` |
| `liudungeon.bypass.cooldown` | 绕过进入冷却**与每日次数上限** | `op` |
| `liudungeon.bypass.cost` | 绕过入场费用与门票 | `op` |

⚠ 另有 **5 个在 `plugin.yml` 里声明、但代码从不校验**的节点：
`liudungeon.use`（父节点）、`liudungeon.use.leave`、`liudungeon.use.list`、
`liudungeon.use.info`、`liudungeon.use.running`。
给玩家这些节点**不会**放开对应的指令（`/ld leave`、`/ld list` 等本来就不需要权限）。
连同第十一节说的另外 5 个预留节点，**`plugin.yml` 里共 9 个节点是纯预留的**。

⚠ **只有 2 个节点支持 `.<副本ID>` 后缀**（源码逐条核对过）：

| 节点 | 后缀形式 |
|---|---|
| `liudungeon.bypass.itemblacklist` | ✅ `liudungeon.bypass.itemblacklist.abyss_01` |
| `liudungeon.bypass.commandblacklist` | ✅ `liudungeon.bypass.commandblacklist.abyss_01` |
| `liudungeon.bypass.cost` | ❌ 不支持后缀，写 `.cost.abyss_01` **是死节点** |
| `liudungeon.bypass.cooldown` | ❌ 不支持后缀 |

带后缀的形式都没在 `plugin.yml` 里声明，但代码会读（权限插件里手写即可）。

⚠ **副本内破坏/放置方块（`world.allow_build`）没有对应的绕过权限节点**，
对 op 一样生效。这是刻意的，别去找 `liudungeon.bypass.build` 这类节点（不存在）。
要改地形：`/ld edit` 编辑模式，或副本脚本里的 `action.setblock` / 障碍物系统。
见 06 章 `world` 段的 `allow_build`。

副本 `config.yml` 的 `requirements.required-permissions` 可写任意权限节点，
入场时逐个校验。

## 4.8 已知问题（尚未修复）

| 问题 | 说明 |
|---|---|
| `/ld revive` 参数与注释不符 | 源码注释写 `/ld revive <玩家> [count <数值>]`，实现只判断 `args[0]` 是否为 `count`，且作用对象固定为**执行者自己**；`/ld revive Steve` 不会作用于 Steve |
| `/ld group`、`/ld stage` 实例 ID 打错不报错 | 找不到指定实例时会**静默回退**到"你所在的实例"，容易误判 |
| `plugin.yml` 里有 9 个预留但无对应指令的权限节点 | `liudungeon.use.sweep`、`.leaderboard`、`.stats`、`.viewstats`、`.confirm`、`.leave`、`.list`、`.info`、`.running` 均**没有对应子指令**（`/ld leave`、`/ld list` 等实际不需要权限节点）。不要依据权限表推断这些功能存在，也不要靠它们做限制 |
| `/npc_choice` 是占位实现 | 无论参数是什么都只回复「NPC 对话功能尚未实现。」 |

## 4.9 配置导出与结构化诊断

这两个指令是**给工具用的**（网页编辑器、CI、脚本），也是排查"我配了为什么没生效"最快的办法。

| 指令 | 输出 |
|---|---|
| `/ld export <副本ID>` | 写 `plugins/liudungeon/export/<副本ID>.json`，并在聊天栏列出校验结果 |
| `/ld export <副本ID> --stdout` | 直接打印到控制台/聊天栏，不写文件（方便 `> out.json` 或贴给别人） |
| `/ld doctor --json` | 写 `plugins/liudungeon/export/doctor.json` |

**导出的是"解析之后"的配置，不是 YAML 转 JSON。** 这一步很关键：

- 默认值已经填好、中英别名已经归一、`world.border` / `world.center` 这类回退已经算完；
- 所以 —— **字段不在导出里，就说明它根本没被解析**。这比翻文档猜快得多。

JSON 顶层结构：

| 键 | 内容 |
|---|---|
| `format` | 格式版本（当前 `liudungeon.export/v1`），工具应当校验 |
| `pluginVersion` / `generatedAt` / `dungeonId` / `directory` | 元信息 |
| `files` | 该副本目录下每个配置文件是否存在（值是字节数，不存在为 `null`） |
| `definition` | **完整解析结果**（`DungeonDefinition` 全量字段） |
| `references` | 脚本里出现过的 `action.*` ID 引用，按 ID 空间分组 |
| `checks` | **交叉引用校验结果**（见下） |
| `issues` | 该副本的加载期问题（与 `/ld doctor` 同源） |

**`checks` 是这里面最有价值的部分。** 它会静态扫描所有脚本文本，把
"配置里的字符串指向了另一个配置的键"这类**运行期完全静默**的错误提前报出来：

```
✘ monsters.yml · action.spawn_group('wave_9') → monsters.yml 的 groups 里没有「wave_9」（现有: wave_1, wave_2, wave_boss）
✘ zones.yml   · action.teleport_point('@all','大厅.终点') → 区域「大厅」里没有点位「终点」
✘ stages.yml  · 目标阶段「隐藏房」不存在
✘ config.yml  · 地图模板「trial」在 plugins/liudungeon/maps/ 下找不到
! monsters.yml · wave_3 → 没有任何脚本引用它，且它不是 AUTO_START/DELAYED/TRIGGERED —— 它永远不会被生成
```

`severity` 为 `error` 的是真错误，`info` 的是提示（比如"这个组永远不会被生成"，可能是故意的）。

> ⚠ **只分析字面量**：`action.spawn_group('wave_' + n)` 这种拼接出来的参数**提取不到**，
> 会被安静跳过。这是有意的取舍 —— 宁可漏报，也不要把合法的动态调用报成错误。
>
> 另外它是**纯文本静态分析**，不加载、不执行脚本，所以对任意文本跑都是安全的。

这两个指令都**只写入 `plugins/liudungeon/export/`，绝不修改 `dungeons/`**。

## 4.10 编辑模式 `/ld edit`（游戏内编辑副本）

**完整说明见 [十二、游戏内编辑模式](12-游戏内编辑模式.md)** —— 本节只给速查与入口。

进入一个副本的**编辑世界**（世界名 `ld_<副本ID>_edit`，`maps/<模板名>` 的文件级拷贝），
用 7 件工具 + 聊天栏面板 + GUI 菜单直接在游戏里改副本配置。
权限 `liudungeon.admin`；除 `status` / `help` 外**全部只能由玩家执行**。

| 指令（中文别名） | 参数 | 作用 |
|---|---|---|
| `/ld edit enter <副本>`（`进入`） | `<副本ID>` | 进入编辑。同副本 = 恢复会话（未保存变更还在） |
| `/ld edit exit [confirm]`（`退出`） | `confirm` / `确认` | 退出。有未保存变更时必须 `confirm`，否则只给 4 个可点按钮 |
| `/ld edit save`（`保存`） | — | 写回 YAML（旧文件备份到 `bak/<副本ID>_edit_<时间戳>/`）+ 地形异步同步回模板 + 全量重新解析 |
| `/ld edit test`（`试玩`） | — | 保存 → 地形**同步**同步回模板 → 关会话 → 正常开本进本。试玩后 `/ld edit enter <副本>` 回来 |
| `/ld edit undo`（`撤销`） | — | 撤销最近一条变更 |
| `/ld edit discard`（`放弃`） | — | 丢弃全部未保存变更 |
| `/ld edit cancel`（`取消输入`） | — | 取消没填完的聊天输入 / 书本编辑挂起 |
| `/ld edit panel`（`面板`） | — | 重发聊天栏面板 |
| `/ld edit viz`（`可视化`） | — | 开关粒子可视化 |
| `/ld edit target <类型> …`（`目标`） | 见 12.6 | 选编辑目标：`spawn` / `center` / `zonebounds` / `zonepoint` / `newzone` / `newzonepoint` / `interact` / `interactbounds` / `newinteract` / `monster <组> <第几只>` / `group` / `clear` |
| `/ld edit add <类型> …`（`新建`） | 见 12.6 | 新建：`zone` / `point` / `interact`（向导）/ `interactentity` / `group` / `monster <组> <mm\|mc> <ID> [数量]` |
| `/ld edit del <类型> …`（`删除`） | 见 12.6 | 删除：`zone` / `point <区域> <点位>` / `interact` / `group` / `monster <组> <第几只>` |
| `/ld edit tp <区域> <点位>`（`传送`） | — | 传送到命名点位 |
| `/ld edit goto <列表代号> <序号>` | — | 把查询器列表里的第 N 项设为编辑目标 |
| `/ld edit delhit <列表代号> <序号>` | — | 删除查询结果里的第 N 项 |
| `/ld edit script <文件> <路径…>`（`脚本`） | — | 翻书编辑该 YAML 路径的多行脚本（`functions.js` 免路径，整文件编辑） |
| `/ld edit delsection <文件> <路径>`（`删除节`） | — | 删除某个配置节 |
| `/ld edit interacttype <ID> <类型>`（`交互类型`） | — | 改交互点类型并自动迁移参数 |
| `/ld edit open [菜单键]`（`菜单`） | — | 打开编辑菜单（`main` / `zones` / `interacts` / `monsters` / `structure` / `pending` …） |
| `/ld edit status`（`状态`） | — | 列出全部编辑会话（**控制台可用**） |
| `/ld edit help`（`帮助`） | — | 子指令速查（**控制台可用**） |

要点（细节见第十二章）：

- **改动先进内存缓冲，`/ld edit save` 才写盘**；旧文件备份到 `bak/<副本ID>_edit_<时间戳>/`。
- 编辑期间 **`/ld enter` 不受影响**：模板在 save/exit 同步前没被任何世界占用；
  已经在跑的实例不受影响，新开的实例用编辑后的模板。
- **掉线保护**：会话保留 10 分钟，重连即恢复；超时（或关服）把未保存变更落草稿到
  `bak/<副本ID>_edit_draft_<时间戳>/`。
- 同一副本、同一模板同时只能有一个编辑会话；共用同一模板的副本会一起变。
- 会话里挖/放方块**就是改地图**，不经过撤销缓冲。
