# 五、GUI 菜单

> [← 四、指令手册](04-指令手册.md) · [总目录](../05-使用说明.md) · [六、配置文件详解 →](06-配置文件详解.md)

入口 `/ld menu`（别名 `/ld gui`、`/ld 菜单`），需要权限 `liudungeon.use.menu`。
标题、图标、文案全部可在 `plugins/liudungeon/gui.yml` 里改，改完 `/ld menu reload` 即生效。

> 本章讲的是**玩家菜单**（`/ld menu` 那 6 套）。
> `/ld edit` 另有一整套**编辑菜单**（写死在代码里、不走 `gui.yml`），
> 见 [5.10](#510-编辑模式下的-gui6-套) 与 [十二、游戏内编辑模式](12-游戏内编辑模式.md#127-gui-菜单)。

## 5.1 菜单入口与配置

| 项 | 值 |
|---|---|
| 打开菜单 | `/ld menu`、`/ld gui`、`/ld 菜单`（仅玩家） |
| 热重载配置 | `/ld menu reload`（需要 `liudungeon.admin`） |
| 配置文件 | `plugins/liudungeon/gui.yml`，首次启动自动写出 |
| 配置容错 | 删掉某个键、删掉整个文件、材质名写错 —— 菜单都照常打开，缺的键回退到内置默认值 |
| 槽位约定 | 槽位从 0 开始；第 N 行第 M 格 = `(N-1)*9 + (M-1)` |
| 未标出的格子 | 一律是填充格，材质取 `settings.filler-material`，点了没反应 |

## 5.2 主菜单 MainMenu（3 行 / 27 格）

标题键 `titles.main`，默认 `&0&l◤ &b&l地牢副本 &0&l◢`。

| 槽位 | 位置 | 按钮 | 配置键 / 材质 | 点击后 |
|---|---|---|---|---|
| `11` | 第 2 行第 3 格 | 地牢列表 | `items.dungeon-list` / `NETHER_STAR` | 打开地牢选择菜单 |
| `13` | 第 2 行第 5 格 | 我的队伍 | `items.party` / `PLAYER_HEAD`（图标是**自己的头颅**） | 打开队伍管理菜单 |
| `15` | 第 2 行第 7 格 | 我的数据 | `items.my-data` / `PAPER` | **关闭菜单**，把各副本冷却/每日剩余输出到聊天栏（没有二级界面） |
| `22` | 第 3 行第 5 格 | 关闭 | `items.close` / `BARRIER` | 关闭界面 |

地牢列表图标的**数量** = 副本数量（截断到 1–64）。

## 5.3 地牢选择菜单 DungeonMenu（6 行 / 54 格）

标题键 `titles.dungeon-list`。内容槽位 4 行 × 7 列：

```
第1行  0-8    全填充
第2行  9-17   填充 | 副本1 … 副本7 | 填充
第3行 18-26   填充 | 副本8 … 副本14 | 填充
第4行 27-35   填充 | 副本15 … 副本21 | 填充
第5行 36-44   填充 | 副本22 … 副本28 | 填充
第6行 45-53   45 上一页 | 48 关闭 | 49 返回 | 53 下一页
```

- **每页 28 个**（槽位 `10-16, 19-25, 28-34, 37-43`）
- 翻页按钮槽位固定 `45` / `53`，按需出现，**材质和名字不可配**
- 副本图标：材质取该副本配置的 `info.icon`（识别失败兜底 `DIAMOND_SWORD`），
  名字 `&b&l` + 副本显示名，运行中实例数 >0 时图标数量 = 该数字
- 图标的 lore（难度、人数、等级、费用、冷却、每日剩余、状态提示）由代码拼装，
  **`gui.yml` 改不了**
- 列表为空时槽位 `22` 显示屏障图标，名字取 `messages.no-dungeon`

**点击进本的流程与 `/ld enter` 完全共用**：先查 `liudungeon.use.enter` →
已在副本中则拒绝 → 关闭界面后走 `collectMembers` + `lifecycle().enter`。
人数/等级/冷却/每日次数/扣费都在那一步校验，所以不会出现「指令进不去但 GUI 能进」。

## 5.4 队伍管理菜单 PartyMenu（6 行 / 54 格）

标题键 `titles.party`。这个菜单有**两种形态**。

**未组队**：槽位 `22` = 创建队伍（`items.create-party` / `EMERALD`），`49` 返回，`53` 关闭。

**已组队**：

```
第1行  0-8    填充 | 4 队伍概况 | 填充
第2行  9-17   填充 | 成员1 … 成员7 | 填充
第3行 18-26   填充 | 成员8 … 成员14 | 填充
第4行 27-35   填充 | 29 邀请 | 30 踢人※ | 31 转让※ | 32 解散/离开 | 填充
第5行 36-44   填充 | 38 结束副本※ | 42 退出副本※ | 填充
第6行 45-53   填充 | 49 返回 | 填充 | 53 关闭
```

※ 槽位 `30`、`31`、`38`、`42` 只有队长才存在；
`38`、`42` 另外还要求**队长此刻确实在这个副本里**（不在副本里就整块不显示）。

| 槽位 | 按钮 | 配置键 / 材质 | 点击后 |
|---|---|---|---|
| `4` | 队伍概况（纯展示） | 固定 `PLAYER_HEAD`，**不走 gui.yml** | 无反应 |
| 成员格 | 成员头颅 | 固定 `PLAYER_HEAD`，**不走 gui.yml** | 队长点**其他成员** → 打开队员操作菜单；点自己或非队长点击无反应 |
| `29` | 邀请玩家 | `items.invite-player` | 打开选人菜单（邀请模式） |
| `30` | 踢出队员（队长） | `items.kick-player` | 打开选人菜单（踢出模式） |
| `31` | 转让队长（队长） | `items.transfer-leader` | 打开选人菜单（转让模式） |
| `32` | 解散队伍（队长） | `items.disband-party` | 先弹**二次确认** |
| `32` | 离开队伍（队员） | `items.leave-party` | 直接离开，**无二次确认** |
| `38` | 结束副本（队长） | `items.end-dungeon` / `NETHER_STAR` | 先弹二次确认 → 结束当前副本、**全队随之退出队伍**，随后重新进入一个全新的副本 |
| `42` | 退出副本（队长 · 副本内） | `items.quit-dungeon` / `RED_BED` | 先弹二次确认 → 离开副本，**同时退出队伍** |

**「结束副本」是队长的强制操作，不需要队员同意**。没有投票、没有"等其它成员点确认"
这一步 —— 操作者自己那次二次确认就是全部手续，点完立即生效，
队员只会收到一条"正在重建世界…"的广播，**没有否决的机会**。
理由很直接：副本是队长开的、入场费是他扣的，
让几个不想走的队员联手把队长卡在副本里没有任何意义。

| 按钮 | 出现条件 | 为什么 |
|---|---|---|
| 结束副本（`38`） | 队长 + **他的队伍占着一个副本实例** | 不要求队长本人在副本里。队友跑散了、队长自己 `/ld leave` 出去过，副本仍在跑，他照样得能结束它 —— 否则会卡在"副本占着实例槽位、而唯一有权结束的人看不见按钮" |
| 退出副本（`42`） | 队长 + **他本人在副本里** | 它做的是"把自己传出去"，人不在里面就没有对象可言 |

**「结束副本」到底做了什么**：它不是"重置当前副本"，而是
**完整结束旧实例（跑 exit 脚本 → 传送还原 → 卸载并删除世界）→ 重新走一遍进本流程**。
所以怪物、阶段、机关、宝箱、脚本变量全部回到初始状态，和第一次进本完全一致，
代价是一次模板克隆的时间（期间全队会看到"正在重建世界…"的提示）。

进本校验（扣费 / 冷却 / 每日次数 / 门票 / 人数 / 等级）在**结束旧副本之前**先跑一遍：
不满足就把拒绝原因发给你，**旧副本的进度原样保留** ——
不会出现"副本已经没了、新的又进不去"这种最坏结果。

**「退出副本」的顺序**：先退出副本，再退出队伍。队长退出后队伍按既有规则处理
（队里还有人就顺位移交，没有别人就自动解散）。它与 `/ld leave` 的唯一区别是：
`/ld leave` 只退副本、**保留队伍**。

> 不想用 GUI 的队长可以用 `/ld restart`（先问一次，再 `/ld restart confirm`），
> 走的是**完全相同**的代码路径，见 [4.2](04-指令手册.md)。

> 📌 这里曾经有 **4 个"点了不生效"的设置项**：战利品分配 / 经验共享 / 共享范围 / 加入方式。
> 现已全部移除。前三个只有字段存储，运行期没有任何代码按它们分配东西
> （详见 [6.4](06-配置文件详解.md) 的说明）；**加入方式**同理 ——
> `/ld party join` 唯一认的硬门槛是"队伍是否公开"，与 `invite` / `apply` 无关。
> 摆一个改不动的开关，比不摆更糟：玩家会以为自己调对了。

## 5.5 队员操作菜单 MemberActionMenu（3 行 / 27 格）

标题键 `titles.member-action`。从队伍菜单点成员头颅进入，
避免「点头像就等于踢人」这种危险默认。

| 槽位 | 按钮 | 配置键 | 点击后 |
|---|---|---|---|
| `4` | 目标玩家头颅（纯展示） | 固定 `PLAYER_HEAD` | 无反应 |
| `11` | 踢出队员 | `items.kick-player` | 弹确认菜单，确认后踢人 |
| `15` | 转让队长 | `items.transfer-leader` | 弹确认菜单，确认后转让 |
| `22` | 返回 | 固定 `ARROW`，**不走 gui.yml** | 回队伍菜单 |

## 5.6 选人菜单 PlayerSelectMenu（6 行 / 54 格）

一个类服务三种动作：

| 模式 | 标题键 | 候选来源 |
|---|---|---|
| 邀请 INVITE | `titles.select-player` | **所有在线玩家**（排除自己；不排除已有队伍的人） |
| 踢出 KICK | `titles.select-kick` | 队内**其他**成员（含离线） |
| 转让 TRANSFER | `titles.select-transfer` | 同上 |

布局与地牢菜单一致：每页 28 个，翻页 `45` / `53`，返回 `49`。
候选图标为玩家头颅 + `&f玩家名`。列表为空时槽位 `22` 显示提示。

> **邀请一次只提示一条**。点中候选后，只有队伍频道那一句「已邀请 X」
> （来自 `PartyManager`）；发送者不再额外收到第二条「已邀请 X。」。
> 被邀请人收到的是一条**可点击**的消息，末尾带 `[✔ 接受]` `[✘ 拒绝]` 两个按钮，
> 点一下就等于自己敲了 `/ld party accept <邀请人名>` ——
> 走的是同一条权限与校验链路，不需要照着提示手打指令。
> 按钮文字与正文都可在 `config.yml` 的 `party.invite-message` /
> `party.invite-buttons.*` 里改。

> 这个菜单**没有关闭按钮**，返回键一律回**主菜单**（不是队伍菜单）。
> 踢出 / 转让从列表点击会**立即执行，没有二次确认** —— 只有从队伍菜单的
> 「踢出队员 / 转让队长」按钮进去才有确认。

## 5.7 确认菜单 ConfirmMenu（3 行 / 27 格）

标题键 `titles.confirm`。危险动作统一走这里，**要點两下**，且左右位置固定。

| 槽位 | 按钮 | 配置键 | 点击后 |
|---|---|---|---|
| `4` | 操作说明 | 固定 `PAPER`，不走 gui.yml | 无反应 |
| `11` | 确认（左） | `items.confirm-yes` / `LIME_CONCRETE` | **先关界面**，再执行动作 |
| `15` | 取消（右） | `items.confirm-no` / `RED_CONCRETE` | 打开**主菜单**（不是返回上一级） |

## 5.8 `gui.yml` 字段说明

**`settings.*`**

| 键 | 作用 | 默认值 |
|---|---|---|
| `settings.filler-material` | 空白格填充材质 | `GRAY_STAINED_GLASS_PANE` |
| `settings.filler-name` | 填充格显示名 | `" "`（一个空格） |

**`titles.*`** —— 每个菜单的标题，支持 `&` 颜色代码，删掉则用内置默认值。

| 键 | 用于 | 默认值 |
|---|---|---|
| `titles.main` | 主菜单 | `&0&l◤ &b&l地牢副本 &0&l◢` |
| `titles.dungeon-list` | 地牢选择 | `&0&l◤ &5&l地牢选择 &0&l◢` |
| `titles.party` | 队伍管理 | `&0&l◤ &a&l队伍管理 &0&l◢` |
| `titles.member-action` | 队员操作 | `&0&l◤ &6&l队员操作 &0&l◢` |
| `titles.select-player` | 选人 · 邀请 | `&0&l◤ &e&l邀请玩家 &0&l◢` |
| `titles.select-kick` | 选人 · 踢出 | `&0&l◤ &c&l踢出队员 &0&l◢` |
| `titles.select-transfer` | 选人 · 转让 | `&0&l◤ &6&l转让队长 &0&l◢` |
| `titles.confirm` | 确认菜单 | `&0&l◤ &c&l确认操作 &0&l◢` |

**`items.*`** —— 每个按钮的 `material` / `name` / `lore` 三个子键。

| 键 | 用在 | 默认材质 | 默认名字 |
|---|---|---|---|
| `items.dungeon-list` | 主菜单 11 | `NETHER_STAR` | `&5&l⚔ 地牢列表` |
| `items.party` | 主菜单 13 | `PLAYER_HEAD` | `&a&l👥 我的队伍` |
| `items.my-data` | 主菜单 15 | `PAPER` | `&b&l📊 我的数据` |
| `items.close` | 各菜单关闭位 | `BARRIER` | `&c&l✖ 关闭` |
| `items.back` | 各地返回位 | `ARROW` | `&7&l◀ 返回` |
| `items.create-party` | 队伍 22 | `EMERALD` | `&a&l✨ 创建队伍` |
| `items.invite-player` | 队伍 29 | `PLAYER_HEAD` | `&e&l📨 邀请玩家` |
| `items.kick-player` | 队伍 30 / 队员 11 | `IRON_SWORD` | `&c&l🚪 踢出队员` |
| `items.transfer-leader` | 队伍 31 / 队员 15 | `GOLDEN_SWORD` | `&6&l👑 转让队长` |
| `items.disband-party` | 队伍 32（队长） | `BARRIER` | `&4&l💔 解散队伍` |
| `items.leave-party` | 队伍 32（队员） | `RED_BED` | `&c&l🏃 离开队伍` |
| `items.end-dungeon` | 队伍 38（队长 · 副本内） | `NETHER_STAR` | `&d&l⏹ 结束副本` |
| `items.quit-dungeon` | 队伍 42（队长 · 副本内） | `RED_BED` | `&c&l🚪 退出副本` |
| `items.confirm-yes` | 确认 11 | `LIME_CONCRETE` | `&a&l✔ 确认` |
| `items.confirm-no` | 确认 15 | `RED_CONCRETE` | `&c&l✖ 取消` |

两点必须知道：

1. **在 `gui.yml` 里写了 `lore` 就会整体覆盖代码内置的动态 lore。**
   默认配置里 `items.dungeon-list.lore` 含 `当前共有 &f{dungeons} &7个副本`，
   这个 `{dungeons}` 会被替换成实时副本数（已支持）。
   但**其他动态内容**（队伍名/成员数等）一旦你在 `gui.yml` 写了 lore 就没了 ——
   想恢复代码内置的动态文案，把对应 `lore` 整段删掉即可。
2. **材质名写错不会报错**，只会回退到该按钮的内置兜底材质，菜单照常打开。

**`messages.*`**

| 键 | 作用 | 默认值 |
|---|---|---|
| `messages.no-dungeon` | 副本列表为空时屏障图标的名字 | `&c当前没有可用的副本` |

## 5.9 点击事件处理规则

| 规则 | 行为 |
|---|---|
| 怎么认领菜单 | 只判断「上半区容器的 holder 是不是我们的菜单对象」（JVM 类型判断），**完全不比较窗口标题** |
| 物品能不能拿走 | **不能**。所有点击一律 `setCancelled(true)`，且是**整个事件**取消，不只是上半区 |
| 会不会误触玩家背包 | 点自己背包时事件同样被取消（物品不会移动），但**不派发**菜单回调 |
| 拖拽 | 单独取消，无法把物品拖进菜单格 |
| 哪些格子有反应 | 只有注册过回调的按钮才有反应；填充格、纯展示格点了没反应 |
| 权限 | GUI 只检查两处：打开菜单 `liudungeon.use.menu`、点副本进入 `liudungeon.use.enter` |
| 刷新方式 | 点击后原地刷新（不闪烁）；尺寸或标题变化时退化为重新打开 |
| 配置读取时机 | 菜单在**打开/刷新时**读一次 `gui.yml`，所以 reload 后要重开才看到新配置 |

## 5.10 编辑模式下的 GUI（6 套）

`/ld edit` 会用到一整套**独立**的菜单 —— 主菜单 + 5 个子菜单（区域与点位 / 交互点 /
怪物组 / 脚本与结构 / 待保存变更），共 6 套。它们与本章的 6 个玩家菜单**没有任何关系**：

| 对比项 | 本章的玩家菜单 | 编辑模式的菜单 |
|---|---|---|
| 入口 | `/ld menu` | `/ld edit open`、聊天面板 `[⚙菜单]`、右键背包第 9 格的**编辑会话菜单钟** |
| 权限 | `liudungeon.use.menu` | `liudungeon.admin` |
| 配置 | `plugins/liudungeon/gui.yml` 全部可改 | **不走 `gui.yml`**，材质与文案写死在代码里 |
| 点击语义 | 左键为主 | 条目按钮普遍区分**左键 / 右键 / `Shift+左键` / `Shift+右键`** |
| 删除 | 走确认菜单（`titles.confirm`） | 也走确认菜单（左确认右取消），但入口是列表里的 `Shift+右键` 或详情里的 `TNT` 按钮 |
| 分页 | 每页 28 个（槽位固定 45/53） | 列表类菜单**每页 45 个**；底栏固定 `45` 上一页 / `47` 次要操作 / `48` 返回 / `49` 主操作 / `53` 下一页，空列表在 `22` 给提示 |

**每个菜单的槽位表、按钮材质、左右键与 Shift 键语义，见
[12.7 GUI 菜单](12-游戏内编辑模式.md#127-gui-菜单)。** 本节不再重复，以免两处不同步。

> 唯一与本章规则相同的部分：容器点击一律取消（物品拿不走），
> 只有注册过回调的格子有反应，纯展示格与填充格点了没反应（见 5.9）。
